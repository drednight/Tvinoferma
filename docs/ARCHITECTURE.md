# Архитектура

Твиноферма — Tauri 2: интерфейс на чистом JavaScript (без фреймворка, сборка Vite) и Rust-часть,
которая открывает окна браузера (WebView) и запускает в них скрипты.

## Главная схема: как приложение получает данные с сайта

```
Интерфейс (js/)          Rust (src-tauri/src/)                 Сайт pwonline.ru
─────────────────        ───────────────────────────           ──────────────────
кнопка / очередь
  │  invoke('команда')
  ▼
queue.js ───────────────► команда (auth / balance / marathons)
                            │ берёт скрытое окно (windows.rs / pool.rs)
                            │ ставит куки персонажа из банка (cookie_bank.rs)
                            │ navigate → страница ─────────────────► загружается
                            │ eval(скрипт из src/scripts/*.js) ────► читает DOM
                            │                                         │
                            │ ◄── location.hash = "#TF_…<json>" ◄────┘
                            │ parsers.rs читает hash, повторяет
                            │ при «Проверке безопасности»
  ◄── событие (emit) ◄──────┘ результат { data, error }
syncManager.js / siteSync.js
  │ обновляет state, persist()
  ▼
state.json на диске (commands/state.rs) + пароли в хранилище ОС (commands/secrets.rs)
```

Ответ передаётся через `hash`, а не через `invoke` из страницы: так внешней странице сайта не нужен доступ
к командам Tauri. Скрипт только пишет ответ в адрес окна, а Rust его читает.

Формат ответа: `#TF_<ИМЯ>_V<N>_<encodeURIComponent(JSON)>`, где JSON = `{ "data": …, "error": null | "строка" }`.
Коды ошибок: `not_logged_in`, `timeout`, `challenge` (сайт показывает «Проверку безопасности»),
`pending` (страница ещё не дорисована). Номер версии в префиксе (`TF_BAL_V5_`) меняется, когда меняется
формат ответа: так старый ответ в hash не принимается за новый.

## Rust (`src-tauri/src/`)

| Файл | За что отвечает |
| --- | --- |
| `lib.rs` | Регистрация команд, плагинов, старт приложения |
| `windows.rs` | Окна персонажей: видимые (ручной вход) и скрытые (фоновые скрипты); у каждого персонажа свой профиль WebView `pw-sync-profiles/<id>` |
| `parsers.rs` | Общий цикл «выполнить скрипт → ждать ответ в hash», журнал шагов (`tf-task-log`), обход «Проверки безопасности». Если время вышло, а страница всё это время отвечала («Проверка безопасности» или «страница загружена, нужных элементов нет»), возвращает этот ответ, а не «таймаут» (`soft_timeout_result`) |
| `auth.rs` | Проверка входа (`usercp.php`) |
| `balance.rs` | Баланс древних монет (`chests2.php`) |
| `marathons.rs` | Прогресс персонажа, поиск марафонов, разбор страницы и новости |
| `pool.rs` | Пул воркеров: до 4 общих скрытых окон вместо окна на каждого персонажа |
| `cookie_bank.rs` | Куки сессий pwonline.ru, зашифрованные AES-256-GCM; ключ лежит в хранилище ОС |
| `commands/` | `state.json` (атомарная запись), резервные копии, пароли в хранилище ОС (`keyring`) |
| `tray.rs` | Иконка в трее |
| `scripts/*.js` | Скрипты, которые внедряются в страницы сайта (`include_str!`). Только читают DOM |
| `scripts/selectors.json` | Все селекторы, тексты («Вы не авторизованы») и регулярные выражения парсеров: имя → список «основной, запасные…» |
| `scripts/common.js` | Общий слой `window.__TF`: поиск по списку селекторов, проверка «Проверки безопасности». Перед каждым скриптом `parsers.rs` (`with_common`) подставляет в него `selectors.json` |
| `automation/`, `injection.rs` | Заготовки (Issues #25, #26, #54), не подключены |

| `modules/{arena,automation,bank,dungeons,injection,runes,cloud}` | Заготовки будущих разделов, помечены ссылками на Issues |

## Состояние парсеров

Каждый итоговый результат парсера (после повторов очереди) записывается в `js/core/parserHealth.js` (`localStorage`, ключ `tf-parser-health`):
парсеры `balance`, `auth`, `progress`, `titles`, `detail`, `news`. Код ошибки превращается в статус:

| Статус | Когда | Что делает приложение |
| --- | --- | --- |
| `ok` | Парсер отработал | Сбрасывает счётчик неудач, запоминает время успеха |
| `empty` | Страница прочитана, но на сайте пусто (нет марафона, нет заданий) | То же, что `ok`: это не поломка |
| `layout_changed` | Нет блока, значения или полос прогресса, число не читается, скрипт упал | +1 к счётчику неудач; со второй подряд — плашка «Парсер устарел» |
| `not_logged_in` | Сайт просит войти | Счётчик не меняется |
| `challenge` | Сайт держит «Проверку безопасности» | Счётчик не меняется |
| `timeout` | Страница не загрузилась или не ответила | Счётчик не меняется |
| `error` | Прочие ошибки запуска | Счётчик не меняется |

При любой ошибке данные в базе не меняются: баланс, история монет и прогресс марафона обновляются только по успешному ответу.
Новый парсер подключается так: ключ в `PARSERS` (`parserHealth.js`), вызов `recordParserResult(ключ, error)` в месте, где известен итог, тест в `tests/parserHealth.test.js`.

## Данные

- `state.json` лежит в `<AppData>/com.tvinoferma.desktop/tvinoferma_data/`. Запись атомарная (временный файл → переименование),
  резервные копии делает `commands/backup.rs`.
- Версия схемы — `SCHEMA_VERSION` в `js/core/migrations.js`. Любое изменение схемы = миграция в `js/core/migrations.js` + тест.
- Пароли, e-mail и телефоны персонажей в `state.json` не пишутся: они в хранилище ОС (Windows Credential Manager).
  В памяти приложения они есть, поэтому экспорт и помощник входа работают как раньше.
- Куки-банк (`cookie-bank/<id>.bin`) в экспорт не входит и на другой ПК не переносится.

## Как добавить новый парсер

1. Скрипт в `src-tauri/src/scripts/имя.js`: читает DOM через `window.__TF` (`TF.q('имя.элемент')`, `TF.has(текст, 'имя.фраза')`), селекторы и тексты добавляет в `selectors.json`; пишет `location.hash = 'TF_ИМЯ_V1_' + encodeURIComponent(JSON.stringify({ data, error }))`. Никаких кликов и отправки форм (см. [COMPLIANCE.md](COMPLIANCE.md)). Прямых `document.querySelector('…')` в скрипте быть не должно, тест `tests/selectorsConfig.test.js` это проверяет.
2. Команда в Rust: `navigate_clean` → `eval_and_wait(…, "#TF_ИМЯ_V1_", таймаут, scope)`; зарегистрировать в `lib.rs`.
3. Обёртка в `js/modules/…` + постановка в очередь `queue.js`.
4. Сохранённая страница сайта в `tests/fixtures/` и тест, который прогоняет скрипт на ней (`tests/helpers/pageScript.js`), в том числе на странице с «изменённой вёрсткой»: парсер должен вернуть ошибку, а не пустой результат. Как делать фикстуры без личных данных: [FIXTURES.md](FIXTURES.md).
