## Магазин

- Offline/непроверенные персонажи видны и выбираются заранее, в том числе через
  общий/ручной выбор. Покупка не обходит вход, контроль свежести и подтверждение.
- Первый шаг — только названия предметов и выбор аккаунтов. **Далее** открывает
  отдельное окно количеств, цен, общего баланса и живого остатка. Изменение
  числа ничего не покупает. Общий аккаунт не удваивает баланс/лимит/покупки.
- Явный X из «N из X» остаётся авторитетным. Иначе используется наибольший
  прочитанный остаток N этого предмета среди аккаунтов; меньший остаток его
  не сбрасывает. Источник максимума подписан как наблюдение, не правило сайта.
- Все / Максимум / Меньше максимума / Исчерпано / Нет данных / Есть дата обновления.
  Просроченная известная дата требует нового чтения, не выдаётся за будущую.
- Реальный `//cdn.pwonline.ru/...` приводится к HTTPS. Разрешён только точный
  официальный host без query/auth; соответствующий точный img-host добавлен
  в native CSP. Выдуманной таблицы изображений нет.
- Прежние runner, fresh/readback, single purchases, retry remainder,
  подтверждения, dry-run, общий баланс и журнал сохранены.

## Сопоставление и сравнение

- Nick-only остаётся подсказкой. Контактное соответствие возможно только при
  однозначных нике+классе+связанных контактах из проверенного файла. Если пароль
  предоставлен, он также должен совпасть. Один пароль без контакта не является
  идентичностью; неоднозначные пары не объединяются. Значения не выходят
  в review-модель/логи. Чужая сильная sync-идентичность не перехватывается.
- Автоматически совпавшая запись требует равенства всей публичной записи,
  включая историю, даты, группы и архивность, и предоставленных приватных полей,
  а не только редактируемых характеристик. Сравнение не зависит от порядка
  ключей JSON. Локальные ID, контакты и пути не переписываются.
- Приватные отличия показывают имя связанного персонажа и человеческое имя поля,
  без значений и без формулировки, будто сравнение уже разрешило перенос.
- Характеристики, проходки, даты и общее сравнение отображаются подписями,
  не сырыми JSON-объектами. Технические witness/consent проверки не изменены.
- Полное сравнение снимков сохраняет различия стабильных идентичностей и графа:
  совпадение полей не разрешает автоматически переименовать ID или удалить дубль.

## Яндекс / Google — не считать исправленными

- Яндекс: добавлен безопасный этап `oauth_identity_binding_mismatch` перед отказом,
  если identity провайдера отличается от pin. Указано, что `psuid` зависит от
  OAuth-клиента, и прежний клиент уже восстанавливается. Почему идентификатор
  отличается в пользовательском запуске, не доказано. Никакого reset привязки,
  токена, ключа, vault или ослабления pin-проверки не сделано.
- Google: добавлены подэтапы materialization для ссылок, assignments/progress,
  planner source/local ID и коллизий. Искусственный конфликт manual/guild записи
  воспроизводит безопасный `roundtrip.materialize.planner/local_id` с сохранением
  отказа и исходных данных. Это не доказывает причину пользовательского файла
  `roundtrip.materialize/invalid` и не является его исправлением.
