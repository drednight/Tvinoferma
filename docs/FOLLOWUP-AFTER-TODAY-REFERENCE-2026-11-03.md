# Добавочный «Сегодня 12» и оставшиеся правки

Этот блок добавляет только вариант демо по `image-25.png` пользователя, не заменяя
прежние дизайны. Прямая ссылка: `/demo2/index.html?page=focus&variant=12`.
Производственные магазин, синхронизация и OAuth **не изменены этим блоком**.

## Демонстрация

Новости над данжами/событиями слева; промокоды и марафон справа сверху,
затем быстрый запуск и клан. Полный календарь не выводится на главной.
Иконки трёх проходок — существующие assets проекта, не рисованные замены.
Новости — сохранённые оригинальные ссылки, не свежая лента. Неподтверждённые
часы событий не выдумываются. Награды марафона — явно подписанная иллюстрация.
Поддержаны ручные промокоды, скрытие/восстановление, даты, другие пати,
предпросмотр запуска всего состава/только неоткрытых окон и независимая отпись.
Без клана остаётся баннер входа. Ввод и решения живут только в памяти демо.

## Магазин — новые указания пользователя, ещё предстоит

Эти правила **заменяют** прежние ограничения PR173:

1. Offline и неизвестный вход не скрывать и не исключать из выбора. Можно выбрать
   заранее; реальная покупка всё равно проверяет состояние сайта и не обходит вход.
2. `Доступно Вам: N шт.` — использовать запомненный максимум N для этого предмета
   среди всех персонажей/чтений как пользовательский лимит. Не терять максимум,
   когда прочитан меньший остаток. Не показывать старую фразу об отсутствии лимита.
3. У предмета действительно есть image URL в HTML. Использовать его проверенный
   URL (`//cdn.pwonline.ru/...` → HTTPS), без выдуманных сопоставлений иконок.
4. Главная страница — только персонажи/аккаунты и названия выбранных предметов.
   Без quantity и «Итого / остаток». В footer «Далее», не «Купить».
5. Далее — дочернее модальное окно с количествами на персонажа/предмет, ценами,
   текущим балансом и пересчитываемым остатком Древних монет. Общий аккаунт не
   удваивает баланс/лимит. Buy внутри этого окна с прежними fresh/consent guards.
6. Фильтры лимитов: Все / Максимум / Меньше максимума / Исчерпано / Нет данных /
   Есть дата обновления. Старые «Без указанного лимита» не соответствуют новой модели.

## Синхронизация — ещё предстоит

1. Идентичные данные не предлагать сверять вручную; сравнивать и доступные
   контакты/пароли из уже расшифрованного файла, учитывая его source character ID.
   Nick-only по-прежнему не доказывает тождество; неоднозначные совпадения не
   сливать и не удалять. Загрузка контактов сама по себе не разрешает их перезапись.
2. Показать, к какому персонажу относятся приватные поля; пароль не выводить в
   отчёты/логи, предусмотреть явный reveal, не показывать сырые объекты JSON.
3. Сравнение — понятные карточки с подписями характеристик/проходок/дат, не
   `{"endurance":0,...}`. Местные ID/GameCenter/контакты сохранять.
4. Новый отчёт: desktop 2.2.0, source `edc8e559e0acdaa6317b01e0883876697ccd909d`,
   2026-11-03T11:26:05.831Z. Yandex в 11:04:13–16 проходит signed_out → browser →
   token → identity и заканчивается `login_account_changed` **до подтверждения
   и установки**. Это уже не просто credential_missing. Код текущего resume
   сравнивает identity.accountKey с pin; нужно определить причину несовпадения,
   не объявляя без доказательств, что пользователь выбрал другой аккаунт.
   Trusted client/slot/account/dataset protections не отключать.
5. Google скачивает и расшифровывает файл, но полная materialization падает
   `setup/identities/roundtrip.materialize/invalid`. Не отключать roundtrip guard;
   отдельно воспроизвести причину. Это не тот же сбой, что OAuth Яндекса.
