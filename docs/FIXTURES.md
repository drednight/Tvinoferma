# Фикстуры: сохранённые страницы сайта для тестов

Фикстура — копия страницы pwonline.ru в `tests/fixtures/`. Тесты запускают на ней настоящие скрипты разбора
(`src-tauri/src/scripts/*.js`) и сравнивают результат с ожидаемым. Если сайт изменит вёрстку, достаточно
сохранить новую страницу и посмотреть, какой тест упал.

## Какие страницы есть

| Файл | Страница | Чем проверяется |
| --- | --- | --- |
| `site-usercp.html` | Личный кабинет, вход выполнен | `check_auth.js` → `online` |
| `site-warning.html` | «Предупреждение»: вы не авторизованы | `check_auth.js` → `offline`, остальные парсеры → `not_logged_in` |
| `site-chests2.html` | Магазин подарков, баланс 464 | `balance.js` |
| `site-supermarathon.html`, `site-supermarathon2.html` | Страницы марафонов | `marathon_titles.js`, `marathon_progress.js`, `marathon_detail.js` |
| `site-news-summer.html` | Новость «Летний марафон» целиком | `marathon_news.js` + `newsParser.js` |
| `news_list_p1.html`, `news_list_p2.html` | Архив новостей | `newsList.js` |
| `news-*.html` | Вырезки новостей (только статья) | `newsParser.js` |

**Промокоды (`promo.js`, `tests/promoScript.test.js`):** все страницы настоящие, обезличенные.

| Файл | Страница |
| --- | --- |

| `site-pin-empty.html` | `/pin.php`: поле пустое |
| `site-pin-result-ok.html` | успех: «Вы успешно активировали пин-код…» и 13 наград |
| `site-pin-result-used.html` | «Вы уже активировали этот пин-код!» |
| `site-pin-result-expired.html` | «Время действия пин-кода истекло!» |
| `site-pin-result-nobonus.html` | «Не добавлены бонусы для этого типа пин-кода» (код неверный или ещё не настроен) |
| `site-pin-result-empty.html` | «Пустой пин-код» |

Нет только страницы ответа на заведомо несуществующий код (если сайт отвечает иначе, чем «Не добавлены бонусы»).

**Передача предметов (`transfer.js`, `tests/transferScript.test.js`):** страницы настоящие, обезличенные (ник персонажа заменён на «#Тестовый», аккаунт — `u_1000000001`).

| Файл | Страница |
| --- | --- |
| `site-promoitems.html` | `/promo_items.php`: форма передачи, предметы с чекбоксами, сундуки, строки без чекбокса |
| `site-promoitems-history.html` | `/promo_items.php?do=history`: «Название x N», игровой аккаунт/персонаж/сервер, статус «В обработке», дата по МСК |

Не хватает страниц: пустого списка предметов, ответа сайта на ошибку передачи (нет места, больше 6 предметов) и окна подтверждения; при появлении добавить рядом тесты.

Тесты: `tests/parsers.test.js` (скрипты на страницах) и `tests/fixturesPrivacy.test.js` (в фикстурах нет личных данных).

В тестах есть три вида проверок:

1. **Хорошая страница → ожидаемый JSON** (баланс 464, `online`, название марафона).
2. **«Вёрстка изменилась»**: из хорошей страницы вырезается нужный блок (`editDom` в `tests/helpers/pageScript.js`),
   и парсер обязан вернуть **ошибку** (`container_missing`, `no_value_tag`, `pending`…), а не ноль и не пустой список.
3. **«Проверка безопасности»** (anti-bot): короткая искусственная страница, парсер отвечает `challenge`.

## Как добавить или обновить фикстуру

1. Откройте страницу в браузере, войдя в **тестовый** аккаунт, и сохраните: «Сохранить как → Веб-страница, только HTML».
2. Очистите страницу скриптом:
   ```powershell
   node scripts/sanitize-fixture.mjs "C:\Users\...\Страница.htm" tests/fixtures/site-имя.html
   ```
   Для длинных страниц оставьте только начало списка: `--trim=".chest_shop>ul:2"` (оставит 2 первых элемента).
3. **Откройте результат глазами** и найдите свой ник, e-mail, номера аккаунтов, имена персонажей, инвентарь.
   Скрипт ловит типовые случаи, но не заменяет проверку человеком.
4. Добавьте тест в `tests/parsers.test.js` (хорошая страница + «вёрстка изменилась») и запустите `npm test`.

## Правила обезличивания

Скрипт `scripts/sanitize-fixture.mjs` делает автоматически:

- удаляет `<script>`, `<style>`, `<link>`, `<iframe>`, `<svg>`, картинки и комментарии;
- удаляет атрибуты `on…`, `style`, `data-…`, очищает значения скрытых полей (`<input type="hidden">`);
- оставляет из `<meta>` только кодировку (там бывают проверочные коды);
- заменяет e-mail на `user@example.com`, ник вида `u_123456789` и id аватара на `u_1000000001` / `1000000001`;
- заменяет `token=…`, `hash=…`, `session=…` в адресах на `X`.

Вручную проверьте и уберите:

- ники и имена персонажей, названия кланов, серверы, если они привязаны к вашему аккаунту;
- список предметов и баланс, если по ним можно узнать аккаунт (баланс в фикстуре баланса оставляйте «круглым»);
- куки, заголовки ответа, «Set-Cookie», сессионные идентификаторы.

`tests/fixturesPrivacy.test.js` падает, если в любой фикстуре остались настоящий e-mail, ник аккаунта, токен
в адресе, имя сессионной куки, длинные скрипты или base64-картинки. Условные значения, которые можно
оставлять: `user@example.com`, `u_1000000001`, `token=X`.

> Что делать, если личные данные уже попали в репозиторий: сначала замените их в файлах и закоммитьте, затем
> смените пароль или токен, если они были настоящими. Удаление из истории Git (`git filter-repo`) нужно только
> для секретов; ник и e-mail из публичной истории убрать нельзя, поэтому их проще не коммитить.

## Сайт изменил вёрстку: что делать

1. Сохраните новую страницу скриптом очистки (см. выше) в `tests/fixtures/` и запустите `npm test`: упавший тест покажет парсер.
2. Откройте `src-tauri/src/scripts/selectors.json`, найдите запись парсера (например, `balance.container`) и **поставьте новый селектор первым, а старый оставьте запасным**:
   ```json
   "balance.container": [".points_box", ".points_info"]
   ```
   Так приложение справится и со старой, и с новой версткой (сайт иногда раздаёт её постепенно).
3. Увеличьте `version` в начале `selectors.json` на 1.
4. Добавьте в `tests/parsers.test.js` проверку на новой странице и убедитесь, что `npm run check` зелёный.

Тексты (`texts`) и регулярные выражения (`regex`) правятся так же. Логику разбора (например, формулу дат этапов в `marathon_detail.js`) файл не заменяет: она остаётся в скрипте.
