# GameCenter → сайт: экспериментальное ожидание «Пополнить счёт»

## Что реализовано в рабочей ветке

В профиле персонажа, в контактах, есть «Проверить вход через GameCenter…».
Кнопка отделена от контактов отступом. Для показа включите соответствующий способ
входа при редактировании персонажа. Он не означает, что вход на сайте уже есть.

В диалоге можно выбрать прикреплённый GameCenter с запомненным входом и нажать
«Начать авторизацию через „Пополнить счёт“». После подготовки начинается ровно
30 секунд ожидания; есть отмена. Закрытие диалога также отменяет ожидание.
Одновременно разрешена одна попытка на приложение. После атомарного начала
навигации отмена уже не может отозвать отправленный запрос — это не обещание
закрыть или откатить уже открытый сайт.

Пользователь сам выбирает аккаунт в GameCenter и нажимает «Пополнить счёт».
Платить не нужно. Твиноферма не меняет браузер по умолчанию, не переключает и
не закрывает GameCenter или внешний браузер, не извлекает его cookies.

## Проверка привязки

Ключ существующего входа выбирается так же, как при запуске игры:
`character@gamecenter`, либо legacy-ключ персонажа. Rust читает `MyComUserUid`
из сохранённого входа в хранилище ОС. Он не передаётся в интерфейс. Если входа
или числового UID нет, автоматическое ожидание не продолжает авторизацию;
нужно заново выполнить «Запомнить вход» в правильном GameCenter.

Из новой командной строки известного браузера принимается только HTTPS URL с
точным хостом `auth-ac.vkplay.ru` и путём
`/oauth2/session/exchange/confirm/init`. Нужны ровно `token` и числовой `user_id`,
без повторов, других параметров, фрагмента или встроенного логина/пароля.
При несовпадении `user_id` и сохранённого `MyComUserUid` попытка останавливается
с сообщением о неправильном аккаунте. Привязка не заменяется автоматически.
Если сохранённый UID изменился во время ожидания, попытка также отклоняется.

Сравнение этих ID — проверяемое допущение для установленной версии GameCenter,
а не доказанный универсальный контракт VK Play. Автоматического угадывания
соответствия и обхода проверки при несовпадении нет.

## Наблюдение на Windows

Опрос раз в 200 мс работает только в явном 30-секундном окне. Сначала снимается
базовый набор PID/времён запуска: старые командные строки не переиспользуются.
Читаются только новые zen/firefox/chrome/msedge/brave/opera/vivaldi процессы
того же Windows-пользователя и сессии. Чтение — ограниченный запрос информации
процесса, не внедрение кода и не чтение cookies. Автоматического повышения прав нет.

Короткий процесс-посредник уже открытого браузера МОЖЕТ быть пропущен. Наличие
долго работающего основного браузера не гарантирует обнаружения URL. Нельзя
считать polling надёжным перехватом каждого запуска. Недоступный процесс и
истечение времени показываются без URL/токена; остаётся ручной способ в details.

## Открытие и проверка сайта

При совпадении ID Rust сам открывает ссылку через существующий браузер профиля
персонажа. Полный URL не возвращается через IPC и не вставляется в поле/журнал.
Используется отдельное cookie-хранилище персонажа независимо от настройки
браузера обычных ссылок. Затем UI запускает существующую проверку наличия входа.
Если страница ещё загружается или проверка недоступна, можно повторить её вручную.

Совпадение ID ссылки не подтверждает итоговую сессию: сайт мог сохранить другую
старую сессию или потребовать CAPTCHA/2FA. Автоматического сравнения личности
сессии пока нет. До массовых операций сверьте аккаунт в открытом сайте, закройте
и снова откройте сайт персонажа, затем повторите после перезапуска приложения.

## Секреты и ограничения

- Токен, cookies и URL не записываются в state, логи, результаты IPC или ошибки.
- Собственные строковые буферы нативной попытки очищаются по мере освобождения;
  полное стирание копий в ОС, парсере URL, WebView/браузере не гарантируется.
- Ручная вставка остаётся отдельным экспериментом, с прежним HTTPS allowlist.
- Не присылайте ссылки, токены, cookies или пароли. Достаточно версии GameCenter,
  домена без пути/параметров, факта совпадения ID и результата проверки сессии.

## Что ещё проверить на реальном Windows-ПК

Исходные наблюдения о Zen и повторном использовании перехода предоставлены
пользователем; в среде разработки GameCenter не установлен.

1. Повторно используемый переход после открытия Zen создаёт вход в чистом WebView.
2. Срок жизни, повторное использование через 5/10 минут.
3. `user_id` действительно совпадает с `MyComUserUid` выбранной сохранённой привязки.
4. Правильный и неправильный аккаунты, два прикреплённых GameCenter, отсутствие UID.
5. Zen уже открыт / закрыт; доступ к командной строке без прав администратора.
6. Отмена, закрытие диалога, таймаут и повторная попытка, без позднего открытия.
7. CAPTCHA/2FA без обхода; сохранение сессии после закрытия/перезапуска.

Наличие интерфейса и успешные автоматические тесты не доказывают прохождение
реальной авторизации VK Play. При одноразовой ссылке, отличающемся пространстве
ID или пропущенном запуске этот способ не объявляется рабочим автоматически.
