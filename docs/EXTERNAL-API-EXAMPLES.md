## Начало работы

### Проверить, что приложение живо

**Когда нужно.** Убедиться, что API отвечает, и заранее узнать текущие права: пока права «Изменение» выключены, любой PATCH вернёт 403.

`GET /api/v1/health` · право: чтение

#### Запрос

```bash
curl -s -X GET \
  -H "Authorization: Bearer <токен>" \
  http://127.0.0.1:47831/api/v1/health
```

#### Ответ

```json
{
  "ok": true,
  "app": {
    "version": "3.0.0",
    "build": "stable"
  },
  "api": {
    "version": 1,
    "uptimeSec": 128
  },
  "storage": {
    "writable": true
  },
  "scopes": {
    "read": true,
    "modify": true,
    "launchClose": true
  },
  "launch": {
    "busy": false
  }
}
```

#### Что это значит

`ok: true` — сервер на месте. `app.build` — профиль сборки (`stable`, `acceptance`, `acceptance-shared`): у тестовых сборок обновление выключено. `scopes` — текущие права: `modify` открывает PATCH/POST, `launchClose` — запуск и закрытие окон. `storage.writable: false` означает, что запись в базу заблокирована и изменения не сохранятся. `launch.busy: true` — уже идёт запуск, второй запрос получит 429.

#### Если придёт ошибка

| Код | Что делать |
| --- | --- |
| 401 `unauthorized` | Не передан заголовок `Authorization: Bearer <токен>` или токен перевыпущен в приложении. |

### Узнать всё одним запросом

**Когда нужно.** Программа хочет понять, что приложение живо и что в нём происходит, не разбирая пять списков: сколько персонажей, что осталось на сегодня, сколько денег в реестре, открыто ли окно игры.

`GET /api/v1/status` · право: чтение

#### Запрос

```bash
curl -s -X GET \
  -H "Authorization: Bearer <токен>" \
  http://127.0.0.1:47831/api/v1/status
```

#### Ответ

```json
{
  "ok": true,
  "app": {
    "version": "3.0.0",
    "build": "stable"
  },
  "api": {
    "version": 1,
    "uptimeSec": 128
  },
  "storage": {
    "writable": true
  },
  "scopes": {
    "read": true,
    "modify": true,
    "launchClose": true
  },
  "launch": {
    "busy": false
  },
  "counts": {
    "characters": 3,
    "parties": 2,
    "marathons": 1,
    "plannerEntries": 12,
    "windows": 1,
    "financeOperations": 7
  },
  "today": {
    "date": "2026-11-24",
    "total": 4,
    "done": 1
  },
  "finance": {
    "balances": {
      "gold": 125000,
      "coins": 340
    }
  }
}
```

#### Что это значит

`counts` — размеры списков, `today` — дела на сегодня (`done` из `total`), `finance.balances` — текущий баланс реестра денег. Здесь нет ни контактов, ни паролей, ни содержимого заметок: сводка безопасна для показа в чужой программе. Если нужно больше — берите адресные методы (`/characters`, `/planner`, `/finance`).

#### Если придёт ошибка

| Код | Что делать |
| --- | --- |
| 401 `unauthorized` | Нет токена или он перевыпущен. |

## Чтение данных

### Кто есть в твин-ферме

**Когда нужно.** Своя программа хочет показать список персонажей: id, класс, уровень и проходки — и не тянуть лишние поля.

`GET /api/v1/characters` · право: чтение

#### Запрос

```bash
curl -s -X GET \
  -H "Authorization: Bearer <токен>" \
  http://127.0.0.1:47831/api/v1/characters?fields=id,nick,class,level,dungeonPasses
```

#### Ответ

```json
{
  "characters": [
    {
      "id": "Mag_1",
      "nick": "Маг",
      "class": "Маг",
      "level": 100,
      "dungeonPasses": {
        "weapon": 2,
        "armor": 1,
        "relic": 0
      }
    },
    {
      "id": "Luchnik_2",
      "nick": "Лучник",
      "class": "Лучник",
      "level": 99,
      "dungeonPasses": {
        "weapon": 1,
        "armor": 1,
        "relic": 0
      }
    }
  ],
  "count": 2,
  "fields": [
    "id",
    "nick",
    "class",
    "level",
    "dungeonPasses"
  ]
}
```

#### Что это значит

`fields` ограничивает ответ: вложенные поля пишутся через точку (`stats.hp`, `dungeonPasses.weapon`). `count` — сколько строк вернулось после фильтра, а не сколько всего. Ещё полезно: `party` (только одна пати), `sort`/`order`, `lang=ru` — русские подписи.

#### Если придёт ошибка

| Код | Что делать |
| --- | --- |
| 422 `invalid_value` | В `fields` есть неизвестное поле — API отвечает списком допустимых имён. |

### Карточка одного персонажа

**Когда нужно.** Нужно узнать, что за персонаж и в каком он окне игры сейчас.

`GET /api/v1/characters/{id}` · право: чтение

#### Запрос

```bash
curl -s -X GET \
  -H "Authorization: Bearer <токен>" \
  http://127.0.0.1:47831/api/v1/characters/Mag_1
```

#### Ответ

```json
{
  "character": {
    "id": "Mag_1",
    "nick": "Маг",
    "class": "Маг",
    "level": 100,
    "stats": {
      "hp": 40
    },
    "dungeonPasses": {
      "weapon": 2,
      "armor": 1,
      "relic": 0
    },
    "running": {
      "pid": 4321,
      "title": "Маг — Маг"
    }
  }
}
```

#### Что это значит

`running` — окно игры этого персонажа: `pid` нужен, чтобы закрыть окно, `title` — заголовок окна. `null` означает, что персонаж сейчас не запущен. Идентификатор персонажа — это `id` в адресе: он же используется во всех правках.

#### Если придёт ошибка

| Код | Что делать |
| --- | --- |
| 404 `not_found` | Персонажа с таким id нет. Список id — в `GET /characters`. |

### Кто сейчас в игре

**Когда нужно.** Своя программа хочет показать открытые окна игры и понять, к какому персонажу какое относится.

`GET /api/v1/windows` · право: чтение

#### Запрос

```bash
curl -s -X GET \
  -H "Authorization: Bearer <токен>" \
  http://127.0.0.1:47831/api/v1/windows
```

#### Ответ

```json
{
  "windows": [
    {
      "pid": 4321,
      "title": "Маг — Маг",
      "known": true,
      "charId": "Mag_1",
      "nick": "Маг"
    }
  ]
}
```

#### Что это значит

`pid` — идентификатор процесса: он нужен для закрытия окна. `known: false` — окно игры, но персонаж ему не сопоставлен; закрывать такое окно можно, но вот привязать к персонажу нельзя.

### Что запланировано

**Когда нужно.** Программа показывает список дел на сегодня и на будущее — из планировщика приложения.

`GET /api/v1/planner` · право: чтение

#### Запрос

```bash
curl -s -X GET \
  -H "Authorization: Bearer <токен>" \
  http://127.0.0.1:47831/api/v1/planner
```

#### Ответ

```json
{
  "entries": [
    {
      "id": "pe_1",
      "title": "Ежедневка",
      "date": "2026-11-24",
      "time": "",
      "durationMinutes": 60,
      "kind": "task",
      "priority": "normal",
      "recurrence": "daily",
      "status": "todo",
      "notes": ""
    }
  ]
}
```

#### Что это значит

У повторяющейся записи (`recurrence: daily`) своё состояние на каждый день: общий `status` показывает последний день, а точный статус за конкретный день меняется через `PATCH` с полем `date`. Правку записи делает рецепт «Отметить задачу».

### Реестр денег

**Когда нужно.** Своя программа показывает приход, расход, позиции магазина и долги.

`GET /api/v1/finance` · право: чтение

#### Запрос

```bash
curl -s -X GET \
  -H "Authorization: Bearer <токен>" \
  http://127.0.0.1:47831/api/v1/finance
```

#### Ответ

```json
{
  "operations": [
    {
      "id": "op_1",
      "date": "2026-11-24",
      "currency": "gold",
      "kind": "in",
      "amount": 25000,
      "counterparty": "Продажа зелья",
      "note": "",
      "characterId": null
    }
  ],
  "shopItems": [],
  "loans": []
}
```

#### Что это значит

`kind: in` — приход, `out` — расход; `currency` — `gold` или `coins`. Реестр — единственная правда о деньгах: записи из интерфейса и из API округляются одинаково, поэтому суммы не расходятся.

#### Запрос

```bash
curl -s -X GET \
```

## Изменение данных

### Поставить стат персонажу

**Когда нужно.** Своя программа вносит правку в карточку: например, поправить HP после боя. У нас есть право «Изменение статов и проходок».

`PATCH /api/v1/characters/{id}/stats/{stat}` · право: изменение

Тело запроса:

```json
{
  "value": 40
}
```

#### Запрос

```bash
curl -s -X PATCH \
  -H "Authorization: Bearer <токен>" \
  -H "Content-Type: application/json" \
  -d '{"value":40}' \
  http://127.0.0.1:47831/api/v1/characters/Mag_1/stats/hp
```

#### Ответ

```json
{
  "id": "Mag_1",
  "nick": "Маг",
  "stat": "hp",
  "value": 40,
  "before": 35,
  "changed": true
}
```

#### Что это значит

Тело — `{"value": N}`: поставить значение. `{"mode":"inc","by":5}` — прибавить, `{"mode":"dec","by":5}` — отнять. В ответе `before` — что было, `value` — что стало: разницу видно сразу, а история «было → стало» сохраняется в базе.

#### Если придёт ошибка

| Код | Что делать |
| --- | --- |
| 403 `forbidden_scope` | В настройках приложения выключено право «Изменение статов и проходок». |
| 422 `invalid_value` | Такого стата нет: список допустимых — в `GET /characters/{id}/stats`. |

### Поставить проходку

**Когда нужно.** Отметить, что оружие усилено до второго уровня.

`PATCH /api/v1/characters/{id}/dungeon-passes/{pass}` · право: изменение

Тело запроса:

```json
{
  "value": 2
}
```

#### Запрос

```bash
curl -s -X PATCH \
  -H "Authorization: Bearer <токен>" \
  -H "Content-Type: application/json" \
  -d '{"value":2}' \
  http://127.0.0.1:47831/api/v1/characters/Mag_1/dungeon-passes/weapon
```

#### Ответ

```json
{
  "id": "Mag_1",
  "nick": "Маг",
  "pass": "weapon",
  "value": 2,
  "before": 1,
  "total": 3,
  "changed": true
}
```

#### Что это значит

Проходки — `weapon`, `armor`, `relic`. `total` — сколько всего усилений у этого вида, `value` — текущий уровень. Как и у статов, в ответе видно, что было до правки.

#### Если придёт ошибка

| Код | Что делать |
| --- | --- |
| 403 `forbidden_scope` | Нет права «Изменение статов и проходок». |

### Отметить задачу в планировщике

**Когда нужно.** Своя программа закрывает дело: ставит «сделано» или переносит запись на другой день. Запись должна вести себя ровно так же, как в интерфейсе приложения.

`PATCH /api/v1/planner/entries/{id}` · право: изменение

Тело запроса:

```json
{
  "status": "done",
  "date": "2026-11-24"
}
```

#### Запрос

```bash
curl -s -X PATCH \
  -H "Authorization: Bearer <токен>" \
  -H "Content-Type: application/json" \
  -d '{"status":"done","date":"2026-11-24"}' \
  http://127.0.0.1:47831/api/v1/planner/entries/pe_1
```

#### Ответ

```json
{
  "entry": {
    "id": "pe_1",
    "title": "Ежедневка",
    "date": "2026-11-24",
    "time": "",
    "status": "done"
  },
  "statusDate": "2026-11-24",
  "statusValue": "done",
  "changed": [
    "status"
  ]
}
```

#### Что это значит

Поля: `status` (`todo`, `doing`, `done`), `date` — день, к которому относится статус (для повтора это конкретный день: у повторов своё состояние на каждый день), `moveToDate` — перенести саму запись на другой день, `title`, `time`. Ответ `changed` перечисляет, что действительно поменялось, а `statusDate` и `statusValue` показывают состояние именно за запрошенный день: у повтора оно своё, поэтому отметка не сбрасывается — отметили вчера, сегодня снова «не сделано».

#### Если придёт ошибка

| Код | Что делать |
| --- | --- |
| 403 `forbidden_scope` | Нет права «Изменение статов и проходок». |
| 404 `no_such_entry` | Записи с таким id нет: id берётся из `GET /planner`. |
| 422 `invalid_value` | Неизвестное поле или неверная дата (нужен формат `ГГГГ-ММ-ДД`). |

### Создать задачу в планировщике

**Когда нужно.** Программа добавляет дело в календарь: «сходить в игру на 19:00».

`POST /api/v1/planner/entries` · право: изменение

Тело запроса:

```json
{
  "title": "Сходить в игру",
  "date": "2026-11-24",
  "time": "19:00",
  "durationMinutes": 120,
  "kind": "task"
}
```

#### Запрос

```bash
curl -s -X POST \
  -H "Authorization: Bearer <токен>" \
  -H "Content-Type: application/json" \
  -d '{"title":"Сходить в игру","date":"2026-11-24","time":"19:00","durationMinutes":120,"kind":"task"}' \
  http://127.0.0.1:47831/api/v1/planner/entries
```

#### Ответ

```json
{
  "entry": {
    "id": "pe_2",
    "title": "Сходить в игру",
    "date": "2026-11-24",
    "time": "19:00",
    "status": "todo"
  }
}
```

#### Что это значит

Обязательно только `title`; остальное необязательно: `date` (сегодня, если не указать), `time`, `durationMinutes`, `kind` (`task`, `event`, `note`), `priority`, `recurrence` (`none`, `daily`, `weekly`, `monthly`). Запись создаётся тем же нормализатором, что и в интерфейсе, поэтому повторы и длительность посчитаются одинаково.

#### Если придёт ошибка

| Код | Что делать |
| --- | --- |
| 403 `forbidden_scope` | Нет права «Изменение статов и проходок». |
| 422 `invalid_value` | Пустое `title` или неизвестное поле — API отвечает, что именно не так. |

### Записать приход или расход

**Когда нужно.** Своя программа ведёт реестр денег рядом с приложением: продал зелье — записал приход, купил расходник — записал расход.

`POST /api/v1/finance/operations` · право: изменение

Тело запроса:

```json
{
  "kind": "in",
  "amount": 25000,
  "currency": "gold",
  "date": "2026-11-24",
  "note": "Продажа зелья"
}
```

#### Запрос

```bash
curl -s -X POST \
  -H "Authorization: Bearer <токен>" \
  -H "Content-Type: application/json" \
  -d '{"kind":"in","amount":25000,"currency":"gold","date":"2026-11-24","note":"Продажа зелья"}' \
  http://127.0.0.1:47831/api/v1/finance/operations
```

#### Ответ

```json
{
  "operation": {
    "id": "op_2",
    "kind": "in",
    "amount": 25000,
    "currency": "gold",
    "date": "2026-11-24",
    "counterparty": "",
    "note": "Продажа зелья"
  }
}
```

#### Что это значит

`kind` — `in` (приход) или `out` (расход, по умолчанию), `amount` — положительное число, `currency` — `gold` или `coins`. Запись идёт через модель учёта приложения: сумма округляется под валюту, поэтому балансы в приложении и в своей программе не разойдутся.

#### Если придёт ошибка

| Код | Что делать |
| --- | --- |
| 403 `forbidden_scope` | Нет права «Изменение статов и проходок». |
| 422 `invalid_value` | Сумма не положительна или валюта неизвестна. |

### Добавить персонажа

**Когда нужно.** Программа заводит нового персонажа в твин-ферме.

`POST /api/v1/characters` · право: изменение

Тело запроса:

```json
{
  "id": "Mag_3",
  "nick": "Маг",
  "class": "Маг",
  "level": 1
}
```

#### Запрос

```bash
curl -s -X POST \
  -H "Authorization: Bearer <токен>" \
  -H "Content-Type: application/json" \
  -d '{"id":"Mag_3","nick":"Маг","class":"Маг","level":1}' \
  http://127.0.0.1:47831/api/v1/characters
```

#### Ответ

```json
{
  "character": {
    "id": "Mag_3",
    "nick": "Маг",
    "class": "Маг",
    "level": 1
  }
}
```

#### Что это значит

Обязателен `id` — он же станет именем файла персонажа и ключом во всех правках. `nick`, `class`, `level` необязательны, но без них персонаж будет выглядеть пустым в списке.

#### Если придёт ошибка

| Код | Что делать |
| --- | --- |
| 403 `forbidden_scope` | Нет права «Изменение статов и проходок». |

## Запуск и окна

### Запустить пати

**Когда нужно.** Нажали «играть» у пати: окна должны открыться в порядке участников, а не одновременно.

`POST /api/v1/launch/party` · право: запуск и закрытие окон

Тело запроса:

```json
{
  "partyName": "Основа"
}
```

#### Запрос

```bash
curl -s -X POST \
  -H "Authorization: Bearer <токен>" \
  -H "Content-Type: application/json" \
  -d '{"partyName":"Основа"}' \
  http://127.0.0.1:47831/api/v1/launch/party
```

#### Ответ

```json
{
  "jobId": "job_1",
  "state": "running",
  "accepted": 2,
  "skipped": []
}
```

#### Что это значит

Ответ — `202`: запуск идёт в фоне, приложение не блокируется. Дальше состояние смотрится по `jobId`: `GET /api/v1/jobs/{jobId}` → `state` (`running`, `done`, `failed`) и `skipped` — список участников, которых пропустили, с причиной. Нужен запуск только для одного окна — `POST /launch/character`, для выбранных в нужном порядке — `POST /launch/selection`.

#### Если придёт ошибка

| Код | Что делать |
| --- | --- |
| 403 `forbidden_scope` | Выключено право «Запуск и закрытие окон». |
| 429 `launch_busy` | Уже идёт другой запуск: одно задание одновременно. |

### Дождаться запуска

**Когда нужно.** Программа запустила пати и хочет показать прогресс: что открылось, что нет и почему.

`GET /api/v1/jobs/{jobId}` · право: чтение

#### Запрос

```bash
curl -s -X GET \
  -H "Authorization: Bearer <токен>" \
  http://127.0.0.1:47831/api/v1/jobs/job_1
```

#### Ответ

```json
{
  "job": {
    "jobId": "job_1",
    "state": "done",
    "done": 2,
    "skipped": []
  }
}
```

#### Что это значит

`state` — `running`, `done` или `failed`. `skipped` — честный список: кто не запустился и по какой причине (например, «персонаж уже в игре»). Задание живёт недолго: если `jobId` протух, придёт 404 — тогда нужно запускать заново.

#### Если придёт ошибка

| Код | Что делать |
| --- | --- |
| 404 `not_found` | Задание не найдено или устарело. |

### Закрыть окна игры

**Когда нужно.** Программа закрывает окна, о которых сказал человек. Закрытие необратимо, поэтому требует явного подтверждения.

`POST /api/v1/windows/close` · право: запуск и закрытие окон

Тело запроса:

```json
{
  "pids": [
    4321
  ],
  "confirm": true
}
```

#### Запрос

```bash
curl -s -X POST \
  -H "Authorization: Bearer <токен>" \
  -H "Content-Type: application/json" \
  -d '{"pids":[4321],"confirm":true}' \
  http://127.0.0.1:47831/api/v1/windows/close
```

#### Ответ

```json
{
  "found": 1,
  "closed": 1,
  "failed": 0,
  "denied": 0,
  "elevated": false,
  "details": [],
  "error": ""
}
```

#### Что это значит

Закрываются именно `pid` из `GET /windows`, а не персонажи: pid — это процесс, он однозначен. `confirm: true` обязателен — без него придёт 400 `confirm_required`. В ответе `closed` — сколько окон реально закрылось, `failed` и `denied` — сколько не закрылось и почему.

#### Если придёт ошибка

| Код | Что делать |
| --- | --- |
| 400 `confirm_required` | Не хватает `"confirm": true` — закрывать окна без подтверждения нельзя. |
| 403 `forbidden_scope` | Выключено право «Запуск и закрытие окон». |

## Диагностика ошибок

### 401 unauthorized: не тот токен

**Когда нужно.** Программа вдруг начала получать 401, хотя вчера всё работало.

`GET /api/v1/health` · право: чтение

#### Запрос

```bash
curl -s -X GET \
  -H "Authorization: Bearer <токен>" \
  http://127.0.0.1:47831/api/v1/health
```

#### Ответ

```json
{
  "error": {
    "code": "unauthorized",
    "message": "Нужен заголовок Authorization: Bearer <токен>"
  }
}
```

#### Что это значит

Токен перевыпускается в приложении: «Настройки → 🔌 Внешний API → Перевыпустить». Старый токен после этого не работает. Бывает и другое: в заголовке `Bearer` без пробела, токен с пробелами или кавычками внутри — его надо вырезать целиком, без переносов строки.

### 403 forbidden_scope: не хватает права

**Когда нужно.** Чтение работает, а PATCH отвечает 403 — как понять, что именно сломано.

`PATCH /api/v1/characters/{id}/stats/{stat}` · право: изменение

Тело запроса:

```json
{
  "value": 40
}
```

#### Запрос

```bash
curl -s -X PATCH \
  -H "Authorization: Bearer <токен>" \
  -H "Content-Type: application/json" \
  -d '{"value":40}' \
  http://127.0.0.1:47831/api/v1/characters/Mag_1/stats/hp
```

#### Ответ

```json
{
  "error": {
    "code": "forbidden_scope",
    "message": "Нужно право «Изменение статов и проходок»"
  }
}
```

#### Что это значит

Права проверяются дважды: в Rust (по таблице маршрутов) и в мосте (по текущим настройкам). Значит, либо выключено право в настройках приложения, либо маршруту нужно другое право: запуск и закрытие окон — «Запуск и закрытие окон», а не «Изменение». Текущие права видно в `GET /health` → `scopes`.

### 422 invalid_value: запрос не поняли

**Когда нужно.** Ответ 422: значит адрес и права в порядке, но содержимое запроса не подошло.

`PATCH /api/v1/planner/entries/{id}` · право: изменение

Тело запроса:

```json
{
  "status": "готово"
}
```

#### Запрос

```bash
curl -s -X PATCH \
  -H "Authorization: Bearer <токен>" \
  -H "Content-Type: application/json" \
  -d '{"status":"готово"}' \
  http://127.0.0.1:47831/api/v1/planner/entries/pe_1
```

#### Ответ

```json
{
  "error": {
    "code": "invalid_value",
    "message": "status: todo, doing или done"
  }
}
```

#### Что это значит

Сообщение в ответе объясняет, что именно не так: неизвестное поле, пустое название, неверная дата (`ГГГГ-ММ-ДД`) или недопустимое значение статуса. Значения перечисляются прямо в тексте ошибки — обычно достаточно поправить одно поле.

### 429: лимит запросов

**Когда нужно.** Программа долго шлёт запросы и начала получать отказы.

`GET /api/v1/characters` · право: чтение

#### Запрос

```bash
curl -s -X GET \
  -H "Authorization: Bearer <токен>" \
  http://127.0.0.1:47831/api/v1/characters
```

#### Ответ

```json
{
  "error": {
    "code": "too_many_requests",
    "message": "Слишком много запросов"
  }
}
```

#### Что это значит

Ограничение — 60 запросов в минуту с одного адреса (окно 60 секунд, с запасом на всплески). В ответе есть заголовок `Retry-After`: столько секунд надо подождать. Чаще всего виноват цикл без паузы: сначала спросите `GET /status` и забирайте всё нужное одним запросом.
