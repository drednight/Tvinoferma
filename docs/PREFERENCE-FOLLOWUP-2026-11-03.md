# Follow-up 2026-11-03: границы выполненного блока

## Реализовано

- Demo2: пять дополнительных вариантов 07–11 на девяти страницах (45 новых,
  всего 99 demo2). Изоляция от состояния приложения, OAuth и сайта сохранена.
- Передача: «Далее» открывает свежую проверку/выбор точных наборов; кнопка
  отправки находится в этом предпросмотре и ведёт в прежнее подтверждение,
  резервное копирование и runner. Неделимые наборы и проверки native не изменены.
- Магазин: левый выбор ограничивает видимые аккаунты; общий refresh по-прежнему
  читает все аккаунты, refresh таблицы — только отмеченные. Общее владение
  аккаунтом и обновление балансов остальных его персонажей сохранены.
- Лимиты: только найденные предметы с явным конечным остатком; известный общий
  месячный максимум из сайта показывается в описании, не как остаток персонажа.
- Таблица ограничена по высоте, горизонтальная полоса ближе, заголовки одной
  высоты с полным названием в tooltip.
- Иконки: только прочитанные URL предметов HTTPS pwonline.ru/www.pwonline.ru,
  без referrer, credentials/query/fragment; ограниченная img-src CSP. Иных
  хостов, guessed mappings, скачанных похожих иконок нет. Если сайт не даёт URL,
  используется нейтральный знак, а не придуманная иллюстрация. Реальная полнота
  иконок на сайте пока не подтверждена; файлы пользователя всё ещё могут понадобиться.
- Ключ/доппараметры: только хранение ключа и автоматическая проверка. Ручное
  обновление, результаты, файлы, статус и повторное открытие сравнения на основной
  странице. Различия сгруппированы по категориям, каждая изначально свёрнута.

## Диагностика / НЕ исправлено этим блоком

- Callback уже пытается закрыть вкладку через 700 мс. Браузер может запретить
  window.close у вкладки, открытой системным браузером; гарантировать закрытие
  нельзя. Не ослаблялись CSP/state/PKCE и не добавлялись попытки обойти браузер.
- Yandex signed_out: путь resume с проверкой прежнего клиента/аккаунта/слота уже
  существует и покрыт синтетическими тестами. Реальная причина сообщения после
  успешного редиректа не установлена. Получение callback не доказывает успешную
  проверку аккаунта/подтверждение/запись credential. Никакие credentials не сбрасывались.
- `setup/identities/roundtrip.materialize/invalid`: валидатор полной замены не
  отключён. Повторные ID пати (2 по отчёту пользователя) делают членство неоднозначным;
  ID и связи не исправлялись молча. Сам код materialize/invalid не доказывает, что
  единственная причина именно эти ID; нужна воспроизводимая безопасная диагностика.
- Пока НЕ реализованы пользовательское сопоставление локальных/облачных персонажей,
  выбор полей вместо полной замены и диалог разрешения дублей по нику + контактам
  с запоминанием решения. Одинаковый ник не считается доказательством личности.
  Текущая полная замена сохраняет локальные launch/login/contacts лишь для уже
  сопоставленных syncId; это не решение требования о сохранении привязок одноимённых
  персонажей с разными syncId. Поэтому полную замену не предлагаем как обход.
- Новости demo2 — реальные заголовки/URL из сохранённых обезличенных фикстур,
  но не проверенная лента последних публикаций на 3 ноября.
- Приёмка реального сайта, Yandex/Google и двух Windows-ПК не выполнялась.
  CI и тестовый exe не являются такой приёмкой; release не создаётся.

## Следующий безопасный блок

1. Установить, на каком этапе Yandex заканчивается без сохранённой credential,
   используя только безопасные коды результата, без токенов/контактов/raw JSON.
2. Объяснимое разрешение неоднозначных пати с показом связей и backup, а не
   безусловная перенумерация или отключение roundtrip-проверки.
3. Явное сопоставление идентичностей и выбор полей с сохранением локальных
   привязок/контактов, stale-preview guards и воспроизводимыми тестами.
4. Отдельное сравнение дублей ник+контакты и выбор оставить оба/удалить один,
   решение с защитой от изменения данных и обязательным резервным копированием.

## Дополнение после PR172: точечные исправления и безопасное обновление

Предыдущий список описывает состояние PR172. В следующем блоке выполнены:

- Передача: footer `Пробный запуск → Далее`; в подтверждении только число
  аккаунтов и наборов, без суммы предметов.
- Магазин: любой выбор (preset, все, пати, ручной, общий аккаунт) допускает
  только `isLoggedIn === true`. Offline и неизвестный вход не отмечаются.
- Лимиты: поиск по персонажу/классу/аккаунту, предмет, остаток/исчерпано/без
  указанного лимита/нет данных. Последние два фильтра дают одну сводку на
  персонажа, а не восемь выдуманных лимитов. Обновление справа внизу запускает
  существующий read-only scanner; повторный запуск блокируется, фильтры сохраняются.
- Парсер читает `Доступно: N из Х` и `Доступно Вам: N из Х`; Х имеет приоритет
  над старым месячным текстом и оценками из истории. Остаток N не изображается
  максимальным лимитом. Общая информация находится только внутри «Описание».
- Облачное сравнение сначала предлагает явное сопоставление существующих
  персонажей и выбор публичных полей. Ник — подсказка, не доказательство.
  Сопоставления сохраняются локально по отпечатку провайдера/аккаунта и source
  syncId; сами local/syncId не меняются. Одинаковые ID можно предлагать как
  существующую идентичность, но поля и подтверждение никогда не выбираются автоматически.
- Обновление не удаляет и не создаёт персонажей, не меняет архивность, контакты,
  GameCenter, партии, задачи, vault, ключи, pending-файлы и accepted/base receipt.
  Это **не принятие полной копии**, не отправка и не общий трёхсторонний merge.
  Перед guarded записью повторно сверяются local witness, аккаунт и hash файла;
  создаётся backup `pre-cloud-character-update`. Дубликаты ID пати не чинятся.
- Полная замена остаётся отдельным свёрнутым опасным режимом со всеми прежними
  materialize/roundtrip/backup/consent guards. Она не используется как обход
  для выборочного обновления.
- Yandex: регистрационная проверка отделена в диагностике от настоящего входа;
  видны local/browser/token/identity/confirmation/install/readback и фиксированный
  результат/код OAuth. Заблокированный вход объясняется на основной странице;
  успешная установка явно подтверждается. В отчёт не попадают Client ID, аккаунт,
  токены, URLs, provider body и сырые исключения. Защиты pinned account/slot,
  dataset и неизвестного результата не ослаблены.

### Всё ещё требуется

1. Воспроизвести реальный Yandex-сбой на Windows: прежний `credential_missing`
   не доказывает причину остановки OAuth. Новая трасса предназначена для её
   установления; это не заявление об исправлении реального входа пользователя.
2. Приёмка сайта (`N из Х`, фильтры, логин) и двух ПК с разными GameCenter.
3. Добавление новых персонажей и сопоставление остальных сущностей вне режима
   полной замены; отдельный осознанный перенос выбранных приватных полей.
4. Отдельный диалог дублей ник+контакты: сравнить один раз и явно решить
   оставить оба / удалить один. В этом блоке **никого не удаляем**.
5. Разрешение неоднозначных пати со связями и backup, без перенумерации вслепую;
   реальный `roundtrip.materialize/invalid` по-прежнему требует воспроизведения.
6. Изображения предметов — только после исходного файла пользователя.

Локально проверяются изменённые сценарии, lint/typecheck/format/build и Chromium
на синтетических данных. Полный набор регрессий и тестовый Windows exe проверяет
CI для конкретного head. Это не приёмка реальных аккаунтов и не release.
