## Стоп

Док и кнопка в окне используют один `Task.stop`. Флаг очереди устанавливается
сразу; затем существующий native cancel закрывает **только скрытые окна текущих
scope**. Уничтожение документа прекращает его JS, таймеры, fetch и наблюдатели,
вместо ожидания полного скрипта/проверки результата на сайте. Между стадиями
native повторно проверяет отмену перед навигацией, инжекцией и нажатием.
Ожидание пула тоже отменяется; слот не выдаётся до очистки. На ошибке/отмене
сессия из банка не заменяется пустыми cookie закрытого окна. Видимые ручные
окна/игра не уничтожаются. Следующий явный запуск снимает отмену после ack
предыдущей остановки, а не одновременно со Stop.

Нельзя гарантированно отменить **уже отправленный** сайту запрос или атомарно
синхронизировать клик UI с ответом сервера. Известный подтверждённый результат
сохраняется; если нажатие могло произойти, но ответ потерян — unknown/uncertain,
не успех, не «точно не выполнено», без автоматического повтора. Очистка окон и
журналирование — не попытка «доделать» покупку/передачу/активацию.

## Поиск промокодов

1. Только публичные страницы `pwonline.ru/news.php`: индексы **1 и 2**
   (`archive=news&type=last`), затем каждая уникальная новость из этих индексов.
2. Только явные официальные ссылки `/pin/<код>`, включая `./pin/` и абсолютные.
   Случайные латинские слова из текста не становятся кодами. Новость и код
   сохраняются как источник; посещения `/pin/` и активации здесь нет.
3. HTML разбирается инертно, не встраивается в UI. Cookie персонажей/авторизация
   не используются. Native GET строит URL сам, запрещает произвольные адреса,
   перенаправления, proxy, повторы и слишком большие ответы (2 MiB).
   UTF-8 и Windows-1251 поддержаны.
4. Срок — осторожный текстовый фрагмент рядом со ссылкой. Полная явная дата
   проверяется; год/время/часовой пояс не выдумываются. Несколько кодов с разными
   условиями требуют просмотра новости. Отсутствие срока ≠ бессрочный код.
5. Коды появляются вариантами в настоящем окне промокодов. «Добавить код» только
   дополняет поле, ничего не запускает. По известной истёкшей дате кнопка отключена.
   Счётчик использует только подтверждённые записи местного журнала: отсутствие
   записи называется «нет подтверждения», не доказанным отсутствием активации.

## Расписание и время

Пока выбран щадящий режим: фоново после готовности приложения и при открытии
окна промокодов, **не чаще раза в день по Москве**. Одновременные вызовы делят
одну проверку. Есть ручная кнопка «Проверить новости сейчас». Проверка в 00:00
пока не включена: пользователь ещё выбирает расписание.

Два запроса одновременно, до 80 новостей, максимум 8 секунд на один запрос
(3 секунды соединение), бюджет выдачи новых запросов 60 секунд. Уже начатые
два запроса могут добавить до 8 секунд к бюджету. Загрузка UI не ждёт сеть.
Успешно прочитанные статьи сохраняют отметки дня; частичная проверка может
продолжиться без повторного чтения успешных статей. После ошибки автоматический
повтор не раньше 10 минут; ручной — по кнопке. Старые найденные коды не удаляются
из-за offline/403/изменения разметки. Причины фиксированные `news_*`, а не HTML
или сырые исключения. Сброс приложения ограждён от поздней записи проверки.

Реальные секунды **не измерены**: sandbox не имеет доступа к pwonline.ru.
Для N уникальных статей требуется 2+N GET в полном проходе. Ожидаемый порядок
времени — секунды/десятки секунд, а не обещанное число: зависит от TLS/сайта и
anti-bot. UI показывает фактическую длительность, прогресс и частичный результат.
HTTP 403/challenge — незавершённая проверка, без обхода защиты и без «кодов нет».
Нужна проверка на настоящем Windows ПК перед обещанием работы сайта.
