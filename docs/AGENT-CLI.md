# `tf` — командная строка для агентов и скриптов

> Документ описывает `scripts/tf/` — тонкий CLI поверх [внешнего API](EXTERNAL-API.md).
> Он нужен, когда `curl` неудобен: агент или скрипт хочет читать данные Твинофермы и,
> с явного разрешения пользователя, запускать окна — не разбирая таблицу статусов.
> Для человека в интерфейсе есть то же самое: страница API
> («Настройки → 🔌 Внешний API» → «Открыть страницу API»), вкладка «Действия».

## 1. Что это и чего в нём нет

`tf` — Node-скрипт без зависимостей. Он умеет ровно четыре вещи:

1. собрать аргументы командной строки в запрос;
2. отправить его в `http://127.0.0.1:<порт>/api/v1` с Bearer-токеном;
3. дождаться задания, если это запуск (`--wait`);
4. напечатать ответ — человеку текстом, скрипту одним JSON-объектом.

Логики данных здесь нет намеренно. Всё, что знает о персонажах, марафонах и запуске,
приложение уже знает в JS-мосте; вторая реализация неизбежно разошлась бы с первой —
ровно от этого в проекте защищают тесты `externalApiActions.test.js`,
`externalApiRecipes.test.js` и `docs:api-examples:check`.

Список команд `tf` не хранит: он строится из
`src-tauri/src/external_api/web/actions.js` — того же каталога, что рисует вкладку
«Действия» на странице API. Отсюда главное свойство CLI: **новое действие страницы
становится командой само**, а расхождение ловит `tests/agentCli.test.js` (34 маршрута в
справочнике ↔ 34 команды, в обе стороны).

Почему Node, а не отдельный бинарник: в репозитории нет ни Rust-инструментов для CLI,
ни Python, а новый бинарник означал бы отдельный `Cargo.lock` с сетевыми зависимостями
(`clap`, HTTP-клиент) и ещё один слой, который надо собирать под Windows. Node уже
инструмент проекта (`npm run build`, `npm test`, `scripts/*.mjs`), и CLI на нём
тестируется общим `npm test` за десятки миллисекунд. Если понадобится поставка
«одним .exe» — это отдельная задача, контракт от этого не изменится.

## 2. Запуск

```powershell
# из копии репозитория
npm run tf -- status --json
node scripts/tf/tf.mjs characters --json                    # краткий список: id и ник
node scripts/tf/tf.mjs characters --detail=list --json      # карточки без статов и заметок
node scripts/tf/tf.mjs characters --full --json             # те же строки со статами, заметками и историей монет
node scripts/tf/tf.mjs list-character-stats --json          # статы и проходки у всех + суммы (totals)
node scripts/tf/tf.mjs describe launch-party
```

Нужен Node 18+ (из-за глобального `fetch`). Приложение должно быть запущено, а внешний
API включён: «Настройки → 🔌 Внешний API» → «Разрешить внешним программам управлять
Твинофермой».

### Адрес

| Источник | Значение |
| --- | --- |
| по умолчанию | `http://127.0.0.1:47831` |
| тестовая (acceptance) сборка | `http://127.0.0.1:47832` |
| `TF_API_PORT` / `--port` | порт по умолчанию меняется на указанный |
| `TF_API_BASE` / `--base` | полный адрес; `…/api/v1` на конце можно писать или нет |

`--base` принимает только `127.0.0.1` или `localhost`: API не слушает другие интерфейсы,
и CLI не делает вид, что умеет работать по сети.

### Токен

Токен берётся **только** из окружения или из файла — флага `--token` нет сознательно:
командную строку видно в `ps`, в истории оболочки и в журнале агента. Приложение
хранит токен в хранилище ОС и тоже не принимает его аргументом — CLI держит ту же
планку.

```powershell
# 1) переменная окружения (для одного запуска)
$env:TF_API_TOKEN = "<токен, скопированный при перевыпуске>"
node scripts/tf/tf.mjs status --json

# 2) файл (для планировщика или systemd-юнита)
node scripts/tf/tf.mjs status --token-file C:\Users\me\.tvinoferma\api-token --json
```

Взять токен: «Настройки → 🔌 Внешний API» → «Скопировать токен» — кнопка читает
значение из хранилища ОС и ничего не меняет, поэтому вставить его в `TF_API_TOKEN`
можно в любой момент, не ломая уже работающие скрипты. «Показать токен» выводит
значение на экран на минуту и гаснет само.
«Перевыпустить токен» нужен, только если токен утёк: после него старые клиенты
получают `401`, и `TF_API_TOKEN` придётся обновить везде — это ожидаемое поведение
перевыпуска, а не поломка.
Значение `TF_API_TOKEN_FILE` работает как переменная (файл читается до первого перевода
строки). Ни один вывод `tf` токен не содержит: в dry-run заголовок показан как
`Bearer <скрыт>`.

## 3. Команды

```
tf                        справка по всем командам
tf ls                     список команд; `tf ls --json` — машиночитаемый каталог
tf describe <команда>    поля, право, пример запроса
tf <команда> [аргументы] [--флаг значение] [--json]
tf call <МЕТОД> <путь> [--body '<json>'] [--yes]   прямой запрос, если команды нет
```

Команда = id действия из каталога. Право доступа (столбец «нужен `--yes`») — из того же
описания, поэтому обмануть CLI нельзя: `--yes` не даёт прав, которых нет в настройках.

### Чтение (работает сразу)

| Команда | Маршрут |
| --- | --- |
| `tf health` | `GET /health` — версия, права, запись, занятость запуска |
| `tf status` | `GET /status` — сводка: счётчики, дела на сегодня, баланс |
| `tf characters` (`list-characters`) | `GET /characters` — по умолчанию `id` и `ник`, дальше `--detail=list\|full` или `--fields=` |
| `tf list-character-stats` | `GET /characters.stats` |
| `tf character-card Mag_1` | `GET /characters/{id}` |
| `tf character-stats Mag_1` / `tf character-stat Mag_1 hp` | `GET /characters/{id}/stats[/{stat}]` |
| `tf character-passes Mag_1` / `tf character-pass Mag_1 weapon` | `GET /characters/{id}/dungeon-passes[/{pass}]` |
| `tf parties` / `tf party-card <id>` | `GET /parties[/{id}]` |
| `tf marathons` / `tf marathon-card <id>` / `tf marathon-participants <id>` | `GET /marathons[/{id}[/participants]]` |
| `tf planner`, `tf finance`, `tf windows`, `tf audit` | одноимённые `GET` |
| `tf jobs --job-id <id>` | `GET /jobs/{jobId}` |
| `tf export --set characters --format csv` | `GET /export/{set}.{format}` |

### Изменения и окна (нужен `--yes`)

| Команда | Что делает |
| --- | --- |
| `tf set-stat Mag_1 hp 45` | поставить/прибавить/отнять стат (`--mode inc`) |
| `tf set-pass Mag_1 weapon 3` | одна проходка |
| `tf bulk-pass --ids Mag_1,Luchnik_2 --pass armor --value 2` | проходка списку (⚠ требует подтверждения) |
| `tf patch-character Mag_1 --level 120` | любые поля карточки |
| `tf create-character --nick Ник --class Маг` | новый персонаж |
| `tf rename-party <id> --name Новое` | название и цвет пати |
| `tf marathon-mark <id> --character-id … --task-id … --date …` | отметить прохождение |
| `tf marathon-adjust <id> …` | +/- к счёту ячейки марафона |
| `tf planner-add --title …`, `tf planner-entry <id> --status done` | дела |
| `tf finance-operation --kind out --amount 100` | приход/расход |
| `tf launch-character Mag_1` | открыть окно одного персонажа |
| `tf launch-party <partyId>` (`--member-ids …`) | всю пати или выборку, в сохранённом порядке; id — из `tf parties` |
| `tf launch-selection --character-ids Mag_1,Luchnik_2` | порядок задаёт вызывающий |
| `tf close-windows --pids 4321,99` | закрыть окна (⚠ подтверждение; `confirm: true` добавляет каталог) |

### Флаги полей

Флаг поля — имя поля через дефис: `--character-id`, `--member-ids`, `--wait-timeout`.
`--characterId` и `--characterid` читаются так же. Тип значения берётся из каталога:

* `number` — приводится к числу, «много» отбивается до запроса;
* `select` — только список допустимых значений (например `--stat hp|mp|…`);
* `date` — `ГГГГ-ММ-ДД`;
* `checkbox` — `--marked` / `--marked=false` / `--no-marked`;
* `list` — через запятую или пробел: `--member-ids Mag_1,Luchnik_2`.

Позиционные аргументы заполняют обязательные поля по порядку каталога, поэтому
`tf set-stat Mag_1 hp 45` и `tf set-stat --id Mag_1 --stat hp --value 45` — одно и то же.
Значения по умолчанию (например `--lang en`, `--sort id`) подставляются как на
странице. **Кого запускать, CLI не угадывает**: страница подставляет первого
персонажа из списка, `tf` вместо этого отвечает «не хватает: --character-id» — иначе
одна оплошность в скрипте открывала бы чужое окно.

## 4. Право пользователя: dry-run и `--yes`

Команды с правом `modify` и `launchClose` без `--yes` **не отправляются**: печатается
тот же запрос, что ушёл бы, и подсказка. Так агент может показать человеку, что он
собирается сделать, до того как это станет правдой.

```console
> node scripts/tf/tf.mjs launch-character Mag_1
dry-run: POST http://127.0.0.1:47831/api/v1/launch/character
   тело: {"characterId":"Mag_1"}
   → повторите с --yes, чтобы отправить
```

`--json` отдаёт то же машиночитаемо:

```json
{
  "ok": true,
  "command": "launch-character",
  "dryRun": true,
  "note": "действие меняет данные или окна — нужен --yes",
  "request": {
    "method": "POST",
    "url": "http://127.0.0.1:47831/api/v1/launch/character",
    "headers": { "Authorization": "Bearer <скрыт>" },
    "body": { "characterId": "Mag_1" }
  }
}
```

Опасные действия (`bulk-pass`, `close-windows`) дополнительно несут текст подтверждения
из каталога — в dry-run он попадает в поле `confirm`, чтобы человек увидел его до
отправки. `--yes` означает «пользователь согласен», и ответственный слой (агент,
планировщик, скрипт) должен получить это согласие, а не ставить флаг «на всякий
случай». `--dry-run` полезен и для чтения: показывает точный адрес запроса.

## 5. Вывод

* `--json` — ровно один объект в `stdout`; сообщения о прогрессе идут в `stderr`,
  поэтому `tf … --json | jq` не ломается.
* без `--json` — человекочитаемые строки: маршрут, код, короткая сводка
  (`персонажей: 12; окон: 2`) и ответ целиком.
* коды выхода: `0` — успех (и dry-run тоже: запрос не отправлен по правилам, а не из-за
  ошибки), `1` — API отказал, `2` — ошибка в командной строке (нет обязательного поля,
  неизвестный флаг, неверный адрес), `3` — сервер не отвечает.

Успешный объект:

```json
{ "ok": true, "command": "status", "method": "GET", "path": "/api/v1/status",
  "status": 200, "summary": "персонажей: 12; окон: 2; дел на сегодня: 3 из 5", "data": { } }
```

Отказ — с подсказкой, что делать (это главная ценность над `curl`: таблицу кодов из
раздела 4.17 `EXTERNAL-API.md` знать не нужно):

```json
{ "ok": false, "status": 403, "error": { "code": "forbidden_scope",
    "message": "Право «запуск и закрытие окон» выключено" },
  "hint": "право выключено: включите нужное в «Настройки → 🔌 Внешний API» — «изменение» или «запуск и закрытие окон»." }
```

## 6. Долгие запуски: 202, jobId и `--wait`

Запуск окон занимает десятки секунд, поэтому API отвечает `202 { jobId }` сразу, а ход
работы виден в `GET /jobs/{jobId}`. `tf` либо показывает, как спросить (поле `next`),
либо опрашивает сам:

```console
> node scripts/tf/tf.mjs launch-party p-osnova --yes --wait
… running · Запуск окон 1/3
… done · Готово 3/3
POST /api/v1/launch/party → 202 · задание: job_8f2c1a
задание job_8f2c1a: done · запущено 2, пропущено 1, ошибок 0
```

`--wait-timeout <мс>` меняет ожидание (по умолчанию 600000). В `--json` итог лежит в
поле `job`, а при `status: "failed"` добавляется `warning` — код выхода при этом `0`:
сервер ответил честно, задача задачи не выполнила.

Строки `result.items[]` с `status: "skipped"` — нормальный итог, а не ошибка. Причины:

| `error` | Что значит | Что делать |
| --- | --- | --- |
| `no_gc` | к персонажу не прикреплён лаунчер игры | «Инструменты → Окна игры → 🎮 GameCenter и персонажи» |
| `no_saved_login` | вход не запомнен | там же — «🔑 Запомнить вход» |
| `already_running` | окно уже открыто | ничего; `tf windows --json` покажет PID |

Ещё два частых случая: `429 launch_busy` — уже идёт другое внешнее задание (одиночное
по дизайну: два конкурентных запуска спорят за очередь окон), `409 launch_not_ready` —
запускать некого. Архивные персонажи не запускаются: их нет в `GET /characters`.

## 7. Рецепты

```powershell
# кто жив, какие права, свободен ли запуск
node scripts/tf/tf.mjs health --json

# сегодня осталось 2 дела — отметить одно выполненным
node scripts/tf/tf.mjs planner --json
node scripts/tf/tf.mjs planner-entry <id> --status done --yes

# выгрузка персонажей в CSV
node scripts/tf/tf.mjs export --set characters --format csv --out characters.csv

# id пати берём из списка (название — только для человека)
node scripts/tf/tf.mjs parties --json
node scripts/tf/tf.mjs launch-party p-farm --yes --wait

# закрыть только окна этой пати: PID берём из списка окон
node scripts/tf/tf.mjs windows --json
node scripts/tf/tf.mjs close-windows --pids 4321 --yes

# что API вообще разрешал минуту назад (для разбора «кто это изменил»)
node scripts/tf/tf.mjs audit --json
```

## 8. Границы

* `tf` видит только то, что видит внешний API, и только с включёнными пользователем
  правами: `read` по умолчанию, `modify` и `launchClose` — по галочке в настройках.
  Скрипт не может ни расширить себе права, ни обойти подтверждение.
* Доступ к локальному порту — это доступ от имени пользователя. CLI не хранит секреты,
  не пишет состояние (`state.json`) и не показывает токен.
* Сайта игры CLI не касается: правила «что можно делать на сайте» (без автономного
  нажатия кнопок, без промокодов и передачи предметов) описаны в
  [COMPLIANCE.md](COMPLIANCE.md), и `tf` их не расширяет — у него просто нет таких
  команд.
* Марафонские награды, статы и финансы — учётные записи пользователя: массовые
  изменения (`bulk-pass`) возможны только осознанно, поэтому они под `--yes` и с
  подтверждением.

## 9. Проверки

```console
npm test -- tests/agentCli.test.js          # паритет каталога и команд, dry-run, вывод
node scripts/tf/tf.mjs --help > tests/fixtures/tf-help.txt   # обновить снимок справки
npm run docs:api-examples:check             # документ примеров не разошёлся с каталогом
```

`tests/agentCli.test.js` покрывает: 1:1 каталога и команд, 1:1 документированных
маршрутов и команд, разбор примеров из `tf describe`, dry-run по умолчанию, совпадение
тела запроса с формой страницы, запрет `--token` и отсутствие токена в выводе,
подсказки по `403`/`429`/`404`, ожидание задания, коды выхода.
