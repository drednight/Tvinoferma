## Часть 1. Что сделано

### 1.1. Починена тема: она была разорвана надвое

Главная причина, по которой интерфейс выглядел несобранным, была технической. В CSS использовались переменные
`--text-primary`, `--text-secondary`, `--text-muted`, `--panel-3`, которых **не существовало** в `variables.css`.
CSS подставлял запасные значения из другой палитры (Catppuccin: `#c0caf5`, `#a9b1d6`), поэтому текст в карточках
и настройках жил в одной теме, а фон — в другой.

Сделано:

* единый слой токенов в [variables.css](../css/core/variables.css) — фон, поверхности, границы, текст, акценты, радиусы, тени, отступы;
* старые имена оставлены как **алиасы** (`--panel` → `--surface-1`, `--text-primary` → `--text`), поэтому существующий CSS и разметка продолжают работать;
* добавлены синонимы, которых не хватало: `--gap*`, `--radius-*`, `--shadow-1/2/3`, `--speed`, `--ease`, `--focus-ring`.

### 1.2. Каркас окна

| Было | Стало |
| --- | --- |
| Четыре отдельные «пилюли»-вкладки | Один сегментированный переключатель с иконками и счётчиками записей |
| KPI-карточки с цветными полосами через инлайн-стили | Полоса показателей `.stat-strip` с токенами состояния (`is-ok`, `is-bad`, `is-gold`, `is-violet`, `is-plain`) |
| Фильтры и действия в одном ряду без группировки | Панель фильтров отдельной карточкой; действия — справа в заголовке раздела |
| Заголовки разделов уровня `h2` без пояснений | Единый блок `.section-head`: название, пояснение, действия |
| Контент растягивался на всю ширину | Ограничение `--content-max`, окно не «разъезжается» на широком мониторе |

### 1.3. Карточка персонажа

Инлайн-стили убраны в CSS — тема снова управляет карточкой. Разметка стала семантичной
(`.char-avatar`, `.char-ident`, `.char-nick`, `.card-stats`, `.card-contacts`, `.card-passes`), а состояние
задаётся одной переменной `--state-c`, которую присылает модель авторизации (`getAuthView`). Раньше цвет
вставлялся прямо в `style` из JS, и поменять оформление статуса можно было только правкой двух модулей.

Дополнительно в `getAuthView` добавлено поле `cls` (`is-on`, `is-off`, `is-busy`): статус передаётся классом,
а не только цветом — это и чище, и доступнее (цвет перестал быть единственным носителем смысла).

### 1.4. Мелкие функции, добавленные по ходу

* **Счётчики разделов в навигации** ([navBadges.js](../js/core/navBadges.js)) — «Персонажи 6», «Пати 3», «Марафоны 1». Обновляются после сохранения и при переключении вкладки; пустой раздел счётчик не показывает, чтобы не кричать нулём. Крупные числа сокращаются: `15400` → «15 тыс.».
* **Кнопка «Сбросить» в фильтрах** — появляется, только когда включён хотя бы один из пяти фильтров, и очищает все сразу. Раньше при пяти фильтрах сброс был ручной работой.
* **Оформлены полосы прокрутки** (Issue #71) — заодно с общей темой.
* **Единый видимый фокус** (`:focus-visible`) для клавиатуры во всём приложении.
* **`aria-expanded`** у меню скриптов и круглой кнопки, доступные имена кнопок.
* **Пустой результат фильтра** подсказывает, что делать: «Измените условия или нажмите «Сбросить»».
* **Уважение к `prefers-reduced-motion`** — анимации отключаются системной настройкой.

### 1.5. Инструмент проверки внешнего вида

Добавлен [scripts/ui-shots.mjs](../scripts/ui-shots.mjs) и команда `npm run shots`. Стенд поднимает Vite,
открывает приложение в headless Edge, кладёт демонстрационные данные (`tests/fixtures/ui-demo-state.json`),
фотографирует все разделы и **машинно проверяет вёрстку**: переполнение окна, наложения в карточках, текст
мельче 11px, кнопки без доступного имени, обрезанный текст, ошибки страницы.

Результат на демонстрационных данных:

```
обрезанный текст: 0
содержимое: персонажи 6, пати 4, марафона 2, панелей настроек 13, счётчики 6/3/1
```

Проверено в окнах 1440×960 и 900×800 — обе ширины чистые. Данные в фикстуре вымышленные; тест
`tests/fixturesPrivacy.test.js` следит, чтобы в ней не появилось настоящих адресов.

## Часть 2. Функции, добавленные после редизайна

### 2.1. Разбор скриншота с характеристиками персонажа

**Вопрос был: можно ли вставить скриншот окна со статами, чтобы данные подтянулись в форму.** Да, реализовано.

Как пользоваться: карточка персонажа → «Править» → блок «Основные характеристики» → **«📷 Заполнить со скриншота»**.
Скриншот можно выбрать файлом, перетащить в окно или просто вставить из буфера (`Ctrl+V` — самый быстрый путь после Print Screen).
Распознанные характеристики показываются списком: каждую можно снять галочкой или поправить число, затем «Перенести в форму».

Технически: разбор идёт **встроенным в Windows распознавателем текста** (`Windows.Media.Ocr`) — русский язык,
ничего доустанавливать не нужно, картинка никуда не отправляется. Код: `src-tauri/src/stats_ocr.rs` (распознавание)
и `js/modules/characters/statsOcr.js` (сопоставление).

Две вещи, которые выяснились на реальном снимке и определили устройство разбора:

1. **Порядок строк не совпадает с порядком на экране.** Распознаватель отдаёт сначала все подписи, потом все значения.
   Поэтому подпись и значение связываются по координатам: значение ищется в той же строке и правее подписи.
2. **Числа распознаются не идеально:** «3 680» превращается в «з 680», «12%» — в «1296».
   Поэтому результат никогда не применяется молча — он показывается на подтверждение, и все числа можно поправить руками.

Надёжность проверена 22 тестами на реальных искажениях (`tests/statsOcr.test.js`), включая перепутанный порядок строк
и значение из соседней колонки, которое не должно подставляться.

### 2.2. Выбор окон игры для закрытия

Было: «Закрыть все окна игры» — только всё разом. Стало: окно со списком запущенных клиентов
(вкладка «Пати» → **«🎮 Окна игры…»**, там же в «Настройках → Запуск игры»).

В списке: ник и класс, PID, время работы, галочки. Внизу — «Закрыть выбранные», «🛡 Закрыть пати…» и «Закрыть все».
Окна, запущенные не из Твинофермы, показываются как «PID 1234» — их ник и класс неизвестны, потому что Твиноферма
подписывает только те окна, которые запустила сама.

Ник и класс берутся из заголовка окна («Ник — Класс»), который ставит запуск игры. Клиенты, запущенные от
администратора, помечаются, а если обычное закрытие не сработало — предлагается закрыть с правами администратора.

### 2.3. Порядок персонажей внутри пати

На вкладке «Пати» у каждого участника появилась ручка перетаскивания и номер места. Порядок задаёт очередь
запуска игры и **сохраняется между перезапусками** (`char.partyOrder` — номер у персонажа для каждой пати,
поэтому один и тот же персонаж может стоять по-разному в основной пати и в марафонной).

### 2.4. Проверка значков и названий окон после запуска

Игра при загрузке может переписать заголовок окна, а окно появляется не сразу. Поэтому после запуска пати
Твиноферма проверяет, что все окна получили название и значок, и **повторяет попытку** для тех, где не вышло
(`launcher_decorate_clients`). В журнале задачи появляется строка, только если что-то не применилось.

В «Настройки → Запуск игры» добавлен отдельный переключатель **«Ставить значок класса на окно игры»**:
если выключить, окно всё равно получит название «Ник — Класс», но значок останется игровым.

### 2.5. «Вернуть к заводским настройкам»

«Настройки → Опасные действия» → вложенный блок «Показать самое опасное». Удаляется всё: персонажи, пати,
марафоны, настройки, журналы, история монет, резервные копии, сессии (банк кук), профили браузера персонажей
и записи в хранилище учётных данных ОС. Приложение возвращается к состоянию сразу после установки.

Действие **необратимо** (копии тоже удаляются), поэтому окно подтверждения честно перечисляет, что пропадёт,
и напоминает про экспорт. Перед удалением интерфейс собирает ключи хранилища ОС из данных — после удаления
`state.json` узнать имена записей уже нельзя, это единственный момент, когда их можно перечислить.

### 2.6. GameCenter и персонажи: фильтр по пати

В окне «⚙ GameCenter и персонажи» появилась панель фильтров: поиск по нику или классу, **выбор пати**
(включая «Без пати») и галочка «Только без GameCenter». У каждого персонажа сразу видны его пати (основная
помечена цветом) и число прикреплённых GameCenter. Счётчик справа показывает, сколько персонажей скрыто фильтром.

### 2.7. Командная палитра (Ctrl+K, Issue #40)

`Ctrl+K` открывает строку поиска по всему приложению. Набрали часть ника — видите команды: «открыть профиль»,
«проверить вход», «запустить игру», «обновить баланс». Работает и мышью, и клавиатурой (`↑` `↓`, `Enter`, `Esc`).

Что ищется: разделы, 14 общих действий (новый персонаж, промокод, окна игры, экспорт, бэкап…),
каждый персонаж и его команды, пати (запуск и закрытие окон пати), марафоны и папки.
Поиск понимает класс персонажа, теги и синонимы: «логин» находит «Проверить авторизацию», «монеты» — «Обновить балансы».

Смысл: горячие клавиши требуют запоминать сочетания, а палитра — нет. Для фермы на 50+ аккаунтов это самый
большой выигрыш по времени на действие: вместо поиска карточки в списке достаточно набрать часть ника.

Данные команд — `js/core/commandPaletteData.js` (поиск покрыт 18 тестами), показ — `js/core/commandPalette.js`
(16 тестов), действия — `js/core/commandRunner.js`.

### 2.8. Мелочи ежедневной работы (Issue #45)

* **Подсказка первых шагов** на пустых данных: три шага с кнопками («Добавьте персонажа → Соберите пати → Войдите на сайт игры»). Раньше пустой список ничего не объяснял. Как только появляется первый персонаж, подсказка исчезает и опытным пользователям не мешает.
* **Справка «Как войти на сайт»** открывается третьим шагом и объясняет, что приложение ничего не нажимает за пользователя.
* **Что нового в окне обновления** — уже работало; окно показывает список изменений из GitHub Releases.

### 2.9. Никаких системных окон подтверждения

`confirmDialog` (обёртка над `window.confirm`) удалён: все подтверждения идут через `confirmModal` в стиле
приложения. Системные окна выглядели чужеродно, не подчинялись теме и не могли показать опасность действия.

Заменено в 11 местах: удаление персонажа и группы, массовое удаление, очистка журналов, восстановление и
удаление резервных копий, завершение и удаление марафона, промокоды, передача предметов.
У каждого окна теперь есть понятный заголовок, текст с последствиями и опасная кнопка там, где действие
необратимо. Тест `tests/dialogs.test.js` (110 проверок) следит, чтобы `window.confirm` и `window.alert`
не вернулись в код.

### 2.10. Исправлено по замечаниям

* **Перетаскивание внутри пати** — персонаж встаёт **на место** того, на кого навели, а цель сдвигается вниз. Раньше вставка шла под ним. Сторона вставки зависит от половины строки: верхняя — перед ней, нижняя — после, поэтому перетаскивание на соседнюю строку меняет местами, а не бросает в конец. Место вставки показывается линией.
* **Кнопка «Заполнить со скриншота» не работала** — обработчик вешался до того, как форма появлялась в DOM. Теперь привязка идёт после создания разметки, поведение закрыто тестами.
* **Характеристики — одним сворачиваемым блоком**: «Основные характеристики», «Бой и Защита», «Показатели боя», «PvE и Пробивание» внутри одного `details` вместо четырёх отдельных панелей. Раскрыт по умолчанию.
* **«Запуск игры» в профиле свёрнут по умолчанию** — это редкая настройка, а запуск идёт кнопкой «Играть».
* **Кнопка закрытия окон переехала в карточки пати** (рядом с «Запустить»): закрыть окна нужно именно после запуска пати, а не с уровня всего раздела. У пустой пати кнопки нет — закрывать нечего. Общий список окон со всеми вариантами по-прежнему доступен в «Настройках → Запуск игры».

### 2.12. Дашборд «Сегодня» (Issue #39)

Раздел «Персонажи» теперь открывается экраном «Сегодня» — три блока над списком карточек
(список остаётся ниже, потому что работать с карточками по-прежнему нужно).

* **Требуют внимания** — истёкшие сессии, персонажи, отстающие в марафонах, и давно не проверенный баланс.
  У каждой строки кнопка действия: «Проверить вход», «Обновить баланс», «Открыть». Порядок — от срочного:
  сначала вход (без него не работает ничего), затем марафоны с дедлайном, затем баланс.
* **Сегодня в марафонах** — идущие марафоны: сколько заданий, сколько участников, сколько всё выполнили,
  сколько отстают и сколько осталось дней.
* **Запасы** — сумма монет, проходки в данжи по видам, число персонажей и авторизованных, ближайшие даты
  окончания событий, пати с онлайном.

Экран сворачивается, состояние сохраняется в настройках. На пустых данных его нет — там своя подсказка
первых шагов. Логика отбора: `js/modules/dashboard/today.js` (24 теста), показ — `todayView.js` (16 тестов).

### 2.13. Исправлено: названия и значки окон не применялись

Нашлись две настоящие причины, обе в `launcher.rs`:

1. **Окно пропускалось, пока у него не появится заголовок.** Условие `is_client_window` требовало непустой
   заголовок — но окно клиента становится видимым раньше, чем игра его заполнит. В этот момент окно
   исключалось из обработки, и подпись не ставилась вовсе. Теперь заголовок не требуется: пустой заголовок —
   как раз то, что нужно заполнить.
2. **Значок ставился один раз за запуск.** Список `with_icons` не давал поставить значок повторно, но игра
   перезаписывает вид окна при загрузке и входе в мир — значок пропадал. Теперь наличие значка проверяется
   по факту (`WM_GETICON`), и если игра его сбросила — он ставится заново.

Обе причины закрыты тестами, которые фиксируют именно исправленное поведение.

### 2.14. Ручная смена названия и значка окна

В списке запущенных окон у каждого окна появилась кнопка **«✏️ Вид…»**: можно задать своё название
(по умолчанию подставлено «Ник — Класс») и выбрать класс для значка, либо вернуть значок файла игры.
Это нужно, когда автоматическая подпись не сработала (игра от администратора, окно открылось позже)
или когда ник в игре отличается от ника в Твиноферме.

Работает и для окон, запущенных не из Твинофермы (они показаны как «PID 1234») — название задаётся вручную.

### 2.15. Улучшен разбор скриншота

Замеры на изображении с мелким шрифтом (как в игре) показали, что дело было не в предобработке:

| Приём | Верных значений |
| --- | --- |
| Исходный размер окна | 1 из 13 |
| + оттенки серого, инверсия, бинаризация, контраст | 1 из 13 (не помогает) |
| **Увеличение ×3** | **12–13 из 13** |
| Увеличение ×4…×8 | 12–13 из 13 (качество то же, время ×5) |

Поэтому изображение теперь увеличивается в 3 раза перед распознаванием (≈160 мс). Дальше исправляются
устойчивые ошибки самого распознавателя: «з 680» → «3 680», «120/0» → «12%», «1О5» → «105». Подписи
с опечатками («Фвическая атака» вместо «Физическая атака») распознаются сравнением по «скелету» слова,
а строки вида «Здоровье 42 350», где подпись и значение слиты, разбираются отдельно.

Проверено на реальном изображении через собранный код: подписи 13/13, значения 13/13.

### 2.16. Убрано

Кнопка «🔍 Проверить окна игры» из «Настройки → Запуск игры» (диагностика подписи окон осталась в коде
и используется автоматической перепроверкой после запуска).

### 3.1. ~~Дашборд «Сегодня» вместо стартового экрана со списком (Issue #39)~~ — сделано

**Реализовано, см. 2.12.** Раздел «Персонажи» открывается экраном «Сегодня» с тремя блоками:

### 3.2. Командная палитра `Ctrl+K` (Issue #40)

Горячие клавиши в приложении есть (`Ctrl+1…4`, `Ctrl+F`), но пользователь должен их помнить. Палитра
переворачивает это: `Ctrl+K` → «аура» → «Ауразак: открыть профиль», «Ауразак: проверить вход», «Ауразак: запустить».
Один и тот же список команд обслуживает и мышь, и клавиатуру, а меню «⚡ Скрипты» и меню карточки становятся
его укороченной версией. Для фермы на 50+ аккаунтов это самый крупный выигрыш по времени на действие.

### 3.3. Марафоны: матрица как основной экран (Issue #19)

Матрица «персонаж × задание» — самая сильная часть приложения, но она спрятана за карточкой марафона. Стоит
сделать её основным видом раздела с честной виртуализацией (Issue #43): сейчас на 20 персонажей и 10 заданий
это 200 ячеек со скруглениями и тенями, и на 100 персонажей страница станет тяжёлой. Плюс:

* **Циклический календарь** (Issue #30) — сегодня/завтра/через день, с подписью «данж: Оружие».
* **Закрепление задания** — колонку можно закрепить слева, как имя персонажа уже закреплено.
* **Фильтр «показывать только отстающих»** — на большом марафоне это главный режим работы.

### 3.4. Промокоды и передача предметов как очередь, а не диалог (Issues #25, #26, #29)

Обе операции массовые, и обе сейчас запускаются модальным окном. Предлагаю превратить их в **очередь задач**,
которая уже есть в доке (`taskLog.js`):

* промокод вводится один раз и ставится в очередь на выбранных персонажей;
* видно, кто активировал, кто уже активировал ранее, у кого ошибка;
* очередь можно приостановить и продолжить — сейчас при закрытии окна прогресс теряется;
* «пресеты скриптов» (Issue #29) — сохранённый набор персонажей и действия для повторного запуска.

### 3.5. Банк и ROI фермы (Issues #56–#58)

У приложения уже есть история монет по каждому персонажу, но нет ответа на вопрос «ферма окупается?».
Предлагаю начать с малого: журнал доходов и расходов с категориями (марафон, промокод, передача, вручную)
и график накопления за период. Это закрывает сразу три пункта роадмапа и опирается на существующую
`coinHistory`.

### 3.6. Представления и массовые действия

* **Сохранённые представления** (Issue #24): «Все, кто не заходил неделю», «Основная пати без баланса» — набор фильтров, сохранённый под именем и доступный одной кнопкой.
* **Меню массовых действий сейчас — строка из 10 кнопок.** При сужении окна она переносится и становится трудночитаемой. Предлагаю сгруппировать: «Проверить (вход, баланс, марафоны)», «Данные (промокод, передача)», «Изменить (теги, пати)», «Удалить».

### 3.7. Данжи, руны, арена, облако (Issues #30–#38, #59–#62)

Модули-заготовки (`js/modules/dungeons`, `runes`, `arena`, `bank`, `cloud`) уже существуют, но не подключены.
Предлагаю подключать их **по одному и сразу с экраном**, а не всем набором:

* **Данжи** — ближе всего к текущим данным: проходки уже хранятся, нужен циклический календарь и таблица допусков.
* **Руны** — карточки шаблонов с копированием кода; самостоятельный раздел, не пересекается с остальным.
* **Облако** — вынести в «Настройки → Перенос данных» третьей кнопкой, рядом с JSON, а не отдельной вкладкой.

### 3.8. Мелочи, которые заметны при ежедневной работе

### Проверка на демонстрационных данных (воспроизводимо)

```powershell
npm run shots                          # снимки в docs/screenshots/
node scripts/ui-shots.mjs --out docs/screenshots/after --width 900 --height 800
```

Стенд печатает отчёт аудита вёрстки и сохраняет PNG по разделам. Скриншоты «до» сняты тем же стендом
до изменений, поэтому их можно сравнить попиксельно (Windows PowerShell, модуль `System.Drawing` уже есть):

```powershell
Add-Type -AssemblyName System.Drawing
function Compare-Shot($a, $b) {
  $ia = [System.Drawing.Image]::FromFile($a); $ib = [System.Drawing.Image]::FromFile($b)
  $ba = New-Object System.Drawing.Bitmap $ia; $bb = New-Object System.Drawing.Bitmap $ib
  $w = [Math]::Min($ba.Width, $bb.Width); $h = [Math]::Min($ba.Height, $bb.Height)
  $diff = 0
  for ($y = 0; $y -lt $h; $y += 4) { for ($x = 0; $x -lt $w; $x += 4) {
    $pa = $ba.GetPixel($x, $y); $pb = $bb.GetPixel($x, $y)
    if ([Math]::Abs($pa.R-$pb.R) + [Math]::Abs($pa.G-$pb.G) + [Math]::Abs($pa.B-$pb.B) -gt 30) { $diff++ }
  } }
  $sampled = [Math]::Ceiling($w/4) * [Math]::Ceiling($h/4)
  $ia.Dispose(); $ib.Dispose(); $ba.Dispose(); $bb.Dispose()
  "{0}: изменилось {1}%" -f (Split-Path $a -Leaf), [Math]::Round(100 * $diff / $sampled, 1)
}
foreach ($f in 'characters','parties','marathons','settings','character-profile') {
  Compare-Shot "docs\screenshots\before\$f.png" "docs\screenshots\after\$f.png"
}
```

На момент сдачи сравнение даёт: персонажи 36,1 %, профиль 16,9 %, настройки 13,3 %, пати 9,8 %, марафоны 5,4 %.

### Как откатить

Все изменения лежат в рабочем каталоге, отдельного коммита или ветки нет. Поэтому откат — обычный `git`:

```powershell
# 1. Посмотреть, что изменено
git status --short
git diff --stat

# 2. Откатить всё оформление и разметку к состоянию репозитория
git checkout -- index.html css js package.json README.md CONTRIBUTING.md
git checkout -- src-tauri/Cargo.toml src-tauri/Cargo.lock src-tauri/src

# 3. Удалить новые файлы, которых не было в репозитории
Remove-Item js/core/navBadges.js, js/core/commandPalette.js, js/core/commandPaletteData.js, js/core/commandRunner.js
Remove-Item js/modules/characters/statsOcr.js, js/modules/characters/statsImport.js, js/modules/characters/onboarding.js
Remove-Item js/modules/launcher/windowList.js, js/modules/launcher/windowPicker.js
Remove-Item js/settings/factoryReset.js
Remove-Item scripts/ui-shots.mjs, tests/fixtures/ui-demo-state.json
Remove-Item css/modules/windowPicker.css, css/modules/statsImport.css, css/modules/onboarding.css
Remove-Item css/core/commandPalette.css
Remove-Item src-tauri/src/stats_ocr.rs, src-tauri/src/commands/factory_reset.rs
Remove-Item docs/UI-REDESIGN.md
Remove-Item -Recurse -Force docs/screenshots

# 4. Проверить, что вернулось исходное состояние
npm run check
```

Чтобы **оставить оформление, но убрать только счётчики** (если не понравились именно они):

```powershell
git checkout -- js/main.js
Remove-Item js/core/navBadges.js
git checkout -- index.html
```

Чтобы убрать **только командную палитру**:

```powershell
Remove-Item js/core/commandPalette.js, js/core/commandPaletteData.js, js/core/commandRunner.js
Remove-Item css/core/commandPalette.css
# из index.html убрать строку подключения commandPalette.css,
# из js/desktop/desktop.js — обработку Ctrl+K и строку из HOTKEYS
```

Откат одной части оформления возможен и точечно: например, вернуть только карточки персонажа —
`git checkout -- css/modules/characters.css js/modules/characters/list.js js/modules/sync/authStatus.js`.

Отдельно стоит знать: **тема не влияет на данные**. `state.json`, пароли в хранилище ОС, сессии браузера
и история монет этой работой не затронуты — менялись только стили, разметка и два модуля интерфейса.
Поэтому откат оформления не может привести к потере данных.
