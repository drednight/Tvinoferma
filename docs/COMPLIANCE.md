# Правила сайта и границы приложения

Здесь записано, что приложение делает на pwonline.ru, а чего не делает. Цель — не подвести аккаунты
пользователей под блокировку и не превратить приложение в инструмент, который сайт запрещает.

> ⚠️ **Статус документа: черновик.** Официальные правила сайта и пользовательское соглашение
> автором документа **не проверялись**. Перед тем как расширять автоматизацию (Issues #25, #26),
> прочитайте актуальные правила pwonline.ru и при сомнениях спросите у администрации.
> Результат запишите сюда (дата, кто ответил, что именно разрешено).

## Принципы (решение 1 из ROADMAP)

1. **Фоновые скрипты только читают.** Скрипты в `src-tauri/src/scripts/` читают DOM страницы
   (баланс, прогресс марафонов, статус входа) и ничего не нажимают, не вводят и не отправляют.
   Сейчас в них нет `click()`, отправки форм и запросов `POST`.
2. **Действие на сайте — только по явной кнопке пользователя.** Всё, что меняет состояние на сайте
   (промокоды, перевод предметов — Issues #25, #26), запускается кнопкой, для каждого персонажа
   показывает, что будет сделано, и позволяет отменить.
3. **Никаких расписаний для действий.** Автоматически (по таймеру) допускается только чтение.
4. **Щадящая нагрузка.** Общая очередь (`js/modules/sync/queue.js`) ограничивает число одновременных
   окон, добавляет паузы между задачами и растущую паузу при повторах. Пул (`pool.rs`) — не больше 4 окон.
5. **«Проверка безопасности» не обходится.** Когда сайт показывает проверку, приложение ждёт и
   повторяет чтение; решать проверку за пользователя оно не должно. Для сценария «пользователь
   пройдёт проверку вручную» есть Issue #15.
6. **Никакого взаимодействия с игровым сервером.** Приложение работает только со страницами сайта.

## Что уходит в сеть

| Куда | Что |
| --- | --- |
| `pwonline.ru` | Страницы, которые открыты в окнах приложения: вход, баланс, марафоны, новости. Запросы идут от окна WebView с куками персонажа, как у обычного браузера |
| `github.com/drednight/Tvinoferma` | Файл `latest.json` и установщик при проверке обновлений |

Телеметрии и аналитики нет. Пароли и куки наружу не отправляются: пароли в хранилище ОС,
куки-банк зашифрован и лежит локально (`cookie_bank.rs`).

При ручном входе через VK / Mail.ru пользователь работает со страницами этих сервисов в видимом окне
сам. Куки этих доменов в куки-банк не сохраняются.

## Чек-лист перед добавлением новой возможности

- [ ] Скрипт только читает? Если нет — это действие, нужна кнопка и подтверждение (принцип 2).
- [ ] Не запускается по расписанию (принцип 3), если меняет данные на сайте.
- [ ] Идёт через общую очередь, а не напрямую.
- [ ] Правила сайта по этому сценарию прочитаны, вывод записан выше.
- [ ] В фикстурах и логах нет паролей, куков и личных данных.
