# Правила сайта и границы приложения

Здесь записано, что приложение делает на pwonline.ru, а чего не делает. Цель — не подвести аккаунты
пользователей под блокировку и не превратить приложение в инструмент, который сайт запрещает.

> ⚠️ **Статус документа: черновик.** Официальные правила сайта и пользовательское соглашение
> автором документа **не проверялись**. Перед тем как расширять автоматизацию (Issues #25, #26),
> прочитайте актуальные правила pwonline.ru и при сомнениях спросите у администрации.
> Результат запишите сюда (дата, кто ответил, что именно разрешено).

## Принципы (решение 1 из ROADMAP)

1. **Фоновые скрипты только читают.** Скрипты в `src-tauri/src/scripts/` читают DOM страницы
   (баланс, прогресс марафонов, статус входа) и ничего не нажимают, не вводят и не отправляют.
   Сейчас в них нет `click()`, отправки форм и запросов `POST`.
   Исключения — «скрипты действия»: `promo.js` (Issue #25), `transfer.js` (Issue #26, режимы `fill`/`click`), `shop.js` (подарки)
   и панель `collection.js` (Issue #72, видимое окно),
   см. разделы «Промокоды» и «Передача предметов» ниже. Режим `scan` у `transfer.js` только читает.
2. **Действие на сайте — только по явной кнопке пользователя.** Всё, что меняет состояние на сайте
   (промокоды, перевод предметов — Issues #25, #26), запускается кнопкой, для каждого персонажа
   показывает, что будет сделано, и позволяет отменить.
3. **Никаких расписаний для действий.** Автоматически (по таймеру) допускается только чтение.
4. **Щадящая нагрузка.** Общая очередь (`js/modules/sync/queue.js`) ограничивает число одновременных
   окон, добавляет паузы между задачами и растущую паузу при повторах. Пул (`pool.rs`) — не больше 4 окон.
5. **«Проверка безопасности» не обходится.** Когда сайт показывает проверку, приложение ждёт и
   повторяет чтение; решать проверку за пользователя оно не должно. Для сценария «пользователь
   пройдёт проверку вручную» есть Issue #15.
6. **Никакого взаимодействия с игровым сервером.** Приложение работает только со страницами сайта.

## Промокоды (Issue #25): скрипт действия

Правила сайта для автоматической активации **не проверены** (см. «Что нужно уточнить»), поэтому действует
осторожная схема:

- запуск только кнопкой «🎁 Активировать промокод»; перед стартом — предпросмотр (коды, число персонажей,
  сколько вводов будет выполнено и сколько пропущено);
- «👁 Пробный запуск»: открывает те же страницы `/pin/<код>` и ищет кнопку «Активировать», но не нажимает её (`dryRun`); ничего не вводится, журнал не меняется;
- никаких расписаний и автозапусков; есть кнопка «Стоп» (новые вводы не начинаются, введённое сохраняется);
- нагрузка как у проверки входа: число одновременных окон и повторов берётся из «Настройки → Скрипты»
  (пул окон — не больше 4); окна стартуют с разбросом, между кодами одного персонажа пауза 1–2 с;
- каждый код — отдельная страница `/pin/<код>`: адрес сам подставляет код в поле, приложение код **не вводит**;
  если код в поле не появился, кнопка не нажимается;
- скрипт нажимает ровно одну кнопку «Активировать» в форме ввода (и только если она одна); «Проверку
  безопасности» не решает — персонаж помечается, остальные его коды не вводятся;
- повторы только пока кнопка не нажата (таймаут, проверка безопасности); после нажатия повтора нет, результат
  «не распознан» требует ручной проверки;
- коды, которые у персонажа уже введены (последние 10 уникальных), пропускаются без обращения к сайту;
- если сайт 3 раза подряд отклонил код и ни разу не принял, он перестаёт вводиться остальным;
- промокод не секретный, поэтому хранится целиком; хранение только локальное: журнал (последние 50 кодов:
  дата первого ввода, награда, кому введён и кому нет и почему) и архив (код, дата, награда) для разработчика.
  Недействительные и просроченные коды не сохраняются.

## Передача предметов (Issue #26): второй скрипт действия

На pwonline.ru предметы передаются **с аккаунта сайта в игру** (страница «Передача предметов»,
`/promo_items.php`). Это не обмен между игроками: получатель — свой персонаж на выбранном сервере. Правила сайта
для автоматической передачи **не проверены** (см. «Что нужно уточнить»), поэтому действует та же осторожная схема:

- запуск только кнопкой «📦 Передать» в диалоге «Передача предметов в игру»; перед стартом — сводка (браузер →
  сервер → получатель, что ждёт передачи), обязательный выбор сервера и галочка «передача необратима»;
- «🔄 Обновить сервера» и «🔄 Обновить информацию по всем персонажам» (все браузеры приложения, без галочек) только читают страницы: `/promo_items.php` (серверы с номерами, персонажи, что ждёт передачи) и `/server_status.php` (названия всех серверов; страница открыта всем, ничего не нажимается); «👁 Пробный запуск» заполняет форму, но «Передать»
  не нажимает; есть «⏹ Стоп» (новые передачи не начинаются, нажатые завершаются и попадают в журнал);
- никаких расписаний и автозапусков передачи. Единственное, что приложение читает само, — публичная страница «Статус серверов» (`/server_status.php`, доступна без входа): при запуске, до проверки входа персонажей, и раз в N минут (по умолчанию 10, «Настройки → Свежесть данных → Статус серверов», 0 — только при запуске). Читает служебное окно без аккаунтов и кук персонажей, ничего не нажимает; результат — плашка в шапке. Журнал и уведомления по этому чтению не ведутся;
- нагрузка и повторы — из «Настройки → Скрипты» (окон не больше 4);
- отмечаются все предметы, которые сайт показывает с флажком (решение владельца: ограничение «6 за раз» на странице
  выполняется только в браузерном JS, и приложение его не применяет; если сайт отклонит такую передачу, результат
  будет виден в «Истории передачи» и в итоговой таблице); **сундуки не открываются**;
- сервер и получателя выбирает пользователь; без выбора передача пропускается, единственный персонаж
  на сервере подставляется сам; список серверов берётся со страницы, id серверов в коде не зашиты;
- если сайт отвечает страницей «Предупреждение… данные предметы можно перевести только на сервер «X»», приложение только читает её текст, затем открывает «История передачи» (чтение) и сверяет предметы; ничего повторно не нажимается. Запомненное ограничение «акция → сервер» хранится локально (`tf_transfer_limits_v1`, 60 дней) и лишь убирает галочки у таких предметов на других серверах;
- «Обойти ограничения приложения» лишь отключает собственный пропуск акций (`tf_transfer_limits_v1`); приложение не обходит защиту сайта: заблокированные строки без галочки не трогаются, отказ сайта (предупреждение, «после 20:00…») читается и показывается как есть. Кнопка «Забыть запомненные ограничения» стирает это локальное хранилище;
- В ВИДИМОМ окне персонажа (его открывает пользователь) на странице `/promo_items.php` скрипт `promo_items_unlimited.js` не пропускает события click/change галочек к обработчикам сайта, поэтому клиентский лимит «не более 6 предметов» не срабатывает (решение владельца, как и в автоматической передаче). Рядом рисуется панель «Типы предметов» (отметка галочек по типу или по акции, только на стороне страницы). Ничего не отправляется и не нажимается: «Передать» нажимает пользователь; ограничения сервера не обходятся. Выключается в «Настройки → Окно браузера персонажа»;
- «Передать» нажимается один раз: повторы — только пока кнопка не нажата; после нажатия результат проверяется
  по «Истории передачи» сайта, неоднозначный ответ помечается «не распознано» и **не повторяется**;
- один аккаунт сайта, открытый в нескольких браузерах, передаётся один раз;
- перед первой реальной передачей за сессию создаётся резервная копия (`createBackup('transfer')`);
- хранение только локальное: списки серверов и персонажей (`tf_transfer_roster_v1`), сервер и получатель каждого браузера
  (`tf_transfer_prefs_v1`) и журнал последних 300 передач (`tf_transfer_log_v1`, «Настройки → Журналы», вид «Передачи»; список серверов с сайта — `tf_transfer_servers_v1`).

## Активация подарков (покупка за Древние монеты): третий скрипт действия

Магазин подарков (`/chests2.php`) продаёт предметы за Древние монеты. Покупка **необратима**: монеты не возвращаются.
Правила сайта для автоматической покупки **не проверены** (см. «Что нужно уточнить»), поэтому схема самая осторожная:

- запуск только кнопкой «🪙 Купить» в диалоге «Активация подарков» (меню «⚡ Скрипты», трей → «Скрипты», «Выбрать» в списке персонажей,
  командная палитра); перед стартом — окно подтверждения со сводкой (аккаунтов, предметов, монет) и словами «необратима»;
- «👁 Пробный запуск» открывает магазин, находит кнопку «Купить» / «Открыть», но **не нажимает** её; есть «⏹ Стоп»
  (новые покупки не начинаются, начатая заканчивается и попадает в журнал);
- чтение магазина (при открытии окна и по «🔄 Обновить цены и баланс») — только чтение: `/chests2.php` (цены, «Доступно Вам: N шт.»,
  описание, баланс, ник аккаунта) и, если у лимитного предмета неизвестна дата последней покупки, `/chests2.php?do=history` («История монет»).
  Цены, наличие и описание **не зашиты в код**: каждый раз берутся с сайта; предметы ищутся по названию из закреплённого списка
  из 8 позиций, ивентовых, которых сейчас нет на сайте, приложение рисует заблокированными;
- одна покупка = один клик «Купить» (для сундуков «Открыть») и один клик «Да» в окне подтверждения самого сайта; перед кликом
  проверяется, что название и ссылка окна относятся к нужному предмету и цена на странице равна ожидаемой (иначе покупка
  не выполняется). Покупки идут штука за штукой с паузой 1–2 с (страница после каждой покупки обновляется, токены новые);
- количество ограничивается лимитом («Доступно Вам») и монетами по данным сайта; если лимит исчерпан посреди заказа,
  покупается столько, сколько доступно, итог помечается «куплено до лимита». Лимит обновляется **через месяц после последней
  покупки** (даже неполной): дата считается по московскому времени и запоминается локально;
- повторы — только пока кнопка не нажата (таймаут, нет окна подтверждения); после нажатия итог сверяется по балансу, затем по
  «Истории монет»; если подтвердить нельзя — «результат не распознан», остальное у этого аккаунта **не выполняется**, ничего
  не повторяется автоматически;
- нет расписаний и автозапусков; нагрузка и повторы — из «Настройки → Скрипты»;
- один аккаунт сайта, открытый в нескольких браузерах, показывается и покупает **один раз** (баланс и лимиты общие);
- после покупок баланс отмеченных аккаунтов перечитывается и записывается всем браузерам аккаунта;
- хранение только локальное: аккаунты, балансы, лимиты, каталог (`tf_shop_state_v1`) и **общий** журнал последних 300 покупок
  (`tf_shop_log_v1`, «Настройки → Журналы», вид «Подарки»; один аккаунт отбирается поиском по нику). Пробные запуски и отказы до
  нажатия в журнал не пишутся.

## Мини-игра «Коллекция» (Issue #72): панель в видимом окне

Страница `/minigames.php?game=collection&doo=display` в ВИДИМОМ окне персонажа (его открывает пользователь). Скрипт `collection.js`
рисует слева, под «Помощником входа», панель «Коллекция». Правила сайта для автоматического открытия карточек **не проверены**
(см. «Что нужно уточнить»), поэтому схема та же, что у остальных скриптов действия:

- запуск только кнопкой «▶ Старт» и только после подтверждения («Карточки тратятся необратимо»: цель, поведение выше цели, лимит);
- «👁 Проверить» только читает `doo=info` (карточки, прогресс категорий) и пишет, что сделает запуск; ничего не нажимается;
- «⏹ Стоп» всегда доступен: новые запросы не начинаются, текущий завершается; никаких расписаний и автозапусков;
- запросы — те же, что делает сама игра (`doo=info`, `turn`, `get_item`, `get_next`), только на тот же сайт и с куками страницы;
  адреса берутся из `data-info`/`data-turn` поля `#collection`, чужой адрес — панель не показывается;
- щадящая нагрузка: пауза 0,35–0,8 с перед каждой карточкой и 0,25–0,5 с перед обменом или призом, строго по одному запросу;
- с неоткрытых карточек падают только категории 1–5; 6-я (фрагменты) даётся лишь обменом 5 карт пятой категории, поэтому в статистике у неё нет выпадений,
  а рост одного лишь счёта 6-й после открытия карточки не засчитывается как выпадение;
- «Проверка безопасности» не решается: сайт вернул страницу вместо JSON — запуск останавливается с понятной причиной;
  так же — при потере входа или изменении формата ответа (ошибка, а не «ноль карточек»);
- действия без повторов: результат проверяется по новому состоянию. Карточка не открылась 3 раза подряд или сайт не принял
  обмен/приз — остановка, а не бесконечный цикл. Предел одного запуска — 5000 карт;
- собрана категория выше цели — остановка, решение за пользователем (по настройке «забрать все до N-й» приз забирается);
- статистика (сколько карт какой категории выпало, призы, обмены, скорость) хранится только в окне: за сессию — в `sessionStorage`
  (до закрытия окна), цель и настройки — в `localStorage` профиля персонажа. Наружу ничего не отправляется;
- анимация выпадения (подсветка строки категории, лента последних карточек) нарисована в самой панели средствами CSS, запросов не добавляет и их не ждёт;
  собственная анимация сайта не запускается, потому что запросы идут напрямую; поле игры на странице обновится после перезагрузки;
- журнал запусков: после каждого запуска, где что-то сделано или были проблемы, панель кладёт отчёт (цель, выпадения 1–5, призы, обмены, время,
  итог; без ника, почты и адресов) в hash адреса окна `#TFCOL1_<json>`. Rust-команда `take_collection_reports` раз в 3 с читает **только адреса окон
  приложения** (`sync-win-*`), возвращает отчёты и убирает hash — для панели это подтверждение. Сайт при этом не трогается, сетевых запросов нет.
  Пока отчёт не принят, он лежит в `localStorage` профиля (до 20 штук) и отправляется снова; в приложении дубли отбрасываются по id;
- отчёт приходит со страницы сайта, поэтому приложение ему не доверяет: числа ограничиваются, строки обрезаются, вывод экранируется
  (`collectionStore.js`). Журнал хранит последние 200 запусков на этом компьютере («Настройки → Журналы → Коллекция», итоги по всем запускам, очистка);
- отключается в «Настройки → Окно браузера персонажа» (действует на окна, открытые после изменения).

Отличие от стороннего userscript `pw-collection`: код написан заново, без Tampermonkey, без внешнего бэкенда статистики и без
запуска на консольной вставке.

## Что уходит в сеть

| Куда | Что |
| --- | --- |
| `pwonline.ru` | Страницы, которые открыты в окнах приложения: вход, баланс, марафоны, новости. Запросы идут от окна WebView с куками персонажа, как у обычного браузера |
| `github.com/drednight/Tvinoferma` | Файл `latest.json` и установщик при проверке обновлений |

Телеметрии и аналитики нет. Пароли и куки наружу не отправляются: пароли в хранилище ОС,
куки-банк зашифрован и лежит локально (`cookie_bank.rs`).

При ручном входе через VK / Mail.ru пользователь работает со страницами этих сервисов в видимом окне
сам. Куки этих доменов в куки-банк не сохраняются.

## Чек-лист перед добавлением новой возможности

- [ ] Скрипт только читает? Если нет — это действие, нужна кнопка и подтверждение (принцип 2).
- [ ] Не запускается по расписанию (принцип 3), если меняет данные на сайте.
- [ ] Идёт через общую очередь, а не напрямую.
- [ ] Правила сайта по этому сценарию прочитаны, вывод записан выше.
- [ ] В фикстурах и логах нет паролей, куков и личных данных.
