# Проверка и перенос команд, диагностика запусков

## Перед вводом

На странице команды доступен «План и проверка — без запуска»: получатели по сохранённым данным, клавиши, клики, повторы, вложенные команды и завершающий фокус. Ошибки настройки и предупреждения отделены от проверок живых окон Windows. В редакторе проверка обновляется при изменениях; существующие проверки исполнителя остаются обязательными. План не гарантирует наличие окон и обработку ввода игрой.

Клики выделены как потенциально расходные действия. Включение непрерывного повтора сохраняется после завершения команды и требует отдельного выключения.

## Результаты фонового сравнения

Для отдельной фоновой последовательности доступны отметки «Не проверено», «Сработало», «Не сработало», «Частично» и заметка до 600 символов. Отметка требует подтверждения наблюдения в игре. API никогда не выставляет её автоматически. Изменение физического плана обесценивает предыдущую отметку; переименование — нет. Изменение контекста пати/ПЛ, точек, профилей или других сохранённых физических планов тоже сбрасывает актуальность отметки (консервативная проверка). Сравнивайте один способ, одну клавишу и одного получателя за раз.

## Перенос, восстановление

«Импорт / экспорт» переносит команды, опционально точки и профили. Пароли, настройки входа, черновики, ручные результаты и корзина не экспортируются. Названия и локальные ID могут раскрывать пользовательские сведения — проверяйте JSON перед передачей.

По умолчанию импорт создаёт копии; замена по названию требует явного режима. Сначала показывается список изменений. Сочетания и разрешение кликов сбрасываются, включается строгий выбор получателей. Импорт заблокирован до проверки и сохранения в редакторе, в том числе во вложенной команде. Внешние ссылки на команды/точки/профили не привязываются случайно к локальным объектам. Координаты, DPI, ПЛ и локальные ID требуют проверки на другом компьютере.

Редактор сохраняет локальный черновик и предупреждает о закрытии с изменениями. При следующем открытии восстановление предлагается, но не применяется автоматически. Ошибка localStorage показывается отдельно. Последние пять удалённых команд можно вернуть; занятое сочетание при восстановлении сбрасывается. Это не резервная копия всего приложения.

## Журнал по запускам

«Диагностика по запускам» показывает и экспортирует JSON текущего сеанса: runId, конфигурационную проверку, IPC-этапы, измеренную длительность IPC, число найденных окон, запросы ввода, результат Windows, завершение/отказ и восстановление горячих клавиш. Для фоновых отчётов отдельно сохраняются доступные проверки личности/состояния/прав/физического ввода и фазы уведомлений/нажатия/отпускания/восстановления. Отсутствующие данные не считаются успешной проверкой.

До 20 запусков, до 250 событий на запуск (первые 50 и последние 200); пропуски подсчитываются. Одинаковые соседние события объединяются. Не добавлены дополнительные фоновые пробы или задержки; собираются уже полученные результаты. Поздний ответ IPC не прикрепляется к другому запуску. Журнал не переживает перезапуск. Обычный журнал и структурированная история очищаются вместе.

В JSON передаются только разрешённые поля, не полные IPC-аргументы, пути клиента или содержимое учётных записей. Перед публичной отправкой всё равно просмотрите файл: он содержит локальные ID, клавиши и этапы команды. Ошибки 1460/5, смена foreground и отказ preflight имеют разные объяснения. Таймаут не доказывает недоставку. API_OK_GAME_UNKNOWN означает только принятие запроса Windows.

## Проверка интерфейса

`npm exec vitest -- run tests/gameMacrosSafety.test.js tests/gameMacrosPanel.test.js tests/gameMacrosRuntime.test.js`

Для реального Chromium: запустите Vite и `node scripts/test-macro-browser.mjs`. Требуются `playwright-core` и Chromium; можно задать `PLAYWRIGHT_MODULE`, `CHROMIUM_EXECUTABLE`, `MACRO_TEST_URL`. Проверяются создание/настройка/сохранение/редактирование/удаление/возврат, план, защита закрытия, клавиатурное открытие/Escape и ширина 390px. Этот браузерный тест не проверяет Windows IPC и реакцию PW.

## Внешний мультибоксинг

Сторонняя программа может использовать иной способ доставки и полезна как отдельное сравнение, но сама по себе не обеспечивает ввод в неактивный PW. Перед экспериментом нужно выбрать конкретную программу, проверить её механизм и актуальные правила игры. Не устанавливать драйверы, не внедрять DLL, не обходить защиту; не запускать одновременно два повтора. Установка сторонних программ этим изменением не выполняется.

## Пошаговый одиночный тест и сравнение

В «Лаборатории фонового ввода» доступны мастер одиночной проверки и таблица результатов. Мастер не создаёт постоянные команды и не меняет старую область получателей. Выбирается один актуальный твин выбранной пати (не ПЛ), одна клавиша/сочетание и один из пяти способов лаборатории.

Проверка окна без клавиш использует существующую диагностику WM_NULL; отчёт необходимо прочитать самостоятельно, его завершение не гарантирует пригодности окна. Изменение выбора сбрасывает согласие. Отправка требует отдельного подтверждения и нажатия «Отправить один раз». Существующий исполнитель заново проверяет получателя; строгий поднабор не расширяется на все окна при ошибке. Во время команды/паузы/повтора запуск теста запрещён. Автоматических повторов, перехода к обычному вводу и перебора способов нет. «Стоп» не отменяет уже отправленные сообщения.

Технический итог сохраняется с отметкой «Не проверено». Реакция игры задаётся только вручную с подтверждением наблюдения. При ошибке сохранения можно повторить сохранение без повторной отправки клавиши. После теста выбор заблокирован — новый эксперимент открывается отдельно.

Таблица хранит последние 40 отдельных тестов: время, ID получателя/пати, клавишу, способ, техническое резюме, runId, ручное наблюдение и заметку. Диагностика теста сохраняется вместе с ним (до 60 разрешённых событий: первые 20 и последние 40; число пропущенных отмечается) и доступна для копирования/экспорта даже после перезапуска. Это отдельная ограниченная история в настройках, не экспортируемая при переносе команд. Полный журнал сеанса остаётся отдельным. Смена ника не меняет ID исторического получателя; удалённый персонаж показывается по ID.

Карточка итога на странице команд отдельно показывает этап, известный факт, неизвестный игровой результат и следующий шаг. Коды 1460, 5, остановка и смена активного окна не объединяются в одну предполагаемую причину. Карточка описывает доступные измерения, а не устанавливает внутреннюю причину отказа PW.

Браузерный сценарий мастера: `node scripts/test-macro-trial-browser.mjs` с теми же переменными окружения Chromium. В этом сценарии Windows намеренно имитируется; реальные сообщения игре не отправляются. Тестовое окно-приёмник Windows, изменение политики старых команд и сторонний мультибоксинг не входят в эту доработку.

## Собственное окно-приёмник Windows и выбранный пакет

В лаборатории появилась кнопка «Окно-приёмник Windows». Она открывает панель, но не создаёт окно и не отправляет клавиши автоматически. «Открыть окно» создаёт отдельное Win32-окно нашего процесса без принудительной активации. Приёмник не является игровым клиентом и не добавляется в список получателей команд.

Окно записывает только свои WM_KEYDOWN/UP, WM_SYSKEYDOWN/UP, WM_ACTIVATE/APP и WM_SETFOCUS/KILLFOCUS. Для каждого события: последовательный номер, время, VK, параметры сообщения и foreground в момент получения. Не устанавливаются глобальные хуки, не читается клавиатура других окон, не записываются WM_CHAR или текст. Физическое нажатие в самом приёмнике тоже попадёт в отчёт как VK; не вводите там секреты. Хранятся только последние 200 событий в памяти; очистка и закрытие доступны явно.

Тест направляется исключительно в принадлежащий приложению HWND, который выбирает backend, а не фронтенд. Доступны B, F8, SHIFT+1 и существующие семь транспортов. Для активности используется тот же отправитель; исключение для окон собственного процесса относится только к нашему зарегистрированному приёмнику и не ослабляет проверки игровых клиентов. Нет непрерывного повтора или перебора. Каждая отправка требует нового согласия; занятый исполнитель, пауза и повтор блокируют её. При ошибке ничего не повторяется автоматически.

Для PostMessage/SendNotifyMessage возврат API может опередить получение сообщений: отдельно обновите отчёт. Полученные события и `delivery` нужно сравнивать, а не считать равнозначными. Успех здесь проверяет транспорт до простого окна, а не готовность PW; поведение игрового клиента может отличаться. Нативная компиляция проверяется Windows CI; UI-тесты с имитацией Windows не доказывают реальное получение сообщений.

В таблице одиночных тестов можно выбрать строки и открыть «Предпросмотр выбранного пакета». Без выбранных строк экспорт не выполняется. До явного скачивания показывается весь JSON. По умолчанию заметки исключены, ID получателей заменены на условные, PID/HWND и исходные runId не включаются. Для технического разбора их можно явно включить. Это не гарантированное обезличивание: время, клавиши и текст ошибок могут содержать контекст. Пароли, настройки входа, остальные команды и невыбранные тесты в пакет не попадают. Обязательно просмотрите текст перед передачей.

## Первое пользовательское сравнение и диагностика открытия оверлея

Получен ручной отчёт: обычная B с активацией выполнилась один раз у выбранного твина, не у ПЛ. PostMessage и post-target-layout: Windows приняла down/up, но пользователь не увидел открытия инвентаря. Activity остановился с 1460 на activate-app; activity-window — с 1460 на activate-window, `inputSent=false`. Для одного activity-notify пользователь отметил открытие инвентаря без изменения фокуса; другой запуск этого способа остался без ручной отметки. Это положительный единичный результат при конкретных условиях, не доказательство стабильной поддержки игры, других клавиш или нескольких получателей. Исходный пользовательский JSON, имена, PID/HWND и ID пати в репозиторий не включены.

Пользователь также сообщил, что оверлей не открывается; точная причина исходным журналом не установлена. Явное открытие теперь разворачивает существующее окно, проверяет его пересечение с текущими экранами и возвращает заэкранное окно в центр, показывает и выводит вперёд. Сохранённые настройки поверх окон не переопределяются. Настройка существующего оверлея в фоне не должна показывать или активировать его.

Журнал содержит отдельные этапы: запрос открытия с ID, завершение native-показа, подтверждение интерфейса по ID после получения состояния. Через 5 секунд без подтверждения выводится предупреждение (не доказательство отсутствия окна). Ошибки создания/показа также записываются. При повторной проверке сохраните эти строки независимо от того, появилось окно или нет. Основной сценарий завершения команды больше не дублирует итоговую строку до и после восстановления горячих клавиш.

## Модификатор «Мышь только в активном окне»

В блоке настроек повтора добавлено независимое поле, по умолчанию выключенное: Ctrl, Alt, Shift или их комбинации. При включённом повторе мыши удержание ровно выбранного набора модификаторов (без Win) оставляет ЛКМ, ПКМ, среднюю и две боковые кнопки только в активном игровом окне. Прокрутка колеса не добавляется в повтор этой доработкой. Сам режим повтора не выключается; отдельные команды/хоткеи и клавиатурный повтор не изменяются.

Это обычный локальный клик с физически зажатым модификатором, а не клик с удалённым Ctrl/Shift/Alt: внутриигровое назначение сочетания надо учитывать. Не используйте расходные действия при первой проверке. Существующий режим «ЛКМ только твинам» сохранён отдельно; при одинаковом наборе модификаторов локальный режим имеет приоритет, исходный клик не блокируется и твинам не отправляется.

Маршрут фиксируется по нажатию каждой кнопки. Если модификатор отпущен до отпускания локальной кнопки, её отпускание тоже не копируется. Если кнопка была отправлена твинам до нажатия модификатора, её отпускание должно дойти по прежнему маршруту. Это предотвращает зависание скопированной кнопки при изменении модификаторов во время удержания. Для локального отпускания учитывается захваченная пара даже при смене фокуса; локальные клики сбрасывают историю распознавания двойного клика повтора.

Ручная проверка: включить только повтор мыши; выбрать, например, Shift; без Shift проверить обычный повтор безопасного клика; с Shift проверить отсутствие копий у твинов для ЛКМ/ПКМ/средней/боковых; отпустить Shift — проверить возврат обычного повтора. Отдельно проверить отпускание Shift раньше кнопки и нажатие Shift после начала обычного удержания. По завершении явно выключить повтор. Реальная работа в PW требует ручного наблюдения, автотесты проверяют маршрутизацию и связность UI/backend.
