# Кандидат 2.3.0 — контроль перед выпуском

**Статус: подготовка и тестирование, не стабильный выпуск.** Тег и публикация Release
не выполнялись. До принятия кандидата сохраняется последний стабильный выпуск 2.2.0.

## Подготовлено в исходниках

- Версия 2.3.0 согласована в package.json, npm lock, Cargo.toml, Cargo.lock и tauri.conf.json.
- Описание выпуска в CHANGELOG.md, README, инструкции и снимки интерфейса обновляются
  вместе с кандидатом; генератор заметок проверяется командой
  `node scripts/release-notes.mjs v2.3.0`.
- Добавлены регрессии на уменьшение счётчика сайта, сохранность ручных данных,
  неверный месяц, будущий марафон, некорректный счётчик и запоздалый ответ.
- Добавлены проверки последовательной принудительной переподписи окон и прогресса,
  выбора сессии персонажа и сопоставления иконок реальных названий предметов.

## Автоматические проверки перед тегом

- [ ] Последняя полная CI успешна на итоговом коммите: четыре группы JS-тестов,
      lint, форматирование, типы, сборка, Rust tests/fmt/clippy и аудит.
- [ ] Тестовый Windows exe успешно собран из того же коммита; его SHA указан в архиве.
- [ ] Проверены актуальные снимки README и наличие всех связанных файлов.

## Требуют ручной проверки на Windows

Проверять в отдельной тестовой учётной записи Windows: тестовый exe использует
обычный identifier и **не изолирует** данные и хранилище контактов от установленной версии.

- [ ] Иконки видны после раскрытия наград на «Сегодня», в промокодах и журнале;
      в передаче и подарках они стоят перед названиями и не растягиваются.
- [ ] Количество и привязка не пропадают; неизвестные предметы не получают чужую иконку.
- [ ] «Названия и значки» заменяет неправильные существующие значки, идёт по очереди,
      показывает процент/ник; отказ в UAC не зависает и не отображается как полный успех.
- [ ] При сверке 5 → 0 сайт показывает 0; ручные даты и поправка сохранены.
      Другой месяц, будущий марафон и ошибка чтения не добавляют зачёт.
- [ ] Кнопка «Сайт» каждого участника открывает правильную страницу в его собственной
      сессии; обычные ссылки по-прежнему учитывают выбор системного браузера/WebView.
- [ ] Резервная копия и восстановление проверены на синтетических данных.
- [ ] Подписанный установщик и проверка обновления 2.2.0 → 2.3.0 приняты отдельно
      после создания черновика релиза владельцем проекта.

Только после приёмки и зелёных проверок: включить PR в main, проверить описание выпуска,
создать тег v2.3.0 и выполнить процедуру из RELEASE.md. Не публиковать latest.json
или стабильный Release автоматически только по факту успешной тестовой сборки.
