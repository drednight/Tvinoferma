# Внешний API и локальная страничка управления

Как другим программам (Python, PowerShell, AHK, своим утилитам) взаимодействовать
с работающей Твинофермой — читать персонажей, менять статы и проходки, запускать
окна игры и пати.

> Статус: **реализовано (M1–M3 и настройки), кроме ручной приёмки на Windows.**
> Сервер — `src-tauri/src/external_api/`, мост и действия —
> `js/modules/externalApi/`, панель — «Настройки → 🔌 Внешний API».
> Приёмка на Windows — чек-лист в разделе 8; Rust-тесты идут в общем `cargo test`
> на CI (в песочнице без Rust они не запускаются).
>
> Интерактивный макет странички лежит в `demo/external-api/` и работает на вымышленных
> данных: `DEMO_ENTRY=/demo/external-api/index.html npm run demo`, затем
> `http://localhost:1420/demo/external-api/index.html`. Токен в макете — любая
> непустая строка; запросы никуда не уходят.

## 1. Короткий ответ: сможет ли сторонняя программа запускать окна

**Да.** Запуск уже полностью реализован в приложении, и внешней программе не нужно
делать его заново — достаточно вызвать тот же код, что вызывает трей или кнопка «▶».
Проверить это короче всего из терминала: `tf` (`npm run tf -- launch-character Mag_1 --yes`)
собирает тот же запрос и объясняет причину отказа; команды и правила для агентов —
[AGENT-CLI.md](AGENT-CLI.md) и `skills/tvinoferma/SKILL.md`. На странице API те же
действия — карточки вкладки «Действия».

| Что | Можно ли из внешней программы | Чем это делается сейчас |
| --- | --- | --- |
| Запустить одно окно игры | да | `launchOne(char, { interactive: false })` |
| Запустить пати целиком | да | `launchPartyByName(name, { interactive: false })` |
| Запустить выбранных участников пати | да | `launchPartyByName(name, { interactive: false, memberIds })` |
| Запустить пати по id | да (тонкая обёртка) | `launchGroup(title, members, { partyId, interactive: false })` |
| Закрыть окна персонажей/пати | да | `runningClientDetails()` + `closeClientsByPid(pids)` |
| Показать главное окно / оверлей | да | `tray::show_main` / `openOverlay()` |
| Изменить статы и проходки | да, **только в базе Твинофермы** | `state` + `persist()` |
| Поменять значения в игре | **нет** | игра не даёт такого канала; статы читаются со скриншота (`stats_ocr`) |

Важные оговорки, которые нельзя обойти:

1. **Это локальный запуск.** Игра запускается через GameCenter (VK Play) на этом же
   компьютере, тем же пользователем и с теми же правами, что и из интерфейса.
2. **Нужен прикреплённый GameCenter и запомненный вход.** Без них `launchGroup` честно
   откажется запускать персонажа и вернёт его в списке пропущенных. API не может
   «обойти» эту проверку — иначе окно откроется под чужим аккаунтом.
3. **Один запуск за раз.** Запуски стоят в общей очереди док-задач (`task.waitTurn()`);
   второй запрос ждёт, а не ломает первый.
4. **Запуск долгий.** Один клиент — обычно 15–60 с, пати — минуты. Поэтому HTTP-запрос
   запуска не держится открытым: API возвращает `jobId`, а результат забирается опросом.
5. **Окна от администратора.** Если игра запущена от администратора, подпись окна
   («Ник — Класс», значок) может потребовать разрешения Windows (`elevate`). Это
   существующее поведение, API его не меняет.
6. **Статы и проходки — это учётные данные Твинофермы**, а не игровые. Меняя их через API,
   вы меняете то, что видно в карточках и профиле. В игру эти числа не отправляются.

Если запуск «не получается», причин обычно три, и все они отвечают по-разному:

- `403 forbidden_scope` — право «запуск и закрытие окон» выключено (по умолчанию выключены
  и `modify`, и `launchClose`: включение сервера не даёт права менять и запускать).
  Включается галочкой в «Настройки → 🔌 Внешний API»; карточка на странице при этом
  остаётся видимой — отказывает сервер, а не интерфейс.
- `429 launch_busy` — уже идёт другое внешнее задание.
- `202` и `skipped` в итоге задания — персонаж не готов к запуску: нет прикреплённого
  GameCenter (`no_gc`), не запомнен вход (`no_saved_login`) или окно уже открыт
  (`already_running`). Это не ошибка HTTP: HTTP-ответ успешен, а итог честно объясняет,
  почему окно не открылось, — так же поступает и кнопка в интерфейсе.

Раньше к этому списку была четвёртая причина: само задание падало с
`launch is not a function` (мост не подкладывал лаунчер), а страница показывала
успешные `202`. Исправлено; проводка проверяет `tests/externalApi.launchWiring.test.js`.

## 2. Почему нельзя просто писать в `state.json`

Технически файл доступен, но внешняя правка почти всегда либо потеряется, либо испортит
данные:

- работающее приложение держит состояние в памяти (`js/core/state.js`), а на диск пишет
  `js/core/storage.js` (`persist()` → `writeNow()`), поэтому внешняя правка будет
  перезаписана ближайшим автосохранением;
- запись защищена флагами `outcomeUncertain`, `protectedState` и очередью записей —
  при внешней правке проверки целостности (`state_diag.rs`, резервные копии) могут
  отправить приложение в режим «Сохранение остановлено»;
- контакты и токены входа в файл не пишутся (Windows Credential Manager, `vault.rs`),
  так что «полный» state снаружи всё равно не собрать;
- интерфейс ничего не узнает об изменении: карточки и панели перерисовываются только
  после действий внутри приложения.

Правильный путь — **просить приложение сделать действие**: локальный HTTP-сервер в Rust
принимает запрос, передаёт его в JS главного окна, JS выполняет его существующими
функциями (с нормализацией, историей статов, очередью и сохранением) и возвращает ответ.

## 3. Архитектура

```
Сторонняя программа            Твиноферма (один процесс)
─────────────────────          ─────────────────────────────────────────────────
Python / PowerShell            Rust: external_api
  POST /api/v1/...   ───────►  ├─ проверка Host и Bearer-токена
  Bearer <token>               ├─ лимиты размера и времени
                               ├─ requestId → oneshot
                               │        │ emit_to("main", "external-api-request")
                               │        ▼
                               │   JS: main window (всегда жив, даже в трее)
                               │   ├─ read:  state.characters, state.parties
                               │   │        runningClientDetails() + windowRows()
                               │   ├─ write: проверка → statsHistory → persist()
                               │   │        → renderCharacters()
                               │   └─ launch: launchOne / launchPartyByName
                               │            (interactive: false)
                               │        │ invoke("external_api_reply")
  HTTP-ответ     ◄────────────  └────────┘
```

Почему мост через JS, а не логика в Rust:

- нормализация, история статов, очередь сохранений и перерисовка уже написаны и
  проверены тестами — дублировать их в Rust опасно;
- изменение сразу видно в открытом окне;
- Rust остаётся «тонким транспортом»: разбор HTTP, права, лимиты, журнал запросов.

Главное окно при закрытии сворачивается в трей, а не уничтожается
(`WindowEvent::CloseRequested` → `prevent_close()` + `hide()`), поэтому JS-контекст жив,
пока живёт приложение. Если приложение действительно завершили — сервер останавливается,
а внешняя программа получает `connection refused`; это и есть проверка «Твиноферма не запущена».

### Два режима ответа

- **Сразу** — чтение и изменение данных (укладываются в секунды).
- **Задание (job)** — запуск окон: `POST` отвечает `202 { jobId }`, результат
  забирается `GET /api/v1/jobs/{jobId}`. Так HTTP-клиент не ждёт 3 минуты, а страница
  может рисовать прогресс. Закрытие окон — обычный синхронный ответ: оно короткое
  и не требует прогресса.

## 4. Контракт API v1

> Подробный справочник всех методов (параметры, ответы, примеры для curl,
> PowerShell и Python, памятка «что можно делать») — отдельный файл
> [`EXTERNAL-API-REFERENCE.md`](EXTERNAL-API-REFERENCE.md). Он же встроен в
> страницу API: вкладка «Справочник API», где у каждого метода своя панель запроса
> («▶ Выполнить» отвечает прямо в карточке).

Базовый адрес: `http://127.0.0.1:<порт>/api/v1`, по умолчанию порт **47831**,
то есть полный адрес списка персонажей — `http://127.0.0.1:47831/api/v1/characters`.
Все ответы — JSON UTF-8. Идентификаторы — строки. Время — ISO 8601.

### 4.1. Общие правила

- `Authorization: Bearer <token>` обязателен для всех `/api/v1/*`.
- Ошибка имеет вид:

  ```json
  { "error": { "code": "no_such_character", "message": "Персонаж не найден" } }
  ```

- `GET /` — статическая страничка (токен вводится в поле, в HTML он не вшивается),
  `GET /favicon.ico` — `204`, чтобы браузер не сыпал ошибками в консоль.
- Никаких CORS-заголовков; `OPTIONS` получает `403`.

### 4.2. `GET /health`

Проверка связи и готовности.

```json
{
  "ok": true,
  "app": { "version": "3.0.0", "build": "stable" },
  "api": { "version": 1, "uptimeSec": 812 },
  "storage": { "writable": true },
  "scopes": { "read": true, "modify": false, "launchClose": false },
  "launch": { "busy": false }
}
```

`storage.writable: false` — приложение в режиме «Сохранение остановлено»: чтение работает,
изменения вернут `423`. `scopes` — фактически включённые галочки: по ним клиент решает
заранее, доступна ли правка и запуск, не получая `403` на каждую попытку. `launch.busy` —
идёт ли сейчас внешнее задание запуска.

#### `GET /status` — сводка одним запросом

Один запрос вместо пяти: счётчики, дела на сегодня, баланс реестра, права и
занятость запуска.

```json
{
  "ok": true,
  "app": { "version": "3.0.0", "build": "stable" },
  "api": { "version": 1, "uptimeSec": 812 },
  "storage": { "writable": true },
  "scopes": { "read": true, "modify": true, "launchClose": true },
  "launch": { "busy": false },
  "counts": { "characters": 3, "parties": 2, "marathons": 1, "plannerEntries": 12, "windows": 1, "financeOperations": 7 },
  "today": { "date": "2026-11-25", "total": 4, "done": 1 },
  "finance": { "balances": { "gold": 125000, "coins": 340 } }
}
```

Контактов, паролей и содержимого заметок в сводке нет — только счётчики и
итоги, поэтому её безопасно показывать в сторонней программе.

### 4.3. `GET /characters`

**Все персонажи списком, по умолчанию отсортированные по `id`.** Без секретов.

Параметры:

| Имя | Где | Тип | Описание |
| --- | --- | --- | --- |
| `party` | query | string | id или название пати (необязательно) |
| `fields` | query | string | Поля через запятую; вложенные — через точку. `id` остаётся всегда |
| `lang` | query | string | `en` (по умолчанию) или `ru` — подписи по-русски |
| `flat` | query | boolean | `true` (по умолчанию) — плоские ключи, `false` — вложенные объекты |
| `sort` | query | string | `id` (по умолчанию), `nick`, `level`, `none` |
| `order` | query | string | `asc` (по умолчанию) или `desc` |
| `full` | query | boolean | `true` — полные карточки: со статами, заметками и историей монет |

**Список по умолчанию — без тяжёлых полей** (`stats`, `notes`, `coinHistory`,
константа `LIST_OMITTED` в `actions/read.js`). Два десятка статов на каждого
персонажа делают ответ втрое длиннее, а в списке их почти никто не читает: список
отвечает на «кто есть и до чего дожил», карточка — на «с чем он». Что убрано, видно
из самого ответа: `detail: "list"` и `omitted: [...]` — сокращение заявлено, а не
промолчано. Полную карточку просят тремя способами: `?full=true`, адресный маршрут
(`GET /characters/{id}`, `/stats/{stat}`, `/dungeon-passes/{pass}` — они полные
всегда) или `fields=stats.hp`, который перекрывает правило: назвал поле — получи его
(`detail: "picked"`). Выгрузки (`/export/characters.csv`) тоже полные: столбцы
таблицы от нового правила не зависят: выгрузка была полной и осталась.

Одним запросом можно попросить сразу несколько полей:
`GET /api/v1/characters?fields=id,class,level,dungeonPasses` →
`{"characters":[{"id":"Mag_1","class":"Маг","level":100,"dungeonPasses":{…}}],"count":1,"fields":[…]}`.
По умолчанию вместо `dungeonPasses` возвращаются плоские ключи
`"dungeonPasses.weapon": 3`; `flat=false` даёт вложенный объект. Неизвестное поле —
`422 invalid_value` со списком допустимых (`CHARACTER_FIELD_NAMES`).

```json
{
  "characters": [
    {
      "id": "Mag_1",
      "nick": "Маг",
      "class": "Маг",
      "level": 100,
      "sky": { "name": "Небо предела", "level": 10 },
      "partyIds": ["p-osnova"],
      "mainPartyId": "p-osnova",
      "stats": { "physAttack": 12000, "magAttack": 96000, "hp": 48000 },
      "dungeonPasses": { "weapon": 3, "armor": 2, "relic": 1 },
      "ancientCoins": 120,
      "isLoggedIn": true,
      "lastLoginCheck": "2026-11-24T09:10:00.000Z",
      "updatedAt": "2026-11-24T09:12:00.000Z",
      "running": { "pid": 12345, "title": "Маг — Маг" }
    }
  ]
}
```

В ответ **не попадают** `contacts`, токены GameCenter, куки, `launch.*` и прочие
секреты — поля перечисляются белым списком.

### 4.4. `GET /characters/{id}`

То же для одного персонажа: `{ "character": { … } }`. `404 no_such_character`.
id в пути — тот же, что в ответе `GET /characters` (читаемый: транслит ника плюс
суффикс, например `Mag_1`). Ник как ключ не используется: у двух аккаунтов он может
совпадать, и тогда запрос попал бы не в того персонажа.

### 4.5. `PATCH /characters/{id}`

Частичное изменение. Меняются только переданные ключи; остальные не трогаются.

```json
{
  "stats": { "physAttack": 12500, "magAttack": 96500 },
  "dungeonPasses": { "weapon": 2 }
}
```

Правила:

- значения — конечные числа, `0 ≤ value ≤ 1 000 000 000`, целые для проходок;
- неизвестный ключ статов игнорируется, неизвестный ключ верхнего уровня — `422`;
- перед изменением снимается снимок в `statsHistory` (`rememberStatsBefore`),
  как при сохранении формы персонажа;
- `updatedAt` обновляется, затем `persist()` и перерисовка списка.

Ответ:

```json
{
  "character": { "id": "Mag_1", "stats": { "…": "…" }, "dungeonPasses": { "weapon": 2 } },
  "changed": ["stats.physAttack", "stats.magAttack", "dungeonPasses.weapon"],
  "statsHistoryAdded": true
}
```

Если запись заблокирована — `423 storage_blocked`, данные в памяти не меняются.

### 4.6. `POST /characters/bulk-update`

До 100 персонажей за раз, частичный успех — нормальный ответ.

```json
{
  "ids": ["Mag_1", "Luchnik_2"],
  "patch": { "dungeonPasses": { "relic": 3 } }
}
```

```json
{
  "updated": [{ "id": "Mag_1", "changed": ["dungeonPasses.relic"] }],
  "failed": [{ "id": "Luchnik_2", "code": "no_such_character", "message": "Персонаж не найден" }]
}
```

### 4.9. `POST /launch/character`

```json
{ "characterId": "Mag_1", "gcId": "gc-1" }
```

`gcId` необязателен — иначе берётся GameCenter персонажа или выбранный в настройках.

Ответ `202`:

```json
{ "jobId": "job_8f2c1a", "status": "queued" }
```

Успешный `202` значит «задание принято и встало в общую очередь запусков», а не
«окно открылось». Запуск требует прикреплённого GameCenter и запомненного входа:
без них задание всё равно завершится, но строки персонажей будут `skipped` с
причиной. Это не ошибка HTTP-запроса — это честный итог.

### 4.10. `POST /launch/party`

```json
{ "partyName": "Основа", "memberIds": ["Mag_1", "Luchnik_2"] }
```

Либо `partyId` вместо `partyName`. `memberIds` фильтруется по составу пати
(`selectMembersById`): чужие id отбрасываются и попадают в `result.ignoredIds`.
Без `memberIds` запускается вся пати в сохранённом порядке — диалог выбора состава
не показывается (`interactive: false`).

Одновременно может быть только одно внешнее задание запуска: второй `POST` до
завершения первого получает `429 launch_busy` и заголовок `Retry-After`.

### 4.11. `POST /launch/selection`

Главный сценарий твин-фермы: выбранные персонажи из разных пати, порядок задаёт
вызывающий. Работает так же, как одиночный запуск: ответ `202 { jobId }`, ход —
в `GET /jobs/{jobId}`.

```json
{ "characterIds": ["Mag_1", "Luchnik_2", "Zhrets_3"], "gcId": "gc-1" }
```

* `characterIds` — 1…100 уникальных id; порядок сохраняется (первым стартует первый).
* Архивные персонажи не запускаются: их нет в `state.characters`.
* Неизвестные id попадают в `ignoredIds` итога задания, а не ломают запуск целиком;
  если известных нет ни одного — `404 no_such_character`.
* `gcId` необязателен: иначе GameCenter берётся у персонажа или выбранный в настройках.
* Один внешний запуск одновременно: второй получает `429 launch_busy`.

Проверки «есть GameCenter», «запомнен вход», «уже запущен» выполняет тот же
`runPreflight`, что и кнопка в интерфейсе, — пропуски видны в `result.items`
как `skipped` с причиной.

### 4.12. `GET /jobs/{jobId}`


### 4.13. Данные твин-фермы: пати, персонажи, марафоны, планировщик, учёт

Эти маршруты отвечают на второй круг задач: «показать всё, что есть, раскрыть
карточку, выгрузить список и запустить выбранных».

#### `GET /parties/{id}`

Карточка пати с составом в сохранённом порядке (как в интерфейсе). Ответ
`{ "party": { … } }` в форме §4.7; `404 no_such_party`.

#### `PATCH /parties/{id}` — право «Изменение»

```json
{ "name": "Основа+", "color": "#000000" }
```

Меняются только переданные поля. `name` не может быть пустым (`422`), `color`
принимает `null` (сброс). Ответ: `{ "party": { "id", "name", "color" }, "changed": […] }`.

#### `PATCH /dungeon-passes/{id}` — право «Изменение»

Короткий путь для простых клиентов: только проходки, без вложенного патча.

```json
{ "weapon": 5, "relic": 3 }
```

Правила те же, что у `PATCH /characters`: ключи `weapon`, `armor`, `relic`,
значения — целые `0…1 000 000 000`. Ответ содержит `dungeonPasses`, `previous`
и `changed`.

#### `GET /characters/{id}/stats` и `/stats/{stat}`

Все статы разом (`character` — плоский объект, `stats` — строки с подписями) или
одно значение: `GET /characters/Mag_1/stats/hp` →
`{ "id": "Mag_1", "stat": "hp", "label": "HP", "value": 120 }`. Неизвестный
ключ — `422`, нет персонажа — `404`.

#### `PATCH /characters/{id}/stats/{stat}` — право «Изменение»

```json
{ "value": 150 }
```

или прибавка:

```json
{ "mode": "inc", "by": 5 }
```

`mode`: `set` (по умолчанию) | `inc` | `dec`; `by` по умолчанию 1. В минус
нельзя, диапазон `0…1 000 000 000`. Снимок истории статов создаётся только при
реальном изменении.

#### `GET /characters/{id}/dungeon-passes` и `/dungeon-passes/{pass}`

Все проходки и сумма (`total`), либо одно число. Имя проходки принимается
по-русски и по-английски: `weapon`/`оружие`, `armor`/`доспех`, `relic`/`реликвия`.
Кириллица в адресе кодируется процентами — это делают `curl` и `urllib`.

#### `PATCH /characters/{id}/dungeon-passes/{pass}` — право «Изменение»

Тело — `{"value": 5}` **или просто число** `5` (короче в curl и PowerShell).
Ответ содержит остальные проходки и новый `total`.

#### `PATCH /characters/{id}` — поля карточки

Тот же маршрут, что в §4.5, теперь принимает и поля карточки вместе со статами:
`nick`, `class`, `level` (0…1000), `notes` (до 5000), `tags` (строка через запятую
или массив, без дублей и регистра), `favorite` и `sky: { name, level }`.

```json
{ "nick": "Маг II", "level": 101, "tags": "основа, PvP", "stats": { "hp": 150 } }
```

Неизвестное поле — `422 invalid_value` (тихого игнорирования нет). Снимок истории
статов создаётся только при изменении статов (`statsHistoryAdded`).

#### `POST /characters` — новый персонаж

```json
{ "nick": "Новый", "class": "Маг", "level": 1, "tags": [] }
```

Обязателен только `nick`. Ответ `201`:
`{ "character": { "id", "nick", "level", "class" }, "duplicateNick": false }`.
`duplicateNick` — предупреждение, а не ошибка: одинаковые ники на разных
аккаунтах допустимы.

#### `GET /marathons`, `GET /marathons/{id}`

Список и карточка марафона: задания с расписанием и наградами, участники,
назначения, прогресс по каждому персонажу и заданию, награды-аворды, бонусы и
`totals` (считает `marathonTotals` из модели интерфейса — API не заводит второй
правды о прогрессе). Папки-серии (`kind: "series"`) отдаются отдельными записями
с `childIds` и без заданий.

```json
{
  "marathons": [
    {
      "id": "m1", "kind": "single", "title": "Марафон ноября",
      "startDate": "2026-11-01", "endDate": "2026-11-30", "status": "active",
      "participantIds": ["Mag_1"],
      "tasks": [{ "id": "t1", "title": "Ежедневки", "targetChecks": 10,
                  "schedule": { "mode": "everyDay", "dates": [], "weekStartDay": 1 },
                  "rewards": [{ "threshold": 5, "rewardText": "100 монет", "rewardCoins": 100 }] }],
      "progress": { "Mag_1": { "t1": { "marks": ["2026-11-02"], "adjust": 1, "site": 2 } } },
      "totals": { "perChar": {}, "perTask": {}, "checks": 3, "maxChecks": 10, "coins": 0, "maxCoins": 100 }
    }
  ]
}
```

`totals` может быть `null`: если модель не смогла посчитать битые данные, список
всё равно отдаётся — пусто лучше, чем падение всего ответа.

#### `GET /marathons/{id}/participants`

Участники марафона и их пати: `{ "marathonId", "characters": [{ "id", "nick" }], "parties": [{ "id", "name" }] }`.

#### `POST /marathons/{id}/marks` — право «Изменение»

Поставить или снять ручную отметку дня.

```json
{ "characterId": "Mag_1", "taskId": "t1", "date": "2026-11-05", "marked": true }
```

Проверки: персонаж участвует в марафоне, задание существует, дата в формате
`YYYY-MM-DD` и внутри сроков марафона. Ответ содержит `marked`, `changed` и
актуальный список `marks`. У папки-серии — `409 marathon_not_ready`.

#### `POST /marathons/{id}/adjust` — право «Изменение»

Абсолютная поправка к счётчику задания (для дел, которые не попали на сайт):

```json
{ "characterId": "Mag_1", "taskId": "t1", "value": 4 }
```

`value` — целое от −100 000 до 100 000. Ответ: `{ "adjust", "previous", "changed" }`.

#### `GET /planner`

Записи планировщика: `{ "entries": [{ "id", "title", "date", "time", "durationMinutes", "kind", "priority", "recurrence", "status" }] }`.

#### `GET /finance`

Учёт: движения денег, позиции магазина, долги и настройки курса. Контакты
персонажей сюда не попадают.

#### `PATCH /planner/entries/{id}` — право «Изменение»

Правка записи планировщика. Тело: `status` (`todo`, `doing`, `done`), `date`
(день, к которому относится статус), `moveToDate` (перенос самой записи),
`title`, `time`.

У повторяющейся записи своё состояние на каждый день, поэтому `date` — это
конкретный день повтора. Правку делает тот же модуль планировщика, что и
интерфейс, — иначе отметки из API и из приложения разошлись бы.

Ответ: `{ "entry": { … }, "statusDate", "statusValue", "changed": [ … ] }` — `statusDate`
и `statusValue` показывают состояние за запрошенный день (у повторов оно своё).

#### `POST /planner/entries` — право «Изменение»

Новая запись в календаре. Обязательно только `title`; остальное необязательно:
`date`, `time`, `durationMinutes`, `kind`, `priority`, `recurrence`.
Запись создаётся тем же нормализатором, что и в интерфейсе.

Ответ: `{ "entry": { "id", "title", "date", "time", "status" } }`.

#### `POST /finance/operations` — право «Изменение»

Новая запись в реестре денег: `kind` (`in`/`out`), `amount`, `currency`
(`gold`/`coins`), `date`, `counterparty`, `note`, `characterId`. Запись идёт
через модель учёта приложения: округление под валюту такое же, как в
интерфейсе, поэтому балансы не расходятся.

#### `GET /export/{набор}.{csv|json}` — выгрузка файлом

Наборы: `characters`, `parties`, `marathons`, `windows`, `planner`, `finance`.
Формат — суффикс в пути (`/export/characters.csv`) или `?format=csv|json`
(приоритет у query). `txt` — тот же CSV.

Ответ приходит с `Content-Type` (`text/csv; charset=utf-8` или
`application/json; charset=utf-8`) и `Content-Disposition: attachment; filename="…"`:
программа сохраняет файл одной командой, без разбора JSON.

```bash
curl -H "Authorization: Bearer $TF_API_TOKEN" \
     -OJ http://127.0.0.1:47831/api/v1/export/characters.csv
```

* CSV — с `;` и BOM: Excel на русской локали открывает без настройки кодировки.
  Значения с `;`, кавычками и переводами строк экранируются по RFC 4180.
* JSON — `{ "dataset", "exportedAt", "rows": [...] }`.
* В выгрузку попадают только белые списки полей: контакты, пароли, путь запуска,
  куки и ключи облака не выгружаются никогда.
* Сводка (набор, формат, число строк, имя файла) есть в теле ответа для клиентов,
  которые разбирают JSON; сам файл — в теле.
* Неизвестный набор — `404 not_found`, неизвестный формат — `422 invalid_value`.

### 4.14. `POST /windows/close`

Закрытие необратимо (несохранённый прогресс в игре теряется), поэтому нужен явный
подтверждающий флаг. Адресат — **PID из `GET /windows`**, а не id персонажа: два
одинаковых ника в разных аккаунтах не должны закрывать чужое окно.

```json
{ "pids": [12345, 23456], "confirm": true }
```

Без `confirm: true` — `400 confirm_required`. Ответ:

```json
{ "closed": 2, "failed": 0, "pending": 0 }
```

Почему так, а не «закрыть пати»: `closePartyWindows` в интерфейсе показывает окно
подтверждения со списком окон, а внешнему вызову подтверждать нечем — поэтому он
получает только то, что уже выбрал по списку `GET /windows`, и передаёт PID явно.
Окна, которых нет в списке, не закрываются.

### 4.15. `POST /app/show`

```json
{ "target": "main" }
```

Показывает главное окно из трея (`tray::show_main`) — это делает **Rust**, не дожидаясь
ответа JS: вызов нужен как раз тогда, когда окно свёрнуто, и не должен зависеть от
очереди моста. Ответ: `{ "shown": true }`. Требуется право «Запуск и закрытие окон».

Тело запроса не разбирается — `target` зарезервирован под будущее (`overlay-open` /
`overlay-close`: `openOverlay()` в `js/modules/gameMacros/runtime.js` — **переключатель**,
поэтому одно значение `overlay` было бы неоднозначным).

### 4.16. `GET /audit`

Кольцевой журнал последних 100 вызовов (только при действующем токене). Отдаётся
только чтением, тела запросов и токены в него не попадают.

```json
{
  "audit": [
    { "atMs": 1763985600000, "method": "GET", "path": "/api/v1/characters", "status": 200, "ms": 12 }
  ]
}
```

| HTTP | `code` | Когда |
| --- | --- | --- |
| 400 | `invalid_json` | тело не разобралось |
| 400 | `bad_request` | строка запроса не разбирается как HTTP |
| 400 | `confirm_required` | закрытие окон без `confirm` |
| 401 | `unauthorized` | нет или неверный Bearer-токен |
| 403 | `forbidden_host` | заголовок `Host` не `127.0.0.1:<порт>` / `localhost:<порт>` |
| 403 | `forbidden_scope` | право выключено в настройках |

| 404 | `not_found` | неизвестный путь или job |

| 429 | `launch_busy` / `too_many_requests` | уже идёт задание / лимит частоты (есть `Retry-After`) |
| 500 | `internal_error` / `save_failed` | сбой приложения / не удалось сохранить состояние |
| 503 | `app_not_ready` | главное окно ещё не загрузилось |
| 503 | `too_many_connections` | больше 16 одновременных соединений |
| 504 | `timeout` (Rust) | JS не ответил за 15 с |

## 5. Безопасность

Локальный порт доступен **любой программе на этом компьютере** и **любой вкладке
браузера**, поэтому API закрыт по умолчанию и включает его пользователь.

1. **Выключен по умолчанию.** Настройка `settings.externalApi.enabled = false`,
   порт `port = 47831`.
2. **Только loopback.** `TcpListener::bind((Ipv4Addr::LOCALHOST, port))` — снаружи
   недоступен, по сети управлять нельзя.
3. **Токен.** `Authorization: Bearer <token>`, сравнение постоянного времени
   (`constant_time_equal`, локальная копия из `cloud_oauth_callback.rs`: там функция
   приватная). Токен проверяется **до** тела запроса: без него — `401`, и тело не
   читается. Формат — ровно 64 hex-символа, иначе сразу `401`.
4. **Защита от DNS rebinding.** Проверка `Host` (разрешены только `127.0.0.1:<порт>`
   и `localhost:<порт>`), ответ `403 forbidden_host`.
5. **Никакого CORS.** Заголовки `Access-Control-Allow-*` не отдаются, `OPTIONS` → `403`.
   Поэтому POST/PATCH с токеном из чужой вкладки браузера невозможны, а GET-эндпоинты
   ничего не меняют.
6. **Токен в хранилище ОС, а не в `state.json`.** JS генерирует 32 случайных байта
   через `crypto.getRandomValues` (64 шестнадцатеричных символа) и пишет их в
   Windows Credential Manager под своим ключом `external-api-v1` — теми же командами
   `secrets_set_many` / `secrets_get_many`, что и контакты персонажей
   (`js/modules/externalApi/token.js`). В `state.json` остаётся только отметка
   `settings.externalApi.tokenCreatedAt`, поэтому резервные копии и облачная
   синхронизация токен не переносят.

   Решения, которые это фиксируют:

   - **Токен можно скопировать или показать в любой момент.** Кнопки
     «Скопировать токен» и «Показать токен» в настройках читают значение из
     хранилища через `peekToken` / `currentToken` — только чтение, ничего не
     создаётся и не меняется (`tests/externalApiToken.test.js` следит, чтобы
     копирование не перезаписывало запись и не «омолаживало» `tokenCreatedAt`).
     Показ гаснет сам через минуту, чтобы значение не оставалось в разметке окна.
     Раньше значение отдавали ровно один раз — при создании, и потерянная копия
     означала перевыпуск, а он роняет все настроенные программы: отсюда и
     «приходится постоянно обновлять токен».
   - **«Перевыпустить токен» — только при утечке.** Он меняет значение, и старые
     клиенты получают `401 unauthorized`; при включённом API сервер перезапускается
     сразу, при выключенном новый токен просто ждёт включения.
   - **«Забыть токен»** удаляет запись из хранилища и останавливает сервер; следующий
     запуск создаст новый — все прежние клиенты получат `401 unauthorized`.
   - **Перевыпуск при включённом API сразу перезапускает сервер** с новым токеном;
     при выключенном — токен просто сохраняется до включения.
   - **Проверка в Rust** идёт по сырому токену из хранилища (сравнение постоянного
     времени `constant_time_equal`, локальная копия из `cloud_oauth_callback.rs`):
     сервер получает токен от JS в `external_api_start` и держит его только в памяти.
     Ни хеш, ни сам токен в `state.json` не попадают, поэтому «утечка через резервную
     копию» исключена.
   - **Хранилище недоступно** — сервер не стартует вовсе (подставлять предсказуемое
     значение нельзя); в настройках показывается ошибка. Повреждённая запись
     (не 64 hex) лечится перевыпуском.
7. **Никаких секретов.** API не отдаёт и не принимает контакты, пароли, куки,
   токены GameCenter, облачные ключи. Нет команд `factory_reset`, восстановления
   из копии, экспорта контактов, `transfer/promo/shop` (действия на сайте).
8. **Права по группам.** Три галочки в настройках: «Чтение», «Изменение статов и
   проходок», «Запуск и закрытие окон». Запрос без права — `403 forbidden_scope`.
9. **Лимиты.** Заголовки ≤ 16 КиБ, тело ≤ 64 КиБ, время чтения ≤ 5 с, ответа JS ≤ 15 с
   (у заданий — опрос), не более 60 запросов в минуту, один активный job запуска.
10. **Журнал.** Последние 100 вызовов (время, метод, путь, код, длительность — без тел
    и токенов) видны на странице и в настройках; запуски дополнительно пишутся в
    существующую историю запусков (`launchLog.js`).
11. **Тестовая сборка.** `external_api_start` работает и в сборках с фичами
    `acceptance` и `acceptance-shared` — иначе контракт нельзя проверить на живой
    сборке. От случайного конфликта с рабочей копией защищают:
    - **порт по умолчанию** `47832` вместо `47831` (`ACCEPTANCE_DEFAULT_PORT`);
      подставляется, если JS прислал умолчание стабильной сборки, явно выбранный
      порт не меняется;
    - **свой токен**: хранилище ОС использует `profile::VAULT_SERVICE`, который
      различается по профилю (`com.tvinoferma.desktop` и
      `com.tvinoferma.desktop.acceptance`);
    - **пометка в панели** настроек и в `application/status` (поле `profile`),
      плюс `GET /health` → `app.build: "acceptance"`.

    Тестовая и рабочая копии могут работать одновременно: они слушают разные порты.

Чего эта схема **не** обещает: защиту от вредоносной программы, запущенной под тем же
пользователем (она может прочитать токен из памяти или нажать те же кнопки). Это
локальный инструмент, а не граница безопасности.

## 6. Страничка

`GET /` отдаёт статическую страницу (`web/index.html`, `web/app.css`, `web/app.js` из
`src-tauri/src/external_api/`, вшитые через `include_str!`), стили — в духе приложения
(тёмная тема, те же токены). Страница — **консоль, а не только справочник**: на ней можно
и менять данные, и запускать окна. Справка вынесена в отдельные адреса: `GET /docs` —
справочник методов, `GET /recipes` — каталог примеров. Rust отдаёт на этих путях ту же
оболочку, а `app.js` по адресу выбирает раздел, поэтому:

- ссылку `/docs#m-characters-list-characters` можно вставить в задачу, чат или
  `AGENTS.md` — она открывается ровно на карточке метода (то же для рецептов:
  `/recipes#rp-export-csv`);
- кнопка «назад» и «открыть в новой вкладке» работают, а адрес можно скопировать —
  ссылка в навигации настоящие `<a href>`, но переход делает JS через
  `history.pushState`: токен, загруженные списки и полученные ответы не теряются;
- поиск, фильтры и оглавление живут в **липкой колонке слева** (`.xapi-rail`), карточки —
  справа; на узком экране (≤ 1040px) колонка становится обычной полосой над списком, а не
  съезжающим блоком;
- у карточек есть кнопка «🔗 ссылка»: она копирует адрес **своей** страницы
  (`pageUrl()`), а не текущий путь — ссылку на метод копруют и с консоли. Но права у страницы ровно те же, что у внешнего
клиента: она ходит в тот же `127.0.0.1` с тем же токеном, поэтому без включённого права
«запуск и закрытие окон» кнопка «Запустить персонажа» получит `403 forbidden_scope` —
как и ваша программа. Ничего своего страница не выдумывает: карточки действий строятся
по каталогу `web/actions.js`, и соответствие маршрутам проверяет
`tests/externalApiActions.test.js`.

Что на странице:

- поле «Токен» (хранится только в `sessionStorage` вкладки), кнопки «Подключиться»
  и «Забыть токен»;
- чипы статуса из `GET /health`: сервер и версия, порт, включённые права,
  доступна ли запись (`storage.writable`);
- карточки персонажей (класс, уровень, небо, пати, статы и проходки, окно, вход),
  пати с составом в сохранённом порядке, список окон игры с PID; сама страница
  просит `GET /characters?full=true`: список по умолчанию статов не отдаёт, а
  панель их показывает;
- оглавление в липкой колонке — ссылкой на каждый метод, а не только на группу (у
  рецептов — на каждый рецепт и раздел: `#rp-…`, `#rg-…`); фильтр скрывает и ссылки,
  чтобы список не обещал то, чего на экране уже нет; якорь `#m-<группа>-<метод>` —
  прямая ссылка на метод (её даёт кнопка «🔗 ссылка» в карточке), поэтому на метод можно
  сослаться из задачи или `AGENTS.md`. Подсветка якоря пережидаёт перерисовку карточек:
  подключение (в карточки подставляются живые id) не «съедает» то место, ради которого
  человек переходил;
- панель выполнения в каждой карточке справочника и в каждом рецепте: строка запроса
  (её можно поправить), чипы параметров, «▶ Выполнить» и ответ прямо под кнопками —
  с кодом, длительностью и размером. Чип вставляет параметр со значением
  (`full=true`, `party=<первая пати>`), чтобы запрос из карточки был рабочим сразу,
  а не `?party=` с пустотой (в рецептах чипы берутся из справочника по совпадению метода
  и пути — тот же запрос, те же параметры). Id в строках — настоящие, из загруженных списков:
  `/characters/{id}` подставит первого персонажа, `/jobs/{jobId}` — id задания,
  которое страница только что увидела в ответе (пока его нет, запрос не отправляется,
  а объясняется: id из примера дал бы `404`). Изменяющий метод требует второго
  нажатия, а запрос, который заведомо не пройдёт (нет токена, выключено право),
  страница называет до подтверждения — впустую щёлкать не за чем;
- ответ рецепта сверяется с примером из документации: под ответом либо «форма ответа
  совпала с примером», либо список полей: которых не хватает / которые добавились.
  Это проверка самих `web/recipes.js` и `docs/EXTERNAL-API-EXAMPLES.md`: устаревший
  пример виден сразу, а не после «а почему у меня нет этого поля»;
- фильтры «Справочника» и «Рецептов»: поиск по тексту, «только чтение», «только
  доступные моим правам» (последние два включаются, когда токен подключён), счётчик
  «показано N из M» и внятная фраза, когда под фильтр не попало ничего; недоступные
  методы подсвечиваются, а не молча отдают `403`;
- журнал последних 100 вызовов: время, метод, путь, код, длительность
  (`GET /api/v1/audit`), кнопки «Обновить» / «Только журнал»;
- готовые примеры **curl, Python и PowerShell** с подставленным адресом и, если токен
  введён, с токеном; кнопка «Скопировать пример».

Токен в HTML **не вшивается** — страница по адресу `127.0.0.1` ничем не отличается от
любой другой вкладки браузера. Поэтому она собирается из отдельных файлов и отдаётся
с CSP

```
default-src 'none'; script-src 'self'; style-src 'self'; connect-src 'self'; img-src 'self' data:;
```

— без `unsafe-inline`, чтобы даже случайно вставленный в HTML текст не стал скриптом.
Собирать её отдельным Vite-входом не нужно: файлы маленькие, читаются при старте
сервера и отдаются из памяти (обновление — вместе с приложением).

Макет страницы (без реальных запросов, на вымышленных данных — удобно смотреть
разметку и правку статов, не поднимая приложение) — `demo/external-api/`, запуск:
`DEMO_ENTRY=/demo/external-api/index.html npm run demo`.

Страницу можно открыть и с настоящим API-мостом, не собирая Rust:
`node demo/serve-api-page.mjs` раздаёт те же файлы из `src-tauri/src/external_api/web/`
и гоняет `/api/v1/*` через `js/modules/externalApi/bridge.js` поверх демонстрационного
состояния. Ответы, права и ошибки тогда — приложенческие; не работает только то, для
чего нужны окна игры (`GET /windows` пуст, запуск завершается ошибкой).

## 7. Настройки в приложении

Вкладка **«🔌 Внешний API»** (`#settings-api`) — отдельная группа в меню настроек,
между «Приложением» и «Синхронизацией». Внутри — одна сворачиваемая панель
`#settings-external-api`; всё, что ниже, уже реализовано.

- **Главный переключатель** `externalApi.enabled` — «Разрешить внешним программам
  управлять Твинофермой». По умолчанию выключен; включение сразу запускает сервер
  (и впервые создаёт токен), выключение — останавливает и освобождает порт.
- **Права** (`#external-api-permissions`), три галочки:

  | Настройка | По умолчанию | Что открывает |
  | --- | --- | --- |
  | `externalApi.allowRead` | включено | `GET /health`, `/characters`, `/parties`, `/windows`, `/jobs/{id}`, `/audit` |
  | `externalApi.allowModify` | выключено | `PATCH /characters/{id}`, `POST /characters/bulk-update` |
  | `externalApi.allowLaunchClose` | выключено | `POST /launch/*`, `/windows/close`, `/app/show` |

  Снятая галочка даёт `403 forbidden_scope` и в Rust, и в JS-мосте. Значения по
  умолчанию: только чтение — включение сервера не даёт права что-то менять.
- **Порт** `externalApi.port` — число 1024–65535, по умолчанию 47831; занятый порт
  показывается в статусе, сервер не падает.
- **Статус** `#external-api-status`: «работает на порту N», «остановлен», «порт занят»,
  «в браузере сервер не запускается»; отдельной строкой — включённые права и
  `clientReady === false` → «главное окно ещё не подключилось» (`503 app_not_ready`).
- **Кнопки**: `#external-api-open` «Открыть страницу API» (в приложении — через
  `plugin-shell`, в браузере — новая вкладка) и `#external-api-copy-curl` — пример
  `curl -s -H "Authorization: Bearer $TF_API_TOKEN" http://127.0.0.1:<порт>/api/v1/health`.

  Адрес берётся **по фактическому порту работающего сервера** (поле `port` в
  `external_api_status`), а не из поля настроек: в тестовой сборке Rust
  подставляет `47832`, пока в настройках остаётся `47831`. Если сервер не
  запущен, используется сохранённый порт; если порт в настройках ещё не применён
  (сервер слушает старый), кнопка ведёт туда, где сервер реально слушает. Правило
  то же, что в Rust (`port_for_profile`): умолчание `47831` в тестовом профиле
  заменяется на `47832`, явно выбранный порт остаётся как есть. Проверка —
  `tests/externalApiAcceptanceProfile.test.js`.
- **Токен** `#external-api-token-copy` «Скопировать токен», `#external-api-token-show`
  «Показать токен», `#external-api-rotate` «Перевыпустить», `#external-api-forget`
  «Удалить», строка `#external-api-token-status` («создан 24.11.2026, 12:00»).
  Копирование и показ **читают хранилище, ничего не меняя** (`currentToken` →
  `peekToken`), поэтому значение можно забрать в любой момент и не платить за это
  `401` у уже настроенных программ. Показ — по явной кнопке и на минуту:
  `#external-api-token-reveal` / `#external-api-token-value` гаснут сами, значение
  не остаётся в разметке окна. После «Перевыпустить» блок показывает новое значение
  с подписью «сохраните его сейчас» — старый тем временем перестаёт работать; см. §5.6.
- **Журнал** `#external-api-audit` (последние 100 вызовов: `HH:MM:SS  METHOD  путь →
  код  (мс)`), кнопки `#external-api-audit-refresh` и `#external-api-audit-clear`
  (очистка и в Rust, и в памяти вкладки).

Чего в панели **нет** намеренно: кнопки «открыть порт наружу», настроек CORS и
времени жизни заданий — это не параметры, а решения контракта (§5). Сохранённый
токен, наоборот, **показан по-человечески**: прятать значение, которое человек и так
хранит в хранилище своей учётной записи, — значит заставлять его перевыпускать
токен и ронять своих клиентов. Показ поэтому читает, но не создаёт и не меняет
(`tests/externalApiToken.test.js`), и выключается сам.

Где что лежит:

- разметка — `index.html`, группа `#settings-api`;
- логика панели — `js/settings/externalApiPanel.js` (`bindExternalApiPanel`),
  подключается из `js/settings/settings.js` вместе с остальными панелями;
- реакция на смену настроек — общий обработчик `[data-setting]` в `js/settings/settings.js`:
  любое изменение `externalApi.*` вызывает `syncExternalApi()`;
- запуск при старте — `js/main.js` после `initNotifications()` (`attachExternalApi()`);
- запуск/остановка и токен — `js/modules/externalApi/index.js`;
- справка внутри приложения — раздел «Внешний API» в `js/settings/guideData.js`
  (id `external-api`, категория `scripts`, связан с «Синхронизацией»
  и «Настройкой браузера»).

Структурные требования, которые проверяются тестами (`npm test`):

- группа настроек обязана быть в `DEFAULT_SETTINGS` (`js/core/constants.js`) и явной
  строкой в `mergeSettings` (`js/core/state/settings.js`) — иначе
  `tests/stateSettings.test.js` поймает «настройка молча не сохраняется»;
- `tests/settingsLayout.test.js` знает группу `api` с панелью `settings-external-api`,
  статусом и журналом: переименование id ломает навигацию по настройкам;
- `tests/settingsGuides.test.js` проверяет, что справка ссылается на существующие
  панели и соседние разделы.

### M3. Запуск и закрытие окон — сделано

- **Задания живут в JS, отдельного `jobs.rs` нет.** Причины: результат задания —
  это результат `launchGroup`, который считается в JS; дублировать прогресс и
  `cancelled` в Rust значило бы завести вторую правду. Реестр —
  `JobRegistry` в `js/modules/externalApi/actions/launch.js`, единственный экземпляр
  на приложение (`globalThis.__tfExternalApiJobs`), TTL 30 минут, не более 50 заданий,
  одно активное. Перезапуск приложения задания теряет — окна уже не откроются «сами»,
  и честнее об этом сказать `404 not_found`, чем показывать вечный `running`.
- JS: `launchCharacterJob` (`launchOne` через `launchGroup`), `launchPartyJob`
  (`launchGroup` + состав пати в сохранённом порядке), `launchSummary` и `publicJob`
  — единая форма прогресса и итога, `closeClientsByPid` для закрытия окон;
- **важно**: `launchGroup` при `interactive: false` не показывает экран проверок, но
  возвращает `results` — оттуда берутся `ok`, `error`, `cancelled`. Пропущенные
  (`noGc`, `noSavedLogin`, `alreadyRunning`) пересчитываются тем же `runPreflight`
  **до** запуска, по тому же списку и тому же `ctx` GameCenter. Своего кода проверки
  в API нет — иначе он разошёлся бы с кнопкой в интерфейсе;
- `runPreflight` и `launchContextForGroup` экспортированы из `partyLaunch.js`;
  `preflight.js launchPreflight` для API не используется;
- закрытие окон: только PID из `GET /windows` и только с `{"confirm": true}`;

### Приёмочный чек-лист (ручная проверка на Windows)

1. API выключен: порт не слушается, `connection refused`.
2. Включили: `GET /health` без токена → `401`; с токеном → `ok`.
3. `Host: evil.example` → `403 forbidden_host`.
4. `PATCH` статов: числа изменились в карточке, в истории появился снимок «было → стало».
5. Остановленное сохранение (`Сохранение остановлено`) → `423`, данные не изменились.
6. Запуск одного персонажа без запомненного входа → задание `done`, строка `skipped`.
7. Запуск пати из 3 человек → 3 окна, порядок как в карточке пати. То же через CLI
   (`npm run tf -- launch-party <partyId> --yes --wait`) обязано дать тот же итог:
   раньше задание умирало на `launch is not a function`, и проверяли это только
   тесты с подменённым лаунчером.
8. Второй запуск во время первого → `429`, первый не ломается.
9. Закрытие окон без `confirm` → `400`, с `confirm` → окна закрыты.
10. Свернуть приложение в трей → API продолжает работать; выйти из трея →
    `connection refused`.
11. `npm run check` и `cargo test/clippy/fmt` на CI — зелёные (кроме известных
    старых замечаний).

`Cargo.lock` на машине с Rust.

## 10. Решения, которые вы приняли

| № | Вопрос | Решение |
| --- | --- | --- |
| 1 | Кто будет вызывать API: Python, PowerShell, AHK, Excel, свой сайт? | **любой клиент**: универсальный JSON API, примеры Python, PowerShell и curl на странице `/` |
| 2 | Нужен ли запуск по расписанию (планировщик Windows дёргает API)? | да, job-модель это позволяет: `POST` → `202 jobId`, результат — опросом |
| 3 | Токен показывать один раз (хеш) или хранить в Credential Manager? | **хранить в хранилище ОС** (Credential Manager); значение можно скопировать или показать снова — перевыпуск нужен только при утечке (§5.6) |
| 4 | Разрешать закрытие окон через API? | да, но только с `{"confirm": true}` и правом «Запуск и закрытие окон» |
| 5 | Нужно ли массовое изменение статов/проходок? | да, до 100 персонажей за запрос |
| 6 | Порт `47831` подходит? | да; поле в настройках, 1024–65535 |
| 7 | Нужна ли страничка внутри приложения или достаточно браузера? | **отдельная вкладка** «🔌 Внешний API» в настройках; сама страница API — обычная вкладка браузера по `127.0.0.1` |
| 8 | Отдавать ли марафоны целиком (прогресс, задания, награды)? | да, с `totals` из модели интерфейса; папки-серии — отдельными записями без заданий |
| 9 | Как менять прогресс марафона извне? | двумя явными вызовами: `marks` (отметка дня) и `adjust` (абсолютная поправка); правка прогресса «мимо» этих полей не принимается |
| 10 | Выгрузки: отдельный формат или просто JSON? | и то и другое: `/export/{набор}.{csv\|json}`; CSV с `;` и BOM, файл отдаётся `Content-Disposition` |
| 11 | Запускать можно только пати? | нет: `POST /launch/selection` — выбранные персонажи из разных пати, до 100, порядок сохраняется |
| 12 | Создавать персонажей через API? | да, `POST /characters`; удаление — нет (только архив в интерфейсе) |

## 11.1. Быстрые рецепты для твин-фермы

Полная база примеров — `docs/EXTERNAL-API-EXAMPLES.md`: там каждый сценарий
разобран целиком (запрос → ответ → объяснение → ошибки), а на странице API есть
вкладка «Рецепты» с тем же набором. Каталог примеров один
(`src-tauri/src/external_api/web/recipes.js`), документ и страница собираются из
него, поэтому разойтись не могут; проверка — `tests/externalApiRecipes.test.js`.

Все примеры — с токеном из §5.6; порт по умолчанию `47831`.

```bash
# 1. Кто есть и кто уже запущен (одним взглядом)
curl -s -H "Authorization: Bearer $TF_API_TOKEN" http://127.0.0.1:47831/api/v1/characters \
  | python -c "import json,sys; [print(c['nick'], c['level'], 'запущен' if c['running'] else '—') for c in json.load(sys.stdin)['characters']]"

# 2. Выгрузить всех персонажей в Excel-совместимый CSV
curl -s -H "Authorization: Bearer $TF_API_TOKEN" -OJ http://127.0.0.1:47831/api/v1/export/characters.csv

# 3. Поставить проходки двум выбранным
curl -s -X PATCH -H "Authorization: Bearer $TF_API_TOKEN" -H "Content-Type: application/json" \
  -d '{"weapon": 5, "armor": 5}' http://127.0.0.1:47831/api/v1/dungeon-passes/Mag_1

# 4. Запустить выбранных в нужном порядке
curl -s -X POST -H "Authorization: Bearer $TF_API_TOKEN" -H "Content-Type: application/json" \
  -d '{"characterIds": ["Mag_1", "Luchnik_2", "Zhrets_3"]}' \
  http://127.0.0.1:47831/api/v1/launch/selection

# 5. Отметить день в марафоне и поправить счётчик
curl -s -X POST -H "Authorization: Bearer $TF_API_TOKEN" -H "Content-Type: application/json" \
  -d '{"characterId": "Mag_1", "taskId": "t1", "date": "2026-11-24"}' \
  http://127.0.0.1:47831/api/v1/marathons/m1/marks
```

```powershell
# PowerShell: выгрузка марафонов в файл рядом со скриптом
$t = $env:TF_API_TOKEN
Invoke-WebRequest -Headers @{ Authorization = "Bearer $t" } `
  -Uri http://127.0.0.1:47831/api/v1/export/marathons.csv -OutFile .\marathons.csv
```

## 12. Чего в этом API не будет

- записи значений **в игру** и чтения игровой памяти;
- кликов, ввода и любых действий в игровом клиенте;
- действий на сайте (`promo`, `transfer`, `shop`, `caravan`) — только ручные кнопки
  в приложении (см. `docs/COMPLIANCE.md`);
- доступа к контактам, паролям, кукам и токенам GameCenter;
- удаления персонажей, восстановления копий, полного сброса;
- работы по сети: только `127.0.0.1` на том же компьютере.
