# Релиз на GitHub и проверка автообновления

Как это устроено: при пуше тега `vX.Y.Z` GitHub Actions (`.github/workflows/release.yml`)
собирает на Windows установщики `.msi` и `-setup.exe`, подписывает файлы обновления вашим ключом
и создаёт **черновик** релиза с `latest.json`. Установленное приложение при запуске (или по кнопке
«Проверить обновления») читает
`https://github.com/drednight/Tvinoferma/releases/latest/download/latest.json`, сравнивает версию
и, если она новее, скачивает и ставит обновление. Подпись проверяется публичным ключом из
`src-tauri/tauri.conf.json`.

Требования: репозиторий **публичный** (иначе приложение не скачает `latest.json`), на вкладке
**Actions** разрешён запуск workflow.

## Шаг 1. Ключ подписи (один раз)

В PowerShell в папке проекта:

```powershell
npm run tauri signer generate -- -w "$HOME\.tauri\tvinoferma.key"
```

Команда спросит пароль (запомните его) и создаст два файла:

- `tvinoferma.key` — приватный ключ. **Никому не отдавать, в репозиторий не класть, сделать копию.**
  Если его потерять, уже установленные копии больше не смогут обновиться.
- `tvinoferma.key.pub` — публичный ключ.

## Шаг 2. Публичный ключ в приложение

Откройте `tvinoferma.key.pub` блокнотом, скопируйте всю строку и вставьте в
`src-tauri/tauri.conf.json` → `plugins.updater.pubkey` вместо `ЗАМЕНИТЕ_НА_ПУБЛИЧНЫЙ_КЛЮЧ…`.

## Шаг 3. Секреты GitHub

Репозиторий → **Settings → Secrets and variables → Actions → New repository secret**:

| Имя | Значение |
| --- | --- |
| `TAURI_SIGNING_PRIVATE_KEY` | всё содержимое файла `tvinoferma.key` |
| `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` | пароль из шага 1 |

## Шаг 4. Первый релиз (v0.2.0)

```powershell
npm run version:bump 0.2.0
git add -A
git commit -m "Версия 0.2.0"
git push
git tag v0.2.0
git push origin v0.2.0
```

`version:bump` меняет версию сразу в `package.json`, `src-tauri/tauri.conf.json`,
`src-tauri/Cargo.toml` и `Cargo.lock`. Версия в теге должна совпадать с версией в файлах.

Дальше:

1. GitHub → **Actions** → workflow **Release** — дождитесь зелёной галочки (~10–15 минут).
   Если красный крестик — откройте шаг с ошибкой; чаще всего это неверные секреты.
2. GitHub → **Releases** → черновик «Твиноферма v0.2.0». Проверьте, что в **Assets** есть
   `…_x64_en-US.msi`, `…_x64-setup.exe`, файлы `.sig` и `latest.json`.
3. Нажмите **Edit → Publish release**. Пока релиз черновик, приложение его не видит.
4. Скачайте `…-setup.exe` (или `.msi`) из релиза и установите **вручную**: версии, собранные до
   появления ключа, обновиться сами не могут. Данные не потеряются — они лежат в
   `%APPDATA%\com.tvinoferma.desktop` и в диспетчере учётных данных Windows.
5. В приложении: **Настройки → Обновления** — там должна быть «Версия 0.2.0».
   Кнопка «Проверить обновления» должна ответить «Установлена последняя версия».

## Шаг 5. Проверка автообновления (v0.2.1)

1. Сделайте любое маленькое изменение (или никакого) и выпустите следующую версию:

   ```powershell
   npm run version:bump 0.2.1
   git commit -am "Версия 0.2.1"
   git push
   git tag v0.2.1
   git push origin v0.2.1
   ```

2. Дождитесь сборки в **Actions** и опубликуйте черновик v0.2.1 в **Releases**.
3. Запустите установленную v0.2.0 → **Настройки → Обновления → Проверить обновления**.
   Должно появиться «Доступна версия 0.2.1 (сейчас 0.2.0)» → «Да» → загрузка → установка →
   приложение перезапустится. В настройках теперь «Версия 0.2.1».
4. Если включено «Проверять при запуске», то же самое предложение появится просто при старте.

## Если что-то не так

| Симптом | Причина |
| --- | --- |
| «Не удалось проверить обновления … signature» | pubkey в `tauri.conf.json` не от того ключа, которым подписан релиз |
| «… 404» / ничего не находит | релиз ещё черновик, репозиторий приватный или в релизе нет `latest.json` |
| Сборка падает на шаге tauri-action | нет секретов или неверный пароль ключа |
| Версия не та | забыли `npm run version:bump` перед тегом — удалите тег (`git push --delete origin vX.Y.Z`) и повторите |
