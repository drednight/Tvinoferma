# Контакты, выбор предметов и сроки куки: проверка Windows

Это план ручной приёмки, **не подтверждение работы на настоящем пользовательском ПК**.
Автотесты используют синтетические контакты и ответы сайта. Выпуск не создаётся.

## Разные контакты в файле и Windows

1. На отдельной тестовой учётной записи Windows сохранить различающиеся синтетические
   контакты в файле и защищённой записи. Закрыть другие копии приложения.
2. Запустить приложение: сохранение остановлено, в баннере есть «Сравнить контакты и
   выбрать источник». Автоматического выбора, удаления или перезаписи нет.
3. Проверить свёрнутый список отличающихся персонажей и полей в баннере.
   Открыть сравнение: значения скрыты, отличаются выделенные строки. Показать значения
   отдельной галочкой. Проверить активных и архивных персонажей, включая намеренно пустое поле.
4. Отмена ничего не меняет. Без отдельного подтверждения кнопка применения недоступна.
5. Выбрать Windows только если именно эта версия нужна. Приложение повторно сверяет файл и
   прочитанные записи, создаёт проверенную точную копию исходного файла и заменяет только
   конфликтующие открытые контакты ссылкой на Windows. Включается защищённое хранение.
   Остальные данные, ID, очереди, ключи шифрования и привязки дисков сохраняются.
6. Проверить копию `state.backup-pre-contacts-windows-choice-*.json`. Она сохраняет старые
   контакты из файла и **может содержать пароли**: не публиковать и хранить безопасно.
   Это не копия защищённого хранилища Windows.
7. До повторной загрузки обычное сохранение заблокировано. Нажать «Перезапустить», сверить
   выбранные контакты, затем сохранить и повторно запустить приложение.
8. Изменение файла/записи во время выбора, отказ копирования или потерянный ответ команды
   должны остановить операцию без автоматического повтора. При неизвестном результате
   проверять файл и копию: ошибка не доказывает, что замены файла не было.

### Выбор контактов файла

1. В том же окне выбрать «Из файла → защищённое хранилище Windows». Согласие должно
   сброситься. Без нового явного согласия записей нет.
2. Перед заменой проверяется неизменность файла и всех прочитанных записей Windows,
   создаётся `state.backup-pre-contacts-file-choice-*.json`.
3. Прежние контакты Windows копируются под новые случайные ключи `recovery-<uuid>-<n>`
   в том же защищённом хранилище. Запись `recovery-<uuid>-manifest` содержит соответствие
   исходных и резервных ключей, без копирования значений в открытый файл или журнал.
   Копии перечитываются до изменения исходных записей.
4. Только после проверки копий выбранные контакты записываются в Windows и перечитываются,
   затем файл заменяется по проверке исходного содержимого. Защищённое хранение включено.
   Для миграции ID проверяются оба ключа; намеренно пустые контакты не восстанавливаются из старой записи.
5. Убедиться, что после перезапуска конфликт исчез, выбранные контакты доступны,
   архивные персонажи и не затронутые записи сохранены. Обычное сохранение работает
   только после успешной повторной загрузки.
6. При сбое/потере ответа не повторять операцию автоматически. Копии сохраняются;
   перезапустить и сравнить источники. Записать только безопасный код защищённой копии,
   если он показан. Значения паролей, исходные файлы и записи хранилища не публиковать.

Выбор Windows не меняет записи хранилища. Выбор файла не удаляет прежнюю версию Windows:
она остаётся в защищённых резервных записях. Автоматической очистки этих копий нет.
Межпроцессной транзакции между файлом и Windows нет: проверки не заменяют закрытие других
экземпляров приложения. Тесты имитируют IPC; этот сценарий необходимо принять на Windows.

## Передача и сундуки

- В свежем «Что будет передано» пять одинаковых наборов ×50 занимают одну строку.
  Выбор 2 наборов означает 100 предметов, не разделение одного набора.
  Остальные три остаются на сайте. Иное количество внутри набора — отдельная строка; разные категории и сроки объединены.
  При выборе части берутся ближайшие известные сроки, затем неизвестные. Проверить кнопку
  «Все», общие «Поставить всё» / «Снять всё», поиск без изменения выбора. Детализация раскрывается только при разных сроках.
- Сервер для всех применяется также неотмеченным персонажам. Если нет подтверждённого
  получателя на выбранном сервере, такой персонаж не передаёт предметы и не переключается на другой сервер.
- Проверить 0, допустимый максимум, дробное, отрицательное, пустое и превышающее максимум
  значения. Некорректное количество блокирует отправку до исправления/повторной проверки.
- Четыре и более позиций размещаются в две колонки, девять и более — в три на широком окне;
  небольшие списки занимают всю ширину. Выбирается целое число наборов (шаг 1), рядом — общее число предметов.
- Подтверждение необратимости, обход фильтра серверов и сброс ограничений — только в маленьком
  окне после «Передать». По умолчанию оба флажка сняты; отмена/закрытие не отправляют предметы.
  Подтверждённый план фиксируется до резервной копии; реальная отправка проверяет сайт заново.
- После изменения сайта между просмотром и отправкой прежний выбор должен быть отклонён.
- В начальном плане караванщика — персонаж и сундуки. До чтения сайта показано «Не проверено»,
  а не ноль; тот же план сохраняется при подсчёте, открытии и результате, ячейки обновляются на месте. Инвентарь общий на аккаунт.
- Пустая корзина распознаётся по сохранённым заголовку и тексту сайта; неизвестная страница не считается нулём.
  После подсчёта справа в той же таблице — количество для открытия и кнопка «Открыть найденные сундуки»
  внизу. При нуле реального запуска нет; один общий аккаунт открывается один раз.
- Карточка промокода: название, новость, срок, сервер, свёрнутый список содержимого;
  действия 🌐 → растянутая «Добавить промокод» → скрытие. Под сроком — дни включительно по Москве либо истёкший срок.
  Истёкшие скрываются автоматически; «Вернуть скрытые промокоды» оставляет их видимыми,
  в том числе после перезапуска, пока не поменялся срок. Ручное скрытие сохраняется.
  Краткая дата без года относится к текущему году по Москве. При явном переходе года
  (разница месяцев больше полугода) выбирается соседний год: в ноябре 05.01 — следующий январь,
  04.10 и 25.10 — истёкший октябрь текущего года. Явно указанный год не меняется.
  Истёкший срок — красный; 1–3 дня включительно — жёлтое «Скоро истечет»; более 3 — зелёный.

## Активация подарков

- Слева «Обновить цены и балансы» читает все аккаунты, включая доступные лимиты.
- Над таблицей «Обновить цены и баланс» читает только отмеченных персонажей; без выбора
  предлагает отметить их, а не запускает всех. Представитель общего аккаунта берётся из отметок.
  Баланс и лимиты общие для членов того же аккаунта; чужие результаты проверки сохраняются.
- Рядом с пробным запуском «Лимиты и сроки»: все персонажи × все предметы, общий лимит
  аккаунта и подтверждённые даты обновления. Отсутствующие данные/даты не выдумываются; открытие ничего не покупает.
- Во всех планах, результатах и подробных отчётах перед ником — класс персонажа.

## Банк куки

- Интерфейс временно скрыт у всех; при открытии настроек метаданные банка не запрашиваются.
- Хранилище куки, ключи, сроки и привязки не удаляются и не сбрасываются.

## Слияние дублирующихся карточек с контактами Windows

Проверять только с тестовыми контактами и закрытыми другими экземплярами приложения:
межпроцессной транзакции нет. Обычная копия состояния сама по себе не содержит vault.

1. Создать две карточки-кандидата с одинаковой почтой / логином: у одной заполнить пароль,
   у другой — телефон и другой пароль. Одинаковый ник без совпадающего непустого логина
   не должен давать кандидата. В «Проверить дубли» выбрать основную карточку и источник пароля.
   Значения контактов в выборе конфликта не выводятся. Отмена не меняет карточки.
2. Подтвердить слияние. До изменения контактов создаётся проверенная копия файла состояния
   `state.backup-…-dup-<код>-….json` и две отдельные копии исходных записей в хранилище ОС.
   Их содержимое сверяется чтением. После этого хранилище проверяется ещё раз, а запись
   файла выполняется только если он всё ещё совпадает с исходным.
3. Проверить объединённые данные, выбранный пароль, ссылки и перезапуск. Сохранённые входы
   и профили браузера не объединяются; у удаляемой карточки не должно быть привязки запуска.
4. В настройках в списке копий нажать «Исходные контакты» рядом с копией до слияния.
   Значения скрыты до отдельной галочки. Исходные контакты двух карточек доступны только
   на этом ПК в том же хранилище ОС; не публикуйте их. Копия состояния и копии контактов
   не являются независимой копией на другом носителе. Обычная ротация не удаляет эту копию
   состояния, но пользователь может удалить её вручную; имя содержит код для поиска контактов.
   Отдельные защищённые записи могут остаться после удаления копии файла и сброса приложения.
5. При сбое или потере ответа не повторять слияние вслепую: файл и записи ОС могли измениться
   частично. Копии из пункта 2 остаются; восстановление файла через настройки не возвращает
   исходные контакты автоматически. Сравнить «Исходные контакты» и вручную внести нужные
   поля в восстановленные карточки. Если сбой до создания проверенных копий — исходные записи
   слиянием не меняются. Проверить отказы копирования, потерю ответа и изменение файла/контактов.
6. Проверить активные и архивные карточки, пустые записи, отключённый/недоступный vault,
   конфликт значений, недоступность резервной копии и попытки сохранения во время операции.

Сверка и копирование не защищают от параллельных внешних изменений между IPC-вызовами или
от повреждения/потери хранилища ОС и не гарантируют устойчивость к отключению питания.
Необходимо отдельно проверить реальный Windows Credential Manager и сборку Windows.

### Отметка возможного прерывания защищённого слияния

Перед изменением контактов и состояния приложение создаёт и перечитывает отметку с именем
копии в локальном профиле WebView (без контактов). После подтверждённого сохранения она
удаляется. При обнаружении отметки после запуска сохранение остановлено: кнопка в предупреждении
позволяет проверить копию состояния и открыть исходные контакты. Операция могла завершиться и
полностью; отметка не устанавливает её исход. Проверка формата не доказывает подлинность,
полноту или согласованность vault и state. При необходимости файл восстанавливается отдельно
в настройках, а контакты сравниваются и переносятся вручную. Продолжение разрешается только
после осознанного подтверждения и перезапуска; само подтверждение ничего не восстанавливает.

Это **вспомогательная отметка**, а не устойчивый журнал транзакций: запись WebView не является
fsync, может потеряться при сбое питания, повреждении или очистке профиля, а другой процесс не
заблокирован. Отсутствие отметки не доказывает, что слияние завершилось. При недоступной или
повреждённой отметке сохранение остановлено; не очищайте профиль и не удаляйте копии, пока не
сохраните их и не выясните состояние данных. Необходимы ручные проверки на Windows с отключением
приложения на разных этапах и независимая защищённая копия контактов вне хранилища ОС.

### Независимый зашифрованный файл текущих контактов

В «Настройки → Данные и безопасность → Локальные копии состояния» доступны отдельные
кнопки создания и открытия защищённого файла контактов. В файл входят только почта/логин,
пароль, резервная почта и телефон активных и архивных карточек, их ID и ник. Удалённые
персонажи и отдельные исторические копии до слияния, входы GameCenter, сессии, профили,
настройки, другие данные и другие записи Credential Manager не входят. При недоступном
или изменившемся vault подготовка останавливается; закройте другие копии приложения.

Для каждого файла создаётся новый случайный ключ. Ключ и файл нужно сохранить **в разных
надёжных местах**: без ключа расшифровать файл невозможно, обладатель ключа и файла сможет
прочитать все контакты. Приложение не сохраняет ключ и не отправляет его автоматически.
AES-256-GCM проверяет целостность файла при расшифровке, но не доказывает актуальность и
авторство: обладатель ключа может создать другой файл. Проверка в памяти не доказывает,
что файл записан на носитель. Откройте сохранённую копию отдельной кнопкой, проверьте
содержимое и наличие ключа. Открытие только для просмотра и ручного переноса, оно не
изменяет приложение или vault. JS не гарантирует очистку секретов из памяти.

Проверка на настоящем Windows/WebView2 и независимом носителе пока не выполнена: вручную
проверить создание, загрузку на другом ПК, неверный ключ, повреждение, архивных персонажей,
недоступный vault, закрытие окна и повторное открытие. Не считать эту функцию полноценной
резервной копией всего приложения или доказательством надёжности синхронизации.
