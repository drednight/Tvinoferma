### 1.4. Противоречия и как я их разрешил

1. **Автоматизация против режима «только чтение».** PDF предлагает гарантию «скрытые окна только читают страницы, ничего не нажимают». Но промокоды и переводы по определению отправляют формы. Решение: два режима скриптов. Скрипты чтения (баланс, марафон, проверка входа) работают по жёсткому правилу «только чтение». Скрипты действий (промокод, перевод) запускаются только по явной команде пользователя, с предпросмотром и подтверждением.
2. **Приоритет автоматизации.** Ваш план ставит её на высокий уровень, PDF советует осторожность из-за правил сайта. Решение: делать, но после проверки правил `pwonline.ru` и только в режиме «действие по нажатию кнопки», без фоновых запусков и расписаний.
3. **Облако.** В коде лежат заглушки `cloud/googleDrive.js` и `googleSheets.js`, в настройках есть раздел `google`, но в вашем плане облака нет. Решение: вынести в отдельный этап 12 с условием «делаем только если нужен перенос между компьютерами», иначе удаляем заглушки.
4. **Заявленная поддержка macOS и Linux.** README и `Cargo.toml` упоминают Keychain и Secret Service, но `docs/RELEASE.md` описывает сборку только установщиков Windows (`.msi`, `-setup.exe`). Решение: либо подтвердить сборки в CI (Этап 13), либо убрать упоминания из README.

## 4. Этап 0. Баги (срочно)

Цель: убрать ошибки, которые портят данные или мешают ежедневной работе. Без этого остальные этапы строятся на неверной базе.

### 0.1. 🔴 Баланс монет: 28,5 превращается в 285 — `баг` · S

**Симптом.** Приложение показывает 285 вместо 28,5.

**Причина (найдена в коде).**
- `src-tauri/src/scripts/balance.js`: значение считывается как `parseInt(strongTag.innerText.trim().replace(/[^0-9]/g, ''), 10)`. Регулярное выражение удаляет **всё, кроме цифр**, в том числе запятую. «28,5» становится «285».
- `src-tauri/src/balance.rs`: данные читаются через `data.as_i64()`, дробные значения не проходят. Нужно `as_f64()`.
- В `state.js` монеты хранятся как `Number(input.ancientCoins) || 0`, то есть дробь модель выдержит.
- Побочный эффект: ошибочные значения могли попасть в `coinHistory`, суммы партий и марафонные «стартовые балансы» (`balance.start`).

**План исправления.**
- [ ] В `balance.js` нормализовать текст: убрать неразрывные пробелы и пробелы-разделители тысяч, заменить запятую на точку, затем `parseFloat`. Допустимые форматы: `285`, `28,5`, `28.5`, `1 285,5`, `1 285`.
- [ ] Определить, как сайт пишет тысячи и дробь. Если возможны оба `1,285` (тысячи) и `28,5` (дробь), нужен явный разбор: сначала узнать реальные примеры с сайта.
- [ ] В `balance.rs` заменить `as_i64()` на `as_f64()`, проверку `v >= 0` оставить, тип поля в ответе сделать числом с плавающей точкой.
- [ ] Хранить монеты с точностью до одного знака, чтобы избежать ошибок вида 28.499999: округлять до 0,1 при записи.
- [ ] В интерфейсе показывать число с одним знаком после запятой и локальным разделителем.
- [ ] Для уже сохранённых данных: пометка «значение могло быть искажено до версии X» либо кнопка «Перепроверить баланс» для выбранных персонажей. Автоматически исправить старые записи нельзя, нельзя отличить 285 от 28,5.
- [ ] Тесты: функция разбора вынесена в отдельный модуль и покрыта на форматах выше. В Rust — тест на дробное значение в ответе.

**Готово, когда:** на тестовом аккаунте с балансом 28,5 приложение показывает 28,5, история и суммы партий считаются верно, тесты проходят.

### 0.2. 🟠 Фильтр по классам не обновляется после добавления персонажа — `баг` · S

**Симптом.** Новый персонаж не попадает в выбранный фильтр сразу, нужно сменить фильтр вручную.

**Гипотеза (в коде не проверено).** После сохранения персонажа в `formEditor.js` не вызывается перерисовка с учётом `state.ui.filters.class`, либо список вариантов фильтра строится один раз при старте.

**План.**
- [ ] Найти место сохранения нового персонажа и вызвать единый `renderCharacters()`, который перечитывает `state.ui.filters`.
- [ ] Список вариантов фильтра (классы, партии, теги) собирать при каждой отрисовке из актуального `state.characters`.
- [ ] Если выбранный фильтр больше не встречается (удалили последнего персонажа класса), сбрасывать его.
- [ ] Тест: добавить персонажа при активном фильтре — он виден сразу, если подходит под фильтр, и не виден, если не подходит.

**Готово, когда:** после добавления, редактирования и удаления список всегда соответствует активным фильтрам без ручных переключений.

### 0.3. 🟠 Описания заданий марафона — `баг/фича` · M

**Цель.** Пользователь видит, что именно нужно сделать в каждом задании, и описание подтягивается с сайта.

**План.**
- [ ] Модель: добавить поле `description` в задание (`marathons/model.js`), поддержать в `migrateMarathon`: для старых данных пустое значение.
- [ ] **Объединение источников в мастере.** Карточки «С сайта» и «Из новости» (шаг 0 мастера, `marathons/wizard.js`) сливаются в один блок «🌐 С сайта» с двумя источниками. «📰 Новость» — основной: в ней название, даты, задания, требования, описания, награды и этапы. «🌐 Страница отметок» — дополнительный: названия заданий и этапов берутся с неё, она же служит проверкой найденного в новости.
