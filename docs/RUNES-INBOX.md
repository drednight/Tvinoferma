# Настройка приёма предложений рун

Форма в приложении отправляет заявки в Google Таблицу через Apps Script. Заявки добавляются на лист `Предложения рун` со статусом `На проверке`; таблица остаётся под вашим Google-аккаунтом.

## Подключение

1. Создайте Google Таблицу и скопируйте её ID из адреса: `https://docs.google.com/spreadsheets/d/ID_ТАБЛИЦЫ/edit`.
2. В таблице откройте **Расширения → Apps Script** и вставьте содержимое файла `scripts/runes-inbox.gs`.
3. В начале скрипта замените `PASTE_GOOGLE_SPREADSHEET_ID_HERE` на ID таблицы и сохраните проект.
4. Нажмите **Развернуть → Новое развертывание**, выберите тип **Веб-приложение**, установите запуск от своего аккаунта и доступ **Все**.
5. Подтвердите разрешения Google и скопируйте URL веб-приложения, который заканчивается на `/exec`.
6. В `js/modules/runes/submit.js` укажите этот URL в `RUNE_SUBMISSION_ENDPOINT`, затем опубликуйте обновлённую сборку приложения.

Приёмник доступен всем пользователям приложения, поэтому не размещайте в таблице или скрипте секретные данные. Скрипт проверяет класс и длину полей (примечание — до 500 символов); введённые значения записываются как текст. Ответ Apps Script нельзя прочитать из приложения из-за ограничений браузера, поэтому проверяйте появление строки в таблице.

## Оформление и проверка заявок

При поступлении каждой новой заявки лист автоматически получает закреплённую тёмно-зелёную шапку, фильтр, чередование строк, перенос длинного текста, формат даты и выпадающий статус. Статусы `На проверке`, `Одобрено` и `Отклонено` подсвечиваются разными цветами. Также создаются уникальный `ID` и готовый JSON-объект для каталога.

Чтобы оформить уже полученные строки и заполнить для них новые ID/JSON, обновите таблицу и выберите **Руны → Обновить оформление и JSON**. Существующие ID сохраняются, недостающие создаются. Если вы исправили данные заявки вручную, повторный запуск команды обновит JSON-объекты. Для применения обновлённого приёмника к новым заявкам откройте **Развернуть → Управление развертываниями**, отредактируйте текущее веб-приложение, выберите **Новая версия** и нажмите **Развернуть**. URL `/exec` при обновлении существующего развертывания сохраняется.

## Публикация одобренных рун

Проверка и публикация остаются ручными. После смены статуса на `Одобрено` скопируйте значение из столбца **JSON-объект для runes** и вставьте его как новый элемент массива `runes` в `public/data/runes.json` репозитория GitHub. Между объектами нужна запятая. В веб-интерфейсе GitHub откройте файл, нажмите карандаш и создайте commit в `main` (или Pull Request, если публикация защищена). Пример объекта:

```json
{
	"id": "voin-2026-10-pve",
	"class": "Воин",
	"pve": "Код PvE",
	"pvp": "Код PvP",
	"additional": "Дополнительные коды",
	"author": "Имя автора",
	"note": "Примечание",
	"addedAt": "2026-10-08"
}
```

Не заменяйте `schemaVersion` и весь список: добавляйте скопированный объект, сохраняя существующие записи. Новые ID создаются в таблице автоматически. После публикации в `main` пользователи нажимают **Обновить** в разделе «Руны»; выпуск новой версии приложения для обновления каталога не нужен. Автоматическая публикация из таблицы пока не включена, чтобы непроверенная заявка не попала пользователям.
