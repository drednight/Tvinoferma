# Внешний API Твинофермы — короткий план

> Это первоначальная записка: она объясняет решения и порядок работ, но **не** является
> актуальным контрактом. Контракт, безопасность, настройки и статус этапов ведутся в
> [`docs/EXTERNAL-API.md`](./EXTERNAL-API.md) — при расхождении прав он.
> Макет страницы: `demo/external-api/` (`DEMO_ENTRY=/demo/external-api/index.html npm run demo`).

---

## 1. Главный ответ

**Да, сторонняя программа сможет запускать окна** — одно окно, пати целиком и выбранных
участников. Запуск уже работает в приложении, и внешний вызов пойдёт тем же кодом:
`launchOne(char, { interactive: false })` и
`launchPartyByName(partyName, { interactive: false, memberIds })`.

`interactive: false` — ключевая деталь: без диалогов и экранов проверки. Ровно так уже
запускают трей и макросы. Единственное условие — у персонажа прикреплён GameCenter и
запомнен вход: иначе задание завершится со строкой `skipped` (причина `no_gc` или
`no_saved_login`), а не откроет окно под чужим аккаунтом.

**Статы и проходки** меняются в базе Твинофермы (карточки, профиль, история изменений).
Поменять числа внутри игры нельзя — игра не даёт такого канала.

## 2. Как это устроено

```
Python / PowerShell / AHK
  │  HTTP на 127.0.0.1:47831, Bearer-токен
  ▼
Rust: external_api  ── проверка Host и токена, лимиты, журнал
  │  emit_to("main", "external-api-request", { requestId, method, path, query, body })
  ▼
JS главного окна  ── существующие функции приложения
  │  чтение state · normalizeStats · rememberStatsBefore · persist · launchOne
  │  invoke("external_api_reply", { requestId, status, body })
  ▼
HTTP-ответ
```

Прямая запись в `state.json` снаружи не годится: работающее приложение перезапишет
файл из памяти, а проверки целостности могут включить режим «Сохранение остановлено».
Поэтому изменения проходят через приложение.

Главное окно живёт в трее даже после закрытия, так что API работает, пока приложение
запущено. Выход из трея = `connection refused` — понятный признак «Твиноферма не работает».

## 3. Что сможет внешняя программа

| Действие | Запрос | Результат |
| --- | --- | --- |
| Проверить связь | `GET /api/v1/health` | версия, можно ли писать, занят ли запуск |
| Список персонажей | `GET /api/v1/characters` | ники, статы, проходки, окно запущено или нет |
| Один персонаж | `GET /api/v1/characters/{id}` | то же для одного |
| Изменить статы/проходки | `PATCH /api/v1/characters/{id}` | снимок в историю, сохранение, перерисовка |
| Массово (до 100) | `POST /api/v1/characters/bulk-update` | `updated` + `failed` |
| Пати и порядок | `GET /api/v1/parties` | участники в порядке запуска |
| Запущенные окна | `GET /api/v1/windows` | pid, заголовок, персонаж |
| Запустить окно | `POST /api/v1/launch/character` | `202 { jobId }` |
| Запустить пати | `POST /api/v1/launch/party` | `202 { jobId }`, можно с `memberIds` |
| Ход запуска | `GET /api/v1/jobs/{jobId}` | прогресс, итог по каждому персонажу |
| Закрыть окна | `POST /api/v1/windows/close` | только с `confirm: true` |
| Показать окно / оверлей | `POST /api/v1/app/show` | из трея или оверлей |

Пример на Python:

```python
import json, os, time, urllib.request

BASE = "http://127.0.0.1:47831/api/v1"
TOKEN = os.environ["TVINOFERMA_API_TOKEN"]

def api(method, path, payload=None):
    body = json.dumps(payload).encode() if payload is not None else None
    request = urllib.request.Request(
        BASE + path, data=body, method=method,
        headers={"Authorization": f"Bearer {TOKEN}", "Content-Type": "application/json"},
    )
    with urllib.request.urlopen(request, timeout=30) as response:
        return json.load(response)

job = api("POST", "/launch/party", {"partyName": "Основа"})
while True:
    status = api("GET", f"/jobs/{job['jobId']}")
    print(status["progress"].get("stage", status["status"]))
    if status["status"] not in ("queued", "running"):
        break
    time.sleep(2)
print(json.dumps(status["result"], ensure_ascii=False, indent=2))
```

## 4. Безопасность (обязательная часть, а не «потом»)

- **Выключено по умолчанию**, включается тумблером в «Настройки → Приложение → 🔌 Внешний API».
- Слушает только `127.0.0.1` — по сети управлять нельзя.
- **Bearer-токен**, сравнение постоянного времени; без токена `401`.
- **Проверка `Host`** — защита от DNS rebinding, иначе `403`.
- **Никакого CORS** — чужая вкладка браузера не сможет дергать `POST/PATCH`.
- Токен хранится в **хранилище ОС** (Windows Credential Manager, ключ `external-api-v1`);
  в `state.json` — только отметка `tokenCreatedAt`. Повторно показать нельзя, только перевыпустить.
- API **не отдаёт** контакты, пароли, куки, токены GameCenter и не принимает команды
  `factory_reset`, восстановления копий, `promo`/`transfer`/`shop`.
- Права по группам: чтение · изменение · запуск/закрытие.
- Лимиты: тело ≤ 64 КиБ, 60 запросов в минуту, один активный запуск; журнал последних
  100 вызовов без тел и токенов.
- В тестовой сборке (`feature = "acceptance"` и `acceptance-shared`) сервер **работает**,
  но на своём порту по умолчанию (`47832` вместо `47831`) и со своим токеном
  (`profile::VAULT_SERVICE`): тестовая и рабочая копии могут быть запущены одновременно.

## 5. Этапы

| Этап | Что делаем | Итог |
| --- | --- | --- |
| **M0** ✅ | контракт, безопасность, макет страницы | согласовать до кода |
| **M1** ✅ | Rust-сервер + чтение (`health`, `characters`, `parties`, `windows`) | можно читать, менять нельзя |
| **M2** ✅ | `PATCH`, `bulk-update`, история статов, ошибка `423` | можно менять статы и проходки |
| **M3** ✅ | задания запуска (в JS), `launch/character`, `launch/party`, закрытие окон | можно запускать окна и пати |
| **M4** ✅ | страница `GET /`, панель настроек, токен, справка | осталась ручная приёмка на Windows |

Код M1–M3 не потребовал новых Rust-зависимостей: `std::net` + поток (как в
`cloud_oauth_callback.rs`). Это важно: CI собирает с `--locked`, а локального `cargo`
может не быть.

Одно отступление от первоначального плана: **задания запуска (jobs) остались в JS**,
отдельного `jobs.rs` нет. Результат задания — это результат `launchGroup`, который
считается в JS; дублировать прогресс и отмену в Rust значило бы завести вторую правду.
Реестр (`JobRegistry`, TTL 30 минут, одно активное) живёт в `actions/launch.js`.

Переиспользуем, а не пишем заново: `normalizeStats`, `rememberStatsBefore`, `persist()`,
`renderCharacters()`, `partyById`/`charactersInPartyOrdered`, `launchGroup`/`runPreflight`,
очередь `startTask`, `runningClientDetails`/`windowRows`/`closeClientsByPid`.

## 7. Решения (приняты)

1. Клиент — любой: универсальный JSON API, примеры curl/Python/PowerShell на странице `/`.
2. Запуск по расписанию — да, job-модель это позволяет.
3. Токен — в хранилище ОС, повторно показывается только перевыпуском.
4. Закрытие окон — да, только с `{"confirm": true}` и правом «Запуск и закрытие окон».
5. Массовое изменение статов/проходок — да, до 100 персонажей.
6. Порт `47831` — да, поле в настройках.
7. Интерфейс — отдельная вкладка «🔌 Внешний API» в настройках; сама страница — браузер.

Полные ответы с обоснованием — `docs/EXTERNAL-API.md` §10.

## 8. Этап 2: данные твин-фермы, выгрузки, выбор для запуска

Запрос: «перечислить аккаунты, пати и марафоны с их настройками; раскрыть персонажа
и менять статы/проходки; выгружать списки программами; выбрать персонажей и запустить
их окна — и многое другое для твин-фермы».

Что добавлено (контракт — `docs/EXTERNAL-API.md` §4.13):

| Область | Маршруты | Право |
| --- | --- | --- |
| Пати | `GET /parties/{id}`, `PATCH /parties/{id}` | чтение / изменение |
| Персонажи | `POST /characters`, поля карточки в `PATCH /characters/{id}`, `PATCH /dungeon-passes/{id}` | изменение |
| Марафоны | `GET /marathons`, `GET /marathons/{id}`, `GET /marathons/{id}/participants` | чтение |
| Прогресс марафона | `POST /marathons/{id}/marks`, `POST /marathons/{id}/adjust` | изменение |
| Планировщик, учёт | `GET /planner`, `GET /finance` | чтение |
| Выгрузки | `GET /export/{набор}.{csv\|json}` (6 наборов) | чтение |
| Запуск | `POST /launch/selection` (до 100, порядок сохраняется) | запуск |

Границы, которые решено не переходить:

1. **Прогресс марафона не пишется «мимо» полей.** Отметка дня и поправка счётчика —
   те же поля `progress[charId][taskId].marks/adjust`, что пишет интерфейс; произвольная
   запись ячейки не принимается, чтобы не сломать расчёт `computeCell`.
2. **`totals` — из модели интерфейса** (`marathonTotals`), а не свой расчёт в API:
   одна правда о прогрессе. Если модель упала на битых данных, `totals: null`.
3. **Выгрузка — белый список полей.** Контакты, пароли, путь запуска, куки и облачные
   ключи не выгружаются ни в CSV, ни в JSON (те же правила, что у чтения).
4. **Сырые ответы ограничены выгрузками:** `Reply.raw` в Rust — только текст с
   `Content-Type`/`Content-Disposition`; JSON-ошибки и остальные ответы идут как раньше.
5. **Удаления через API нет:** архивирование и удаление остаются в интерфейсе —
   их нельзя откатить, а внешняя программа не должна этого делать «на автомате».

Побочно исправлено: в мосте `load()` возвращал фабрику ленивого импорта вместо модуля,
поэтому маршруты, не подменённые в `deps`, падали. Добавлен регресс-тест.
