# План: полезный первый запуск, ярлык и нативный календарь

Статус на 10.10.2026: **все три задачи сделаны**. Задача 1 выполнена с отклонением от
плана: вместо недели на 7 колонок сделан вид «5 дней» (вчера, сегодня и три дня после).
Задачи 2 и 3 подтверждены пользователем как работающие.

## Зачем

Приложение выросло до 1.0.0, но три вещи мешают им пользоваться с первого запуска:

1. Подсказка первых шагов свёрстана «вертикальной простыней» строк — читается как список, а не как
   приглашение к работе.
2. Приложение трудно найти поиском Windows, а регистрация для уведомлений происходит слишком поздно.
3. Календарь показывает месяц из 31 мини-шкалы: мелко, и нельзя сравнить дни между собой.
   Нужен нативный вид, знакомый по Google Calendar и Outlook.

## Что выяснено до начала работы (факты, а не предположения)

| Факт | Значение |
| --- | --- |
| Идентификатор приложения | `com.tvinoferma.desktop` в `tauri.conf.json` |
| Где он используется | папка данных **и** имя службы в хранилище учётных данных ОС |
| Записей в хранилище | **21** (контакты персонажей, ключи GameCenter, `cookie-bank-key`) |
| Объём профилей браузера | `pw-sync-profiles` — **1756 МБ** |
| Текущий MSI upgradeCode | `5dbcc9ea-3fb8-5bc2-bef0-11e504fb947e` (выводится из `productName`!) |
| Установлено сейчас | **две копии**: 0.2.0 «Твиноферма» и 0.2.2 «Tvinoferma» |
| Задача автозапуска | `Tvinoferma autostart`, указывает на exe |

**Вывод:** `upgradeCode` выводится из `productName`, поэтому смена названия уже однажды

повторение проблемы при любой будущей правке названия.

## Задача 1. Календарь: неделя × 24 часа (вариант A) — СДЕЛАНО ИНАЧЕ, чем планировалось

### Отклонение, о котором надо помнить

План обещал неделю из **7** колонок. Сделано **5** (вчера, сегодня, +3 дня) в `8eeecf6`:
на неделю смотреть не нужно было, а семь колонок на ноутбуке превращались в кашу
из узких полос. Месячная сетка при этом переоформлена и осталась рабочей.

Если семь дней всё-таки нужны — это отдельная правка: в `weekView.js` меняется
список смещений от текущего дня, остальное (`timelineBlocks`, автопрокрутка, окно дня)
готово и не зависит от числа колонок.

### Что делаем

Новый компактный вид — колонки дней, время идёт сверху вниз.

- Ось времени слева: линии каждый час, подписи каждые 3 часа.
- Запись — блок от времени начала на всю длительность, цвета как в месяце.
- **Наложения разводятся по дорожкам** — `timelineBlocks` уже это умеет, переиспользуем как есть.
- Красная линия текущего времени, сегодняшняя колонка подсвечена.
- Постоянные ивенты — штриховкой; марафон — плашкой в строке «весь день».
- Записи без времени — плашками в шапке колонки.
- При открытии — автопрокрутка к текущему часу (не начинать с 00:00).
- Данж дня — цветной полосой в шапке колонки.

### Переключатель вида

- **«Неделя»** — новый компактный вид (вид по умолчанию).
- **«Месяц»** — текущая сетка, работает как есть, не трогаем.
- Выбор запоминается в `settings.planner.view` (`week` | `month`) через `persist()`.
- Кнопка «Сегодня» работает в обоих видах.

### Окно дня — одно на оба вида

`openPlannerDay` уже одна функция и вызывается из ячейки месяца и из панели «Сегодня».
Сведём к одному поведению: полная шкала `00:00–24:00`, список записей, добавить/править/удалить.
Из недели открывается по клику на колонку или на блок.

### Что не меняется

`plannerEventsForDate` — источник данных остаётся тем же. Меняется только отображение.

**Файлы:** `js/modules/dashboard/plannerView.js`, новый `js/modules/dashboard/weekView.js`,
`css/modules/today.css`, `js/core/constants.js` (настройка вида), `todayView.js`,
`tests/plannerWeek.test.js`.

## Задача 2. Поиск в Windows и ярлык — СДЕЛАНО, подтверждено 10.10.2026

1. **Регистрировать AUMID при запуске**, а не при первом уведомлении: сейчас до первого
   уведомления приложения нет ни в «Параметры → Уведомления», ни в результатах поиска.
   → `notify::register_at_startup()` вызывается в `setup` (`src-tauri/src/lib.rs:71`).
2. `DisplayName` = **«Твиноферма (Tvinoferma)»** — оба написания в одной строке.
   → `notify.rs:26`.
3. **Ярлык в меню «Пуск» — «Твиноферма».** `productName` остаётся `Tvinoferma`: его смена
   меняет папку установки и имя exe, а это лишний риск при обновлении.
4. **Фиксируем `upgradeCode`** явным значением `5dbcc9ea-3fb8-5bc2-bef0-11e504fb947e`,
   чтобы установщик заменял версию, а не ставил копию рядом. → `tauri.conf.json:44`.
5. **Проверено фактически пользователем 10.10.2026:** ярлык в «Пуск», `DisplayName`
   в реестре и поиск Windows по обоим словам работают.

**Риск (не понадобился):** имя ярлыка задаётся фрагментом WiX. Если бы через фрагмент
не вышло, запасной путь — переименование ярлыка при первом запуске.

## Задача 3. Приветственное окно при первом запуске

- Показывается один раз, когда персонажей нет; повторно — по кнопке.
- Те же три шага, но как **окно-приглашение**: что делать, зачем и кнопка действия в каждом шаге.
- Короткая справка «Как войти на сайт игры» (текст в `onboarding.js` уже есть).
- Логика исчезновения не меняется: появился первый персонаж — окно не показывается.
- Закрывается `Esc`, после закрытия не мешает работе.
