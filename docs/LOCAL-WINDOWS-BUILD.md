# Локальная тестовая сборка Windows

Скрипт `scripts/build-windows-local.ps1` собирает текущий checkout на вашем ПК,
без GitHub Actions и расхода его минут. Он **не устанавливает системные инструменты**,
не скачивает секреты GitHub, не переключает ветку, не публикует релиз, не создаёт
установщик/подпись автообновления и не запускает полученную программу.

## 1. Подготовка один раз

Нужна **Windows x64**, доступ в интернет и несколько гигабайт свободного места
(для Rust/SDK/кэшей лучше иметь запас в десятки гигабайт).

Установите из официальных источников:

1. **Git for Windows** — <https://git-scm.com/download/win>.
2. **Node.js 22 LTS**, не ниже 22.12 — <https://nodejs.org/> (включая npm).
3. **Visual Studio Build Tools 2022** — <https://visualstudio.microsoft.com/downloads/>,
   раздел Tools for Visual Studio → Build Tools. В установщике выберите
   **Desktop development with C++ / Разработка классических приложений на C++**,
   MSVC x64/x86 и Windows 10/11 SDK.
4. **Rust stable, MSVC x64** — <https://rustup.rs/>.
   Если уже установлен другой toolchain, выберите нужный самостоятельно:
   `rustup default stable-x86_64-pc-windows-msvc`.
5. **Microsoft Edge WebView2 Runtime** — нужен для запуска приложения:
   <https://developer.microsoft.com/microsoft-edge/webview2/>.

После установки откройте **новое** окно PowerShell. Поддерживается Windows
PowerShell 5.1 и PowerShell 7. Обычный запуск не требует прав администратора.
Системные установщики могут отдельно запросить повышение прав.

## 2. Получить исходники

Для первой загрузки откройте PowerShell в папке, где хотите хранить проект:

```powershell
git clone --branch arena/95755e6b-tvinoferma --single-branch https://github.com/drednight/Tvinoferma.git
cd Tvinoferma
git rev-parse --short HEAD
```

Скрипт и все его файлы должны быть из одного checkout, не копируйте только `.ps1`
поверх старой версии проекта. Если используете существующий checkout нужной ветки,
обновите его сами после проверки местных правок:

```powershell
git status --short
git branch --show-current
git pull --ff-only
```

Не сбрасывайте свои изменения через `reset --hard`. Скрипт по умолчанию откажется
собирать изменённую рабочую копию. Параметр `-AllowDirty` разрешает её явно, но
результат получает отметку `dirty: true`: SHA коммита уже не описывает весь код.

## 3. Запустить сборку

Из корня репозитория:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\build-windows-local.ps1
```

`Bypass` действует только на этот процесс PowerShell; глобальная политика не меняется.
Не обходите корпоративную политику, запрещающую выполнение скриптов.

По умолчанию выполняются `npm ci`, lint, проверка форматирования, типов и
Tauri release build без упаковки. Frontend собирается автоматически через
`beforeBuildCommand`. Cargo использует `--locked`, LTO выключен и codegen-units=16,
как у acceptance-сборки. Target явно `x86_64-pc-windows-msvc`.

**Первая сборка может быть долгой**: загружаются npm/Rust-зависимости и компилируется
приложение. Прогресс виден в консоли; не закрывайте её. Скрипт останавливается
при ненулевом коде любой команды, а изменённые lock-файлы не откатывает молча.

### Дополнительные режимы

Полные frontend-тесты и Rust library tests (дольше, не равнозначно всем заданиям CI):

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\build-windows-local.ps1 -Checks Full
```

Повторная сборка с уже установленными зависимостями:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\build-windows-local.ps1 -SkipInstall
```

`-SkipInstall` не подтверждает соответствие `node_modules` текущему lock-файлу.
После изменения зависимостей запускайте без него. `-Checks None` пропускает lint,
format/typecheck и тесты, но не саму сборку; это **не успешное прохождение CI**.
Не выдавайте такую сборку за проверенный релиз.

## 4. Где результат и как его использовать

При успехе консоль напечатает `SUCCESS: ...`. В новой папке
`local-acceptance/<дата>-<коммит>-<суффикс>/` появятся:

- `Tvinoferma.exe`;
- `SHA256SUMS.txt` — SHA-256 исполняемого файла;
- `BUILD-INFO.json` — коммит, ветка, признак местных правок, версия и режим проверок;
- `READ-ME.txt` — ограничения и предупреждения.

Предыдущие сборки не перезаписываются. Папка исключена из Git.
Можно проверить хеш вручную:

```powershell
Get-FileHash .\local-acceptance\<папка-сборки>\Tvinoferma.exe -Algorithm SHA256
```

**Это неподписанная тестовая программа, а не установщик. Встроенный номер версии
может совпадать со стабильным. Профиль и Windows vault НЕ изолированы особым
identifier. Запускайте только в отдельной тестовой учётной записи Windows без
рабочих данных Твинофермы. Не запускайте одновременно с другой версией.**

Скрипт сам приложение не запускает. SmartScreen может предупредить об отсутствии
подписи; не отключайте защиту Windows целиком. Проверьте происхождение исходников
и собранного файла. Копирование exe не переносит профиль, контакты или vault.

Для тестов фонового ввода см. `docs/GAME-MACROS.md`. Сборка сама по себе не доказывает
совместимость с игрой. Скрипт не получает OAuth-настройки CI: облачные интеграции,
требующие build-переменных, могут быть недоступны. Для игровых проверок не нужно
копировать секреты из GitHub или пересылать их в чат.

## Если сборка не удалась

- `Missing prerequisite` / MSVC: установите нужные компоненты и откройте новое окно PowerShell.
- Ошибка линкера/Windows SDK: проверьте C++ workload и SDK в Visual Studio Installer.
- `npm ci` не скачивает пакет (в том числе SheetJS): проверьте интернет/прокси,
  затем повторите без `-SkipInstall`. Не отключайте TLS и не меняйте lock-файл наугад.
- Cargo сообщает, что lock-файл требует обновления: не удаляйте его; пришлите ошибку.
- Сообщение о грязной копии: сначала посмотрите `git status --short`; скрипт ничего не сбрасывает.
- Ошибка компиляции Rust: это полезный результат — Windows-компиляция новых правок
  могла не пройти на GitHub из-за лимита. Нужен текст ошибки, не повторные попытки вслепую.

Пришлите SHA исходников (`git rev-parse HEAD`), выбранный режим и последние строки
ошибки. При успешной сборке достаточно `BUILD-INFO.json`; `.exe` для диагностики
не нужен. Перед отправкой вывода уберите пароли, токены и личные пути. Не присылайте
переменные окружения, cookies, vault или резервные копии данных.

Скрипт подготовлен в Linux-среде: настоящая Windows-сборка должна быть выполнена
на вашем ПК; статические проверки скрипта не заменяют этот прогон.
