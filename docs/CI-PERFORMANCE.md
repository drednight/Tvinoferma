# Измерения CI

JS-набор остаётся полным. Все восемь заданий строят один и тот же детерминированный
LPT-план: сначала самые дорогие файлы, затем каждый файл в наименее загруженную часть.
Источник весов — длительности файлов последнего успешного прогона этой ветки в кеше
Actions. Новый файл получает консервативный вес; первый запуск без истории собирает
базовую статистику. Изоляция тестов и два worker на задание сохраняются.

После восьми частей отдельное задание проверяет полноту покрытия: каждый найденный
`tests/**/*.test.js` должен быть указан ровно один раз и иметь измерение. Только после
этого сохраняется следующая таблица весов. Обязательная frontend-проверка зависит и
от этой проверки. В артефакты попадают лишь пути файлов и длительности — не тела тестов,
сообщения об ошибках, содержимое состояния или учётные данные.

В summary JS-задания видны самые дорогие файлы; таблицы `.ci-results` и `.ci-timings`
не коммитятся. Сравнивать нужно не один случайный прогон, а несколько одинаковых
ревизий на прогретом кеше. Балансировка не является ускорением самих тестов.

Rust summary отдельно показывает точное попадание в кеш, время восстановления
(включая накладные расходы Actions), компиляцию/линковку тестов через `--no-run`,
выполнение с повторной проверкой свежести Cargo и Credential Manager smoke.
Clippy измеряется отдельно целиком. Исходные коды/зависимости не исключаются из проверки,
ошибка любой стадии сохраняет ненулевой код возврата. Cargo также создаёт локальный
HTML `target/cargo-timings` для разбора компиляции.

Решение о sccache принимается после измерения: он не ускоряет сами тесты, линковку,
восстановление кеша Actions и подготовку runner. Если основное время уходит туда,
добавлять ещё один кеш нецелесообразно. Зависимые от Windows/Credential Manager тесты
не переводятся в Linux и не отключаются ради скорости.

## Первый замер (622b8f7)

- compile-and-link-tests: 170,69 с; execute-tests-with-cargo-freshness-check: 6,03 с;
  Credential Manager smoke: 1,70 с; clippy: 38,52 с.
- Следующий прогон подтвердил точное попадание кеша clippy и восстановление за 21,55 с.
- JS: группа 06 — около 112 с на провайдера, группа 21 — 50–62 с, группа 22 — около 48 с.

Группы 06/21/22 разделены на четыре независимые единицы регистрации на провайдера.
Утверждения и настоящая криптография не заменены моками, KDF и проверки секретов не
ослаблены. Параметризованная группа остаётся целой; объединение всех четырёх частей
регистрирует каждую группу ровно один раз.

В Windows CI тестовый профиль теперь собирается без debug symbols (`CARGO_PROFILE_TEST_DEBUG=0`):
это попытка уменьшить генерацию/линковку отладочной информации, а не отключение проверок.
Release-профиль приложения не меняется. Первый запуск может быть холодным из-за смены
профиля; эффект требует повторного прогона с прогретым кешем.

Для отдельного сравнения добавлен ручной параметр `rust_sccache` workflow CI. По умолчанию
он выключен. Эксперимент печатает статистику sccache, сохраняет полную проверку и не
считается доказанным ускорением без холодного/тёплого сравнения одной ревизии.
