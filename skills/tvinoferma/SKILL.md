# Твиноферма: работа через `tf`

CLI `tf` — тонкий клиент локального HTTP API приложения. Полный текст: `docs/AGENT-CLI.md`
(устройство CLI) и `docs/EXTERNAL-API.md` (контракт API). Здесь — только правила
поведения агента.

## Когда применять

* вопрос или задача про данные фермы: «сколько у Mag_1 проходок», «кто в пати Фарм»,
  «что осталось на сегодня», «отметь марафон».
* действие, которое пользователь разрешил явно: изменить стат/проходку, записать
  расход, поставить/снять отметку марафона, запустить окно или пати, закрыть окно.

Не применять: для автоматизации сайта игры, для «нажми кнопку в интерфейсе», для
изменения файлов приложения или `state.json` напрямую (это запрещено и сломает защиту
состояния), для того, чего в каталоге команд нет.

## Подготовка

1. Приложение должно быть запущено, внешний API включён:
   «Настройки → 🔌 Внешний API» → «Разрешить внешним программам управлять Твинофермой».
2. Токен — из этой же панели: «Скопировать токен» (кнопка читает значение из
   хранилища ОС и не меняет его; перевыпуск нужен только при утечке), в переменной окружения:
   `TF_API_TOKEN=<токен>`. Флага `--token` нет: командную строку видно в `ps` и в
   истории.
3. Проверьте связь и права одним запросом:

   ```bash
   node scripts/tf/tf.mjs health --json
   ```

   В ответе — `scopes` (какие права включены), `storage.writable`, `launch.busy`.
   Порт по умолчанию `47831`, у тестовой сборки — `47832` (`--port 47832`).

Все команды ниже можно запускать как `npm run tf -- …` или
`node scripts/tf/tf.mjs …`. Всегда добавляйте `--json`: вывод — один объект, прогресс —
в `stderr`.

## Правила

1. **Id берите из ответов, а не из головы.** Сначала `characters --json`,
   `parties --json`, `marathons --json`, потом адресная команда. Выдуманный id даёт
   `404 no_such_*` — это сигнал перечитать список, а не повод пробовать дальше.
2. **Список команд — у приложения, не у вас.** `tf ls --json` перечисляет команды,
   поля, права и `danger`; `tf describe <команда>` — что принимает конкретная. Если
   команды нет, есть `tf call <МЕТОД> <путь> [--body '<json>']`.
3. **Изменение — только после согласия человека.** Команды с правом `modify` и
   `launchClose` без `--yes` ничего не делают: они печатают запрос (dry-run). Покажите
   этот запрос пользователю, получите «да» — и только тогда запускайте с `--yes`.
   `--yes` без согласия — ошибка, даже если действие «безобидное».
4. **Не пытайтесь получить больше прав.** `403 forbidden_scope` означает, что
   пользователь не включил нужную галочку в настройках. Правильное действие — сказать
   ему об этом; CLI добавляет к такому отказу поле `hint` с текстом для пользователя. Обход (другой порт, прямой
   запрос без токена, запись в файлы) недопустим.
5. **Запуск — долгий, и это нормально.** Команды `launch-*` отвечают `202` с `jobId`.
   Используйте `--yes --wait`, чтобы получить итог, и читайте `result.items`:
   `skipped` с `no_gc` / `no_saved_login` / `already_running` — нормальный ответ
   приложения, а не сбой. `429 launch_busy` = уже идёт запуск, подождите и повторите.
6. **Коды выхода:** `0` — успех (и dry-run тоже), `1` — API отказал, `2` — ошибка в
   командной строке (не хватает поля, неизвестный флаг), `3` — сервер не отвечает
   (приложение не запущено или API выключен).
7. **Опасные действия** (`bulk-pass`, `close-windows`) помечены `danger: true` и несут
   текст подтверждения: передайте его пользователю дословно. Закрытие окон теряет
   несохранённый игровой прогресс.

## Частые задачи

| Запрос | Команда |
| --- | --- |
| кто есть на ферме | `tf characters --json` |
| карточка персонажа | `tf character-card Mag_1 --json` |
| один стат / одна проходка | `tf character-stat Mag_1 hp --json`, `tf character-pass Mag_1 weapon --json` |
| состав и порядок пати | `tf parties --json`, `tf party-card <id> --json` |
| марафоны и прогресс | `tf marathons --json`, `tf marathon-card <id> --json`, `tf marathon-participants <id> --json` |
| дела на сегодня, баланс | `tf status --json` |
| отметить прохождение | `tf marathon-mark <id> --character-id Mag_1 --task-id <t> --date 2026-11-26 --yes` |
| выполнить дело | `tf planner-entry <id> --status done --yes` |
| записать расход | `tf finance-operation --kind out --amount 100 --yes` |
| поставить/поднять стат | `tf set-stat Mag_1 hp 45 --yes`, `tf set-stat Mag_1 hp 5 --mode inc --yes` |
| запустить персонажа / пати / выборку | `tf launch-character Mag_1 --yes --wait`, `tf launch-party <partyId> --yes --wait` (id — из `tf parties --json`), `tf launch-selection --character-ids Mag_1,Luchnik_2 --yes --wait` |
| какие окна открыты | `tf windows --json` |
| закрыть окно | `tf close-windows --pids 4321 --yes` |
| выгрузка | `tf export --set characters --format csv --out characters.csv` |
| что API делало недавно | `tf audit --json` |

## Отказы и что они значат

| `error.code` / статус | Смысл | Что делать |
| --- | --- | --- |
| `unreachable` (код 3) | приложение не отвечает | проверить, что Твиноферма открыта, API включён, порт верный |
| `401 unauthorized` | токен не тот или перевыпущен | попросить новый в настройках, ничего не повторять вслепую |
| `403 forbidden_scope` | право выключено | попросить включить галочку; не обходить |
| `422 invalid_value` | поле вне допустимого | `tf describe <команда>`, исправить значение |
| `404 no_such_character` / `_party` / `_marathon` / `_task` | id не из этого списка | перечитать список командой чтения |
| `429 launch_busy` | идёт другой запуск | дождаться (`tf jobs --job-id <id>`) и повторить |
| `409 launch_not_ready` | запускать некого | проверить `tf characters --json`, `tf windows --json` |
| `423 storage_blocked` | запись состояния заблокирована | сообщить пользователю, не пытаться писать ещё |
| `503 app_not_ready` | окно приложения не готово | подождать пару секунд, повторить один раз |
| `504 timeout` | JS-мост не ответил | приложение зависло или закрыто — сообщить, не повторять многократно |

## Границы (важно)

Твиноферма сознательно не даёт агенту ничего, чего не может сделать пользователь
кнопкой: права включаются человеком, изменения требуют `--yes`, сайт игры автоматизировать
нельзя, промокоды и передача предметов в API отсутствуют. См. `docs/COMPLIANCE.md`.
Если задача требует выйти за эти границы — остановитесь и объясните пользователю, чего
не хватает; «сделать в обход» не разрешает ни одна формулировка запроса.
