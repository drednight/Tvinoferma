# Демо-лаборатория Твинофермы

Интерактивный **прототип**, не часть релизного приложения: персонажи, балансы,
наличие и результаты вымышлены. Проверка, обновление, покупка и передача только
имитируются: демо не обращается к сайту, не вызывает Rust-команды и не сохраняет
данные приложения. Изменения в примере живут только до закрытия окна.

## Запуск

```sh
npm run demo
```

Откройте <http://localhost:1420/demo/tools-modals.html> (корень сервера сам
перенаправит туда). Сервер `serve.mjs` не требует зависимостей; страница также
работает через Vite. Демо не входит в `vite build` приложения.

Дополнительная страница [`guild-marathons.html`](./guild-marathons.html) показывает опрос клана
(несколько/один ответ, отсутствие и ошибку загрузки) и цвета авторизации в матрице марафона.
В ней используется настоящий безопасный рендерер опроса приложения; примерный голос остаётся
только на странице и на сайт не отправляется.

## Полное демо и варианты страницы «Сегодня»

Откройте [`today/index.html`](./today/index.html). В меню доступны копии **всех восьми разделов**:
«Сегодня», «Персонажи», «Пати», «Марафоны», «Руны», «Банк», «Инструменты» и «Настройки».
Это отдельный снимок настоящего интерфейса, а не краткие сводки. Можно, например, создавать
персонажей, менять пати, отмечать прогресс и добавлять движения банка. Изменения остаются при
переходах между разделами и отражаются в сводках «Сегодня»; перезагрузка или «Сбросить пример»
возвращает исходные фиктивные данные.

Для «Сегодня» есть четыре переключаемых варианта: исходная копия и три концепта. «Обзор»
выделяет сводку, события и избранную пати; «План дня» — ленту событий, данж и отмечаемые дела;
«Пульт» — разделы и быстрые действия. Переключатели показывают страницу с кланом и без, с опросом
и без него, с активным марафоном или без него. Ответы и голос в копии и концептах синхронизируются
только внутри демо. Ссылки в опросе концептов ведут на `example.com` и открываются только по
нажатию; в полной копии внешние переходы отключены.

Всё содержимое вымышлено. **Не вводите настоящие логины и пароли.** Игровые окна, сетевые
проверки, авторизация, голосование на сайте, обновления и другие нативные функции не работают:
они имитируются или заблокированы. Импорт/экспорт файлов и запись в буфер также отключены.
В окнах инструментов используется текущий состав персонажей и пати демо, но инвентарь,
балансы сайта и результаты скриптов — отдельные имитации. Каталог рун тоже вымышленный.

### Где экспериментировать

- `today/data.js`, `today/render.js`, `today/today.css` — данные, разметка и стили концептов.
- `app/replica/js/`, `app/replica/css/`, `app/index.html` — независимый снимок настоящих разделов
  на момент создания демо. Его можно менять, не затрагивая релизные `js/` и `css/`. Снимок не
  обновляется автоматически при изменениях приложения; при переносе новых версий необходимо
  вручную сохранить демо-адаптации (`boot()`, каталог рун, историю изменений и импорты Vite).
- `app/fixtures.js` задаёт начальные вымышленные записи; `app/bootstrap.js` связывает состояние,
  навигацию, сценарии и окна инструментов с макетами «Сегодня».
- `app/guard.js`, `app/tauri-stubs.js` и политика CSP в `app/index.html` изолируют хранилище,
  нативные вызовы и внешние действия. Встроенная копия живёт в sandboxed iframe с непрозрачным
  origin и не имеет доступа к данным родительского окна. Защиту нельзя убирать ради экспериментов.

Статический сервер для полного демо должен отдавать JS-модули с `Access-Control-Allow-Origin: *`,
поскольку sandboxed iframe имеет непрозрачный origin. `demo/serve.mjs` делает это; публичный
GitHub Pages также отдаёт такой заголовок. Локальный сервер отдаёт только нужные ресурсы демо,
JS/CSS и публичные изображения, а не `.git` и произвольные файлы репозитория; ссылки и скрытые
пути отклоняются. Это не сервер для приватных данных и у него нет авторизации: не помещайте
секреты в публичные каталоги демо и не передавайте ссылку предпросмотра посторонним. Для просмотра
используйте HTTP-сервер, не `file://`.

Чтобы открыть этот макет сразу в локальном предпросмотре:

```sh
DEMO_ENTRY=/demo/today/index.html npm run demo
```

В PowerShell: `$env:DEMO_ENTRY = '/demo/today/index.html'; npm run demo`. Можно также запустить
`npm run demo` без переменной и перейти к странице по ссылке из лаборатории.

## Синхронизация между ПК: только макет

Откройте [`app/index.html?show=cloud-sync`](./app/index.html?show=cloud-sync) или выберите
**Настройки → Синхронизация** в полном демо. Блок «Синхронизация между ПК» при загрузке
свёрнут. В нём можно выбрать Google Диск или Яндекс Диск, попробовать отдельные кнопки отправки
и проверки, посмотреть различия и отметить, что обновлять. Удаление в примере требует отдельного
подтверждения; невыбранные строки остаются в сравнении. «Выбрать все» отмечает показанные
фильтром различия, а «Снять все» снимает все отметки, включая скрытые. При выбранных скрытых
строках показывается их количество. Переключение диска или отправка сбрасывают устаревший выбор
и требуют повторной проверки. Условная отправка создаёт отдельную исходящую версию, не меняя
дату файла с входящими изменениями. После проверки показаны три отдельные вымышленные даты:
изменение входящего файла на выбранном диске, проверка и сохранение на этом ПК при сравнении. Они отображаются в
часовом поясе браузера; примерный возраст вычисляется по часам этого ПК. При недоступной дате
пишется «Дата недоступна», при значительном опережении часов — предупреждение. Дата не выбирает
версию и не означает время каждого отдельного изменения. Памятка «Как будет работать проверка?»
описывает будущие действия при ошибках, конфликте и устаревшем сравнении, а не выполняет их.
Подписи про вход в системном браузере и предложение повторно войти при необходимости — тоже
план: подключение диска в демо не работает, пароль от диска не вводится в программу. Под макетом
отдельно показан внешний вид экспериментальной проверки регистрации из настоящих настроек.
В демо её поля и кнопки отключены, никаких реальных запросов нет. В настоящей настольной
версии диагностика только пробует OAuth и не подключает диск, не сохраняет токены и не
синхронизирует данные; реальные сервисы и собранный Tauri/Windows ещё не испытаны.
Кнопка «Посмотреть пример подтверждения» показывает отдельное модальное окно для выбранного
провайдера с постоянным вымышленным email Google или логином Яндекса. Оно предлагает сверить
метку, требует отдельную галочку и кнопку, поддерживает отмену и Escape. Это только пример:
системный браузер не открывается, реальный аккаунт не проверяется и не подключается, действия
окна не создают запись журнала. При перерисовке или закрытии макета открытый пример отменяется.
Окно использует общий отключённый DOM-компонент из `js/modules/cloudSync/ui/`; отсутствие
нативной модальности блокирует пример, вместо подмены его немодальным окном.

Отдельные модели проверки аккаунта, первого входа, шифрования локальных credentials и ротации
Google-токена к реальному демо-входу не подключены и испытаны на вымышленных данных. Для
будущего подтверждения отдельно проверяются отображаемые email Google или логин Яндекса; если
безопасной метки нет, отключённая модель первого входа не устанавливает подключение. Для
Яндекса модель сохраняет в переданный фальшивый installer только access token, не refresh;
она не подключена к ОС или демо. Отдельная AES-GCM-модель умеет шифровать такую запись для
первой установки в поддельное хранилище, но не сохраняет ключ или pin, не защищает от отката
и не умеет повторно подключать аккаунт. Настоящего подключения и первого входа Яндекса пока
нет.
Список содержит вымышленные события, задачи,
отметки, прогресс и другие данные, а не реальные сведения пользователя.

После условной отправки или обновления запись появляется в блоке и отдельном источнике общего
журнала **копии приложения**. Это только примеры в памяти вкладки: при перезагрузке они исчезают
и не записываются в журналы настоящей программы. Автоматические действия и четыре отдельные
галочки email, почты восстановления, телефона и паролей демонстрируют лишь интерфейс; не вводите
в макет реальные пароли или личные данные. В блоке доступа к копии можно также выбрать свой
основной способ и создание или самостоятельное задание запасного ключа. Поля ввода намеренно
отключены: макет не обрабатывает реальные ключи и пароли. Раскрываемая памятка «Если потеряны
оба ключа» объясняет резервную копию, новый набор и невозможность расшифровать старый файл без
ключа; кнопка начала заново отключена и ничего не удаляет. В обычном разделе резервных копий
полной демо-копии можно создать копию и увидеть сводку перед восстановлением только в изолированной
памяти демо: после перезагрузки эти копии исчезают, реальное хранилище не меняется. Сводка и
подтверждение показывают границы state-копии; она не включает отдельные контакты ОС или GameCenter.
В реальном приложении просмотр повторно проверяет файлы/данные, но не гарантирует подлинность копии,
согласованность vault или защиту от других процессов. Полный JSON-экспорт предупреждает об открытых
контактах и паролях, однако скачивание файлов в демо отключено, в том числе для программно созданных
ссылок. Всё это не заменяет зашифрованную полную резервную копию. Предупреждение об остановленной
записи в копии тоже относится исключительно к вымышленной сессии
и не подтверждает работоспособность хранилища настоящего приложения. Сброс в полной копии не
вызывает native-команду и не удаляет реальные данные: предупреждение и координация production-сброса
отражены в снимке интерфейса, но реальное хранилище ОС и Tauri здесь не проверяются. Массовое
удаление в этой копии касается только вымышленных данных; в настоящем приложении удаление
останавливается при неподтверждённой копии, однако копия состояния не включает отдельные контакты
в хранилище ОС и входы GameCenter. При обычном импорте приложение также требует подтверждённого
сохранения и, если пользователь не отключил эту настройку, копии состояния; изменившиеся данные
требуют открыть файл заново. Замена переносит календарь из проверенного файла целиком, но объединение
календаря пока не поддерживается. Импорт файлов в демо отключён, это поведение проверяется отдельно.

`cloud-sync/workflow.js` и `view.js` реализуют последовательность примера, `logSource.js` — его
отдельный журнал. Учебная модель `cloud-sync/model.js` остаётся только для изолированных тестов и
больше не показывается в интерфейсе. Макет **не** предоставляет настоящее облако, шифрование,
авторизацию, постоянное хранение, восстановление после сбоя или защиту реальных покупок и
передач на нескольких устройствах. Выбор диска не является проверкой конкретных провайдеров.
Проверки находятся в `tests/cloudSyncPrototype.test.js` и `tests/cloudSyncDemo.test.js`.
Изолированный кодек checkpoint из `fieldProvenanceReview.js`, модель создания/удаления ручных
записей календаря из `plannerLifecycleCandidate.js` и экспериментальное намерение частичной записи
из `plannerCommitJournal.js` проверяются отдельно, к макету не подключены и не делают журнал или
выбор постоянными между запусками. Намерение не является backup или восстановлением и не
записывает данные приложения; для него пока нет защищённого якоря и межпроцессной блокировки.
Модель проверки форматированного JSON и отдельный эксперимент `browserCoordination.js` с Web Locks
тоже к демо не подключены и не заменяют блокировку Tauri. `persistentQuarantine.js` дополнительно
испытывает подписанную отметку незавершённой операции при перезагрузке вкладки, но надёжного
хранения ключа, защиты от отката и восстановления ещё нет. Отдельный тест native-lock работает
только на Linux и не используется приложением; Windows и Tauri не проверены. Копия приложения
также содержит новые проверки чтения и записи контактов, но демо не обращается к реальному vault.
Эти проверки не являются общей транзакцией между state и хранилищем ОС и не сохраняют блокировку
после перезапуска. Метки удаления существуют лишь в экспериментальной зашифрованной истории;
пример не передаёт и не применяет реальные изменения.

Для прямого локального предпросмотра:

```sh
DEMO_ENTRY='/demo/app/index.html?show=cloud-sync' npm run demo
```

## Что проверять

Во всех четырёх операциях оставлен **вариант B**: настройка слева, план и ход
справа. «Выбрать вручную» открывает отдельное окно с поиском, фильтрами входа,
пати и класса, сортировкой и массовым выбором показанных персонажей. Фильтры
не снимают скрытые отметки; только «Сохранить выбор» меняет план, а отмена или
Escape возвращает предыдущий режим. Список пати виден только при «По пати».
Цветная полоса показывает состояние входа на сайт, а не то, запущено ли окно
игры. Иконки классов — из `public/assets/icons/classes`.

- «Промокод»: ввод кодов, план, пробный запуск и имитация обновления статусов.
- «Передача»: имитация проверки инвентаря по персонажам, список предметов,
  выбор сервера и получателя для каждого браузера. Общий аккаунт обрабатывается
  один раз. Реальный автоматический скрипт переносит всё доступное для отметки,
  а не выбранные категории; ограничения и сундуки с выбором награды учитываются
  отдельно. В ручном окне сайта есть группировка по типам и акциям — это другой режим.
- «Подарки»: имитация чтения балансов, цен и лимитов, количество для каждого
  аккаунта, ограничения по монетам/наличию и прогноз остатка. Иконка «ⓘ»
  открывает описание из примера страницы. Если товара нет в примере, его эффект
  не выдумывается. Каталог и расчёт берутся из `shopCore.js`.
- «Сундук караванщика»: имитация подсчёта, пробное или демонстрационное
  открытие всех найденных сундуков. Общий инвентарь учитывается один раз.

Кнопка «Обновить данные» в каждом окне заново читает его **внутренний пример**,
а не настоящий сайт. После имитации покупки/передачи обновление показывает
изменения примера и разрешает следующий запуск. `scenario-fixtures.js` хранит
примеры, `scenarios.js` — макеты, `character-picker.js` — общее окно выбора.
Снимок описаний и пример цен шести товаров сверен с `tests/fixtures/site-shop.html`;
актуальная цена в приложении берётся с сайта.

В `tools-modals.js` остался не подключённый к странице код старых окон
промокода: он не открывается в лаборатории. Для внедрения B в приложение нужно
отдельно изменить реальные модули `js/modules/automation/` и их тесты: подключение
демо само по себе поведение релиза не меняет. Поведение прототипа проверяется в
`tests/demoScenarios.test.js`.
