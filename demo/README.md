# Лаборатория окон скриптов

Интерактивный **прототип**, не часть релизного приложения: персонажи, балансы,
наличие и результаты вымышлены. Проверка, обновление, покупка и передача только
имитируются: демо не обращается к сайту, не вызывает Rust-команды и не сохраняет
данные приложения. Изменения в примере живут только до закрытия окна.

## Запуск

```sh
npm run demo
```

Откройте <http://localhost:1420/demo/tools-modals.html> (корень сервера сам
перенаправит туда). Сервер `serve.mjs` не требует зависимостей; страница также
работает через Vite. Демо не входит в `vite build` приложения.

Дополнительная страница [`guild-marathons.html`](./guild-marathons.html) показывает опрос клана
(несколько/один ответ, отсутствие и ошибку загрузки) и цвета авторизации в матрице марафона.
В ней используется настоящий безопасный рендерер опроса приложения; примерный голос остаётся
только на странице и на сайт не отправляется.

## Что проверять

Во всех четырёх операциях оставлен **вариант B**: настройка слева, план и ход
справа. «Выбрать вручную» открывает отдельное окно с поиском, фильтрами входа,
пати и класса, сортировкой и массовым выбором показанных персонажей. Фильтры
не снимают скрытые отметки; только «Сохранить выбор» меняет план, а отмена или
Escape возвращает предыдущий режим. Список пати виден только при «По пати».
Цветная полоса показывает состояние входа на сайт, а не то, запущено ли окно
игры. Иконки классов — из `public/assets/icons/classes`.

- «Промокод»: ввод кодов, план, пробный запуск и имитация обновления статусов.
- «Передача»: имитация проверки инвентаря по персонажам, список предметов,
  выбор сервера и получателя для каждого браузера. Общий аккаунт обрабатывается
  один раз. Реальный автоматический скрипт переносит всё доступное для отметки,
  а не выбранные категории; ограничения и сундуки с выбором награды учитываются
  отдельно. В ручном окне сайта есть группировка по типам и акциям — это другой режим.
- «Подарки»: имитация чтения балансов, цен и лимитов, количество для каждого
  аккаунта, ограничения по монетам/наличию и прогноз остатка. Иконка «ⓘ»
  открывает описание из примера страницы. Если товара нет в примере, его эффект
  не выдумывается. Каталог и расчёт берутся из `shopCore.js`.
- «Сундук караванщика»: имитация подсчёта, пробное или демонстрационное
  открытие всех найденных сундуков. Общий инвентарь учитывается один раз.

Кнопка «Обновить данные» в каждом окне заново читает его **внутренний пример**,
а не настоящий сайт. После имитации покупки/передачи обновление показывает
изменения примера и разрешает следующий запуск. `scenario-fixtures.js` хранит
примеры, `scenarios.js` — макеты, `character-picker.js` — общее окно выбора.
Снимок описаний и пример цен шести товаров сверен с `tests/fixtures/site-shop.html`;
актуальная цена в приложении берётся с сайта.

В `tools-modals.js` остался не подключённый к странице код старых окон
промокода: он не открывается в лаборатории. Для внедрения B в приложение нужно
отдельно изменить реальные модули `js/modules/automation/` и их тесты: подключение
демо само по себе поведение релиза не меняет. Поведение прототипа проверяется в
`tests/demoScenarios.test.js`.
