# Лаборатория окон скриптов (демо)

Живая площадка для сравнения вариантов модальных окон скриптов раздела «Инструменты».
Не часть приложения: в сборку (`vite build`) и в тесты (`vitest`) не попадает,
в хранилище ничего не пишет, Rust-команды не вызывает — все данные вымышлены,
«запуск» имитируется на месте.

## Запуск

```
npm run demo
```

и открыть <http://localhost:1420/demo/tools-modals.html> (корень перенаправит сам).
Зависимости не нужны — сервер (`serve.mjs`) на чистом Node, страница работает и через
`vite dev`, если он уже запущен: <http://localhost:1420/demo/tools-modals.html>.

## Что внутри

Один сценарий («Промокод»: коды → персонажи → запуск → итог) в пяти окнах, чтобы
варианты можно было честно сравнить:

| Вариант            | Файл-логика                  | Идея                                                                       |
| ------------------ | ---------------------------- | -------------------------------------------------------------------------- |
| 0 · Как сейчас     | `openCurrent()`              | копия диалога `promo.js` на настоящих `openOverlay`/`scriptUi`             |
| A · Мастер шагов   | `openWizard()`               | «Коды → Персонажи → Проверка → Выполнение», подтверждение встроено в шаг 3 |
| B · Два столбца    | `openSplit()`                | настройка слева, план/ход/итог справа — ничего не переключается            |
| C · Быстрый запуск | `openQuick()` + `openDock()` | маленькое окно параметров, выполнение — в плавающем доке                   |
| D · Консоль        | `openConsole()`              | `activate КОДЫ --target=logged`, поток строк, `stop`/`status`              |

## Связь с настоящим кодом

Импортируются реальные модули приложения, поэтому окна выглядят и ведут себя как
в приложении: `js/modules/marathons/overlay.js` (окно), `js/modules/automation/scriptUi.js`
(блоки `sd-*`), `js/modules/automation/promoCore.js` (разбор кодов, статусы, итоги),
`js/core/ui.js` (`confirmModal`, `toast`). Стили — настоящие `css/core/*` и
`css/modules/promo.css`; новые классы вариантов (`wz-`, `sp-`, `ql-`, `cn-`) живут
в `tools-modals.css` и построены на токенах темы.

Если вариант выбирается для продакшена, переносить нужно разметку/стили из этого демо
в соответствующий модуль `js/modules/automation/`, а не подключать демо к приложению.
