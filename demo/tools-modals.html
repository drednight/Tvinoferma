Инструменты → Скрипты: пять вариантов модальных окон

Все окна собраны на настоящих компонентах приложения — openOverlay, scriptUi.js (классы sd-*), promoCore.js, confirmModal, toast — и на настоящих токенах темы. Сценарий один и тот же: «Промокод» (коды → персонажи → запуск → итог), чтобы варианты можно было честно сравнить. Персонажи, коды и результаты вымышлены; «запуск» имитируется.

💡 Совет: попробуйте в любом окне код PWOLD2024 — он «просрочен», и вы увидите ветку с предупреждениями. Кнопка «Стоп» тоже работает.

Как сейчас

Страница «Инструменты»: восемь карточек-скриптов. Три «проверки» окон не имеют вообще — только тосты «запускаю… / завершено». Пять «операций» открывают большие диалоги, собранные вручную: длинная форма (пояснение → коды → список персонажей) → отдельное окно подтверждения → это же окно превращается в прогресс и таблицу → итог чипами. Ниже — живая копия сетки карточек.

Варианты модальных окон

Каждая карточка открывает полностью рабочее окно: вводите коды, выбираете персонажей, запускаете, останавливаете, смотрите итог. Закрываются по Esc, крестику и «Закрыть».

сейчас

0 · Текущий диалог (копия)

Ровно то, что есть в приложении: общее окно openOverlay, пояснение «что сделает скрипт», пронумерованные секции, подтверждение отдельным окном, прогресс и итог — всё в одном окне по очереди.

Плюсы
  • всё видно сразу, без шагов и кликов
  • единый язык sd-* на все четыре скрипта
Минусы
  • окно длинное: на небольшом экране форма + список = прокрутка
  • форма, прогресс и итог сменяют друг друга — «назад» пересобирает окно
  • пока скрипт идёт, окно занято и держит внимание
вариант A

1 · Мастер шагов

Скрипт как мастер: «Коды → Персонажи → Проверка → Выполнение». Один шаг = один экран, внизу «Назад / Далее». Отдельное окно подтверждения не нужно — его заменяет шаг «Проверка», где видно «что произойдёт» крупным шрифтом до запуска.

Плюсы
  • невозможно «перепрыгнуть» через настройку: порядок ведёт за руку
  • каждый экран короткий — нет длинной прокрутки
  • подтверждение встроено в поток, а не всплывает поверх
Минусы
  • больше кликов до запуска (для новичка — плюс, для вас ежедневно — минус)
  • сложнее «поправить мелочь»: нужно ходить между шагами
вариант B

2 · Два столбца: настройка + живой ход

Окно не переключает экраны: слева настройка (коды, кого запускать), справа — таблица персонажей, которая из «плана» на глазах превращается в «ход работы» и итог. Запуск происходит в том же виде, где настраивали.

Плюсы
  • нет скачков «форма → прогресс → итог»: всё в одном виде
  • план виден до запуска: кто получит пропуск, кто в работу
  • легко править коды и смотреть эффект на плане справа
Минусы
  • окно шире остальных — на узком экране столбцы придётся складывать
  • плотнее всего в реализации: два живых столбца синхронизируются
вариант C

3 · Быстрый запуск + фоновый док

Маленькое окно только для параметров: коды, «кому» сегментами, большая кнопка «Запустить». После нажатия окно закрывается, а скрипт живёт в плавающем доке справа внизу: пилюля с прогрессом, клик — панель с ходом работы и итогом. Окно больше не «держит» вас.

Плюсы
  • запуск в 2 клика; можно уйти на любую вкладку — док всегда виден
  • несколько скриптов могут идти параллельно, каждый со своей пилюлей
  • совпадает с идеей журнала задач, который у вас уже есть в шапке
Минусы
  • мало места для сложной настройки (для «Передачи» придётся расти обратно)
  • нужен новый компонент дока и правила «кто кому мешает» в очереди
после «Запустить» смотрите в правый нижний угол
вариант D

4 · Консоль скриптов

Терминал внутри приложения: activate PWZNANIYA26 --target=logged, ответ — поток строк с временем и статусами. Есть help, status, stop, clear. Для ежедневных запусков «не глядя» — самый быстрый путь.

Плюсы
  • максимальная скорость для опытного: одна строка вместо всей формы
  • естественно дружит с палитрой команд (Ctrl+K) и пресетами
  • журнал строк сам по себе — готовый отчёт о запуске
Минусы
  • порог входа: команды и флаги нужно помнить или держать шпаргалку
  • выбор персонажей текстом неудобен — нужна «мышиная» половина

Как по-другому реализовать сами скрипты (не только окна)

Сейчас четыре диалога («Промокод», «Передача», «Подарки», «Сундук») написаны вручную — это ~2 700 строк похожего кода: у каждого свой рендер формы, свой прогресс, свой итог. Окна — только верхушка; вот что можно изменить под ними.

1

Единый скриптовый движок

Один движок + декларативное описание скрипта вместо четырёх рукотворных диалогов: defineScript({ id, icon, title, fields, targets, run, results }). Движок сам рисует окно (любой из вариантов выше), ставит задачу в очередь, пишет журнал, показывает итог. Новый скрипт = конфиг на ~40 строк, а не файл на ~600. Ваши promoCore/transferCore/shopCore уже почти подходят на роль run.

2

Настройка → очередь → док

Разделить «настроить» и «выполнить»: любое окно только собирает параметры, а выполнение всегда уходит в док задач (вариант C) и общую очередь — она у вас уже есть (startTask/waitTurn). Тогда «Передача» может идти фоном, пока вы запускаете «Подарки», а модалки перестают быть «комнатой, где заперт скрипт».

3

Пресеты и запуск в один клик

На карточке скрипта — кнопка «Запустить» с последними параметрами и стрелка «Настроить…». Пресеты: «всем с входом», «пати Альфа», «только новые коды». 90 % запусков повторяют прошлые — незачем каждый раз проходить всю форму. Это же лечит главную претензию к мастерам (вариант A).

4

Боковая панель вместо модального окна

Drawer справа: страница «Инструменты» остаётся видна, а скрипт настраивается и работает рядом. Удобно для «Передачи», где хочется сверяться со списком персонажей на странице, и для длинных очередей. Технически — тот же openOverlay, но с классом «прижато к правому краю, во всю высоту».

5

Консоль + палитра команд

Вариант D как второй интерфейс поверх того же движка: Ctrl+K → «промо …» — и запуск без окон вообще. Палитра команд у вас уже есть (commandPalette.js) — скрипты могут стать её командами с аргументами, а консоль — местом, где виден поток событий.

6

Проверкам — статус, а не тосты

«Проверка входа», «Балансы», «Марафоны» сейчас отвечают двумя тостами («запускаю…», «завершено») — между ними непонятно, что происходит. Им окно не нужно вовсе: достаточно строки прогресса на самой карточке (или пилюли в доке из варианта C) и короткого итога «обновлено 6 из 8, ошибки: 1».

Сравнение

Оценка по одному сценарию «Промокод»: от открытия окна до видимого итога.

Вариант Кликов до запуска Процесс виден Окно держит внимание Порог входа Сложность внедрения Кому подойдёт
0 · Как сейчас 3–4 (+ подтверждение) в окне, таблицей да, всё время низкий — (уже есть) база, от которой отталкиваемся
A · Мастер шагов 5–6 на шаге «Выполнение» да самый низкий средняя новичкам и редким запускам
B · Два столбца 3 всегда рядом с настройкой да низкий выше средней «хочу видеть план и ход сразу»
C · Быстрый запуск + док 1–2 в доке, окно свободное нет 🎉 низкий средняя (нужен док) ежедневным запускам и очередям
D · Консоль 1 (строка + Enter) потоком строк да, но компактно высокий средняя вам лично и power-users

🧭 Моя рекомендация — гибрид: C как основа (настройка компактным окном, выполнение в доке — это заодно путь к идее №2 «единый движок»), B для «Передачи» и «Подарков», где параметров много и важен план, A оставить как «режим новичка», а D — как вторую голову палитры команд.
