> ⚠️ **Важное замечание по архитектуре.** В плане пункты 5 и 6 описаны в терминах Playwright/Node (`exposeFunction`, headless Chrome). В проекте это Tauri: «headless» — скрытые окна WebView, а связь страницы с приложением идёт через `initialization_script`, события и `invoke`. Предлагаю в плане заменить формулировки, а пункт 5 считать закрытым.

## Мои идеи

**Надёжность (самое ценное, потому что всё держится на парсинге сайта)**

- **Проверка парсеров.** Если сайт поменял вёрстку, приложение показывает «парсер марафонов сломался» вместо тихих нулей. Фикстуры страниц уже лежат в `tests/fixtures`; расширить их и добавить тесты на Rust.
- **Удалённый каталог контента.** Данные (данжи, допуски, рекомендуемые статы, шаблоны марафонов, руны) лежат JSON-файлами в GitHub и обновляются без релиза приложения. Один механизм закрывает фазы 3 и 4.
- **Авто-бэкап перед любым массовым скриптом** (промокоды, переводы). `backup.rs` уже есть.
- Кнопка «Скопировать отчёт об ошибке» с логом задачи без паролей, чтобы удобнее присылать баги в Issues.

**Удобство**

- **Дашборд «Сегодня»:** данж дня, невыполненные задания марафонов, кому нужно перелогиниться, баланс партий. `dashboard.css` есть, самого модуля нет.
- **Уведомления:** конец этапа марафона, истёкшая сессия, смена данжа дня (`notifications.js` уже есть).
- **Расписание скриптов:** авто-сверка марафонов и балансов раз в день, пока приложение свёрнуто в трей.
- **Массовые операции:** назначить партию или тег выбранным персонажам (режим выбора уже есть).
- **Быстрый поиск (Ctrl+K)** по персонажам, партиям, марафонам.
- **Прогноз по марафону:** «успеете ли набрать цель к концу этапа» на основе текущей скорости.

**Безопасность**

- Блокировка приложения паролем или PIN при запуске (в настройках есть раздел `security`).
- Шифрование файла бэкапа паролем: он содержит данные аккаунтов.

**Технический долг**

- Иконки данжей весят 1–2,4 МБ каждая: сжать до WebP, сократить установщик.
- Заглушки `cloud/googleDrive.js` и `googleSheets.js` не входят в ваш план. Либо довести до ума (синхронизация между компьютерами), либо удалить.
- Проверка типов (`npm run typecheck`) включена только в файлах с `// @ts-check` (`js/core/`, часть `js/data/`). Остальные файлы подключать по одному.
- Тесты на Rust и e2e для критичных сценариев (миграции, импорт, сверка марафона) расширять вместе с каждой фазой.
