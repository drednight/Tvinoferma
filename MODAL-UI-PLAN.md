# Поэтапный план доработок Твинофермы: модалки и унификация UI

## Цель
Свести модальные окна к единому компоненту, унифицировать пустые состояния/кнопки/списки и сделать UI предсказуемым без глобального рефакторинга.

## 1. Подготовка (0.5 дня)
Перед правками зафиксировать текущее состояние.

| Шаг | Действие | Файлы/инструменты | Критерий готовности |
|---|---|---|---|
| 1.1 | Прогнать checks | `npm run check` (lint + typecheck + tests) | All tests green, no new errors. Save output. |
| 1.2 | Обзор текущих модалок | `js/core/ui.js`, `js/modules/*/overlay.js`, места вызова `confirmModal/openOverlay` | Список всех мест вызова и типичные паттерны зафиксированы. |
| 1.3 | Снять стили модалок | `css/` поиск `.modal`, `.overlay`, `dialog` | Понять что есть сейчас, что конфликтует. |

## 2. Этап 1. Фундамент модального компонента (1-2 дня)
Цель - создать ядро, не ломая существующие места. Новые модалки будут сразу на нём, старые переводить постепенно.

| Шаг | Действие | Детали реализации | Файлы | Критерий готовности |
|---|---|---|---|---|
| 2.1 | Добавить CSS-переменные | Добавить z-index и переменные модалки (`--z-modal`, `--z-overlay`, `--z-toast`, `--modal-radius`, `--modal-pad`). | `css/core/vars.css` | Переменные есть, используются. |
| 2.2 | Создать стили модалки | Базовые классы: `.modal`, `.modal__backdrop`, `.modal__dialog`, `.modal__header`, `.modal__body`, `.modal__footer`, размеры `sm/md/lg/xl/full`, модификатор `.modal--danger`. Учитывать `prefers-reduced-motion`. | `css/core/modal.css` (создать) | Стили подключены в `css/index.css`/главный css-файл. |
| 2.3 | Создать ядро модалки | API: `openModal(options)`, возвращает `{ close(), setBody(html/el), setFooter(html/el), element }`. Создание DOM, бэкдроп, Esc, клик по бэкдропу, блокировка скролла body, возврат фокуса. | `js/core/modal.js` (создать) | Модуль работает в dev, можно открыть тестовую модалку через консоль. |
| 2.4 | Фокус-трап | При открытии сохранять `activeElement`, перехватывать `Tab`, циклировать фокус по focusable элементам, возвращать фокус при закрытии. | `js/core/modal.js` | Tab не выходит за пределы модалки, фокус корректно возвращается. |
| 2.5 | Подключить модуль | Импортировать стили и модуль. | `css/index.css`, возможно `js/core/index.js` | Приложение собирается, стили применяются. |

**Тест:** Открыть консолью `openModal({title:'Тест', body:'<p>Привет</p>', footer:'<button class="btn primary" data-close>Ок</button>'})` — закрывается по крестику/кнопке/Esc/бэкдропу, фокус-трап работает.

## Порядок выполнения (приоритет)
1. Этап 1 (фундамент) — без него всё остальное костылём
2. Этап 2 (confirm/openOverlay) — много мест, низкий риск при обёртке
3. Этап 3 (формы) — самые заметные
4. Этап 4 (мелочи) — параллельно
5. Этап 5 (доводка) — в конце

## Риски и меры предосторожности

| Риск | Вероятность | Влияние | Меры |
|---|---|---|---|
| Сломать `confirmModal` (много вызовов) | Средняя | Высокое | Сохранить API, тестировать после изменений. |
| Конфликт z-index | Средняя | Среднее | Единые переменные, проверка оверлеев/тостов/командной палитры. |
| Потерять события при замене DOM | Средняя | Среднее | Не удалять старый DOM пока готов новый, делегирование где возможно. |
| Длинные формы ломают скролл | Низкая | Среднее | `max-height` + `overflow:auto` на `modal__body`, тест на узком экране. |
| Фокус-трап блокирует ввод в сложных виджетах | Низкая | Среднее | Исключать элементы вне диалога, корректно определять focusable элементы. |

## Рекомендуемый темп
- **Оптимально:** по 1 этапу за раз, коммитить после каждого шага.
- **Быстро, но аккуратно:** Этапы 1-2 за 2-3 дня, Этапы 3-5 за 2-3 дня.
- **Принцип:** не переписывать всё сразу, **оборачивать**. Если больше часа и неуверенность — сделать обёртку над старым с новым фреймом.
